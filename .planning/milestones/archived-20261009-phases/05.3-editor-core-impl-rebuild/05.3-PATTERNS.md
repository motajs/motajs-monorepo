### `src/undo/undoSystem.ts`（service，有状态栈）

**参照：** `packages/libs/utils/lib/advance/message/index.ts`（仓内最接近的「持有私有 Map/Set 状态、方法内异步派发」的类）

**导入与类骨架**（`utils/lib/advance/message/index.ts:1-23`）：
```ts

import { isMatching, P } from 'ts-pattern';

export class MessageClient {
  private id = 0;
  private readonly connectionHandlers: Map<number, ConnectionHandler> = new Map();
  constructor(private readonly postMessage: (msg: Message) => void) {}
}
```

**核心模式（撤销栈语义，来自 INTERFACE-NAME + RESEARCH Pattern 3 / D-31..D-33）：**
- `UndoEntry` 作为**模块内非导出接口**，保存「可撤回对象 + 撤回上下文」。
- `addUndoContext(undo, context)`：`undoStack.push({ undo, context })`，超过 `maxUndoStep` 用 `shift()` 裁剪；**任何新操作要清空 `redoStack`**（RESEARCH Validation Map D-13/D-31/D-33）。
- `undo()`：弹出 `undoStack` 顶部，交给 `entry.undo.undo(entry.context)`，压入 `redoStack`；空栈 no-op。
- `redo()`：反向，压回 `undoStack`。
- 状态全部放**实例字段**（`private undoStack: UndoEntry[] = []`），**不得**模块级 `const = []`——否则 `coreModuleState.js` / eslint `no-restricted-syntax` 判红（`eslint.config.js:183-188`）。

**异步派发样式**（`utils/lib/advance/message/index.ts:43-56`，`Promise.withResolvers`）：
```ts
request<ReqT, ResT>(type: MessageType<ReqT, ResT>, req: ReqT, options?: MessageRequestOptions): Promise<ResT> {
  const handler = Promise.withResolvers<ResT>();
  const requestId = this.id++;
  this.connectionHandlers.set(requestId, handler);
  ...
  return handler.promise;
}
```

**注释与 JSDoc：** 用户接口已在 `src/undo/types.ts` 写好逐参数 `@param`；实现类**不重复**接口的 JSDoc（AGENTS §Code style「方法 JSDoc 必须写在接口的源头处」）。私有方法要写**完整**注释。

**参照 B —— `useSyncExternalStore` 的 `subscribe`/`getSnapshot` 契约（`editorConfigService.ts:121-143`）：**

**关键语义（D-22 / D-24 / D-26 / D-28..D-32 / D-37）：**
- `switchTo(panel, param?)`：同面板 no-op；`this.undoSystem.addUndoContext(this, { type: PanelUndoType.Switch, data: { from, fromParam, to, toParam } })`，再 `internalSwitchTo`。

- `render()`：在**构造器**里创建一次稳定 `FC` 并缓存（RESEARCH Pitfall 3）；组件返回 `<Panel/>`。
- `dispose()`：按注册**逆序** `unload()` 钩子并 `await panel.dispose()`。
