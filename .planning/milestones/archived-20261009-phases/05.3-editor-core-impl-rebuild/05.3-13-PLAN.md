<objective>
把资源/面板**接口**的返回类型加宽，让「资源系统尚未初始化」这种情形可以用「什么都没有」来回答，而不是硬造一个值：读资源内容的两个接口改为可能返回 `undefined`，创建资源的两个接口改为可能返回 `null`；并只做**保持 editor-core 类型检查与测试全绿所必需的最小机械跟随**（实现类返回类型同步、唯一受影响的钩子调用点就地 guard）。不实现未初始化时的空守卫本身，那是下层实现计划 05.3-14 的事。

Purpose: 接口先行（D-34 / AGENTS §Project Rules「先接口、后实现」）——先让接口允许「空结果」，再由实现计划补上真正产生空结果的分支；避免接口与实现揉进同一个计划。
Output: 加宽后的 `resource/types.ts`、`panel/types.ts`，同步返回类型的 `resource/resource.ts`、`panel/panelContext.ts`，以及 `panel/panelSystem.ts` 中 `EditorPanelHooks.onUpdateResource` 的最小 guard。

说人话：有四个「要资源」的接口，现在规定它们必须给出一份数据；我们把它改成「可以没有数据」——请求内容可能得到 `undefined`，创建资源可能得到 `null`。这一步只动「接口怎么规定」和「为了编译通过必须跟着改的那几行」，不写「什么情况下会没有数据」的逻辑。

⚠️ 本计划只加宽返回类型 + 必要机械跟随，不改任何方法体逻辑、不改公共 `IEditorPanel` 接口。若发现需要改行为或扩大接口才能通过编译，先停下汇报（D-34），不擅自扩大范围。
</objective>
