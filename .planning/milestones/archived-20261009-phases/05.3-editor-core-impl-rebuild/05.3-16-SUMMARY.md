# Phase 05.3 Plan 16: 面板与核心缺陷修复（gap closure） Summary

## Accomplishments

- **WR-05 修复：** `PanelSystem.dispose()` 在移除监听、逆序释放面板、清空注册表之后追加 `initialized = false` 与 `currentParam = {}`；`PanelSystem.initialize()` 入口以 `initialized` 守卫幂等返回，避免重复挂窗口监听；释放后再次 `initialize()` 能重新挂监听并补调新版待初始化面板。
- **WR-07 修复：** `PanelSystem.registerPanel` 保持「先创建、后查重」顺序，重复 id 分支先 `await panel.dispose()` 再记 `panel.duplicateId` 并返回 `null`，被丢弃的面板不再泄漏上下文/资源。
- **WR-08 修复：** `PanelSystem.switchTo` 在「与当前面板相同」判断之后校验 `this.panels.get(panel.id) === panel`，未注册面板记 `panel.notRegistered` 后直接返回，不切换、不记录撤回；`internalSwitchTo`（`undo` / `redo` 路径）保持不校验，维持 D-32。
- **WR-06 修复：** 构造器里 `handleFocus` / `handleBlur` 由 `void this.currentPanel?.onFocus()` 改为 `Promise.resolve().then(...).catch(...)`，回调同步抛错或返回被拒绝的 Promise 都统一捕获，经集中日志 `panel.callbackFailed` 记录，不再产生未处理 rejection。
- **IN-02 修复：** `EditorCore` 新增私有 `initialized` / `disposed`；`initialize` 先判 `disposed`（记 `core.initializeAfterDispose`，error 级，不下发注入）再判 `initialized`（记 `core.duplicateInitialize`，warn 级，不重复下发）；`dispose` 末尾置 `disposed = true`；`package.json` 版本由 `0.0.0` 对齐到 `0.1.0`，与 `EditorCore.version` 一致。
- **日志表：** `log/messages.ts` 新增四条英文模板（`panel.notRegistered` / `panel.callbackFailed` / `core.duplicateInitialize` / `core.initializeAfterDispose`），仍为 `Object.freeze`，既有 id 逐字保留。

## Decisions Made

- **面板释放语义**：`dispose` 使系统回到「未初始化」状态（复位 `initialized` / `currentParam`），因此释放成为可逆动作，重入 `initialize` 必须重新挂监听且只能生效一次。
- **重复注册的处理顺序**：面板只能在创建后才能拿到 id，因此保持「先创建、后查重」；重复分支必须在丢弃前 `dispose`，否则 creator 已申请的上下文/资源泄漏。
- **切换校验的边界**：`switchTo` 只接受系统亲自注册过的面板；历史回退路径 `internalSwitchTo` 不校验，保持 D-32「撤回不自证循环」。
- **焦点回调兜底统一走异步链**：`Promise.resolve().then(cb).catch(log)` 同时覆盖同步抛错与拒绝 Promise，复用 `panel.callbackFailed` 一条 id。
- **组合根生活周期次序**：`disposed` 判定排在 `initialized` 之前——一旦释放，重复初始化也统一按「释放后拒绝」处理，不下发注入。
- **版本对齐**：`package.json` 与 `EditorCore.version` 统一为 D-12 既定版本 `0.1.0`。
