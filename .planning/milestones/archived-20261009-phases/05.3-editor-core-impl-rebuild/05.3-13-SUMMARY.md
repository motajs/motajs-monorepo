# Phase 05.3 Plan 13: 资源/面板接口返回类型放宽与未初始化资源守卫 Summary

**把「要资源」的四个接口从「必须给出一份数据」改成「可以没有数据」——请求内容可能得到 `undefined`、创建资源可能得到 `null`；实现只做编译所需的最小跟随（两个实现类声明同步、唯一消费点就地 guard），不写任何「什么情况下会没有数据」的逻辑。**

## Accomplishments

- `resource/types.ts` 加宽三处：`IResource.request()`、`IResourceStore.readContent<T>` 返回 `Promise<T | undefined>`；`IResourceAccess.createResource<T>` 返回 `Promise<IResource<T> | null>`。每个方法的多行 jsDoc（含 `@param`）保持原样，只改 `Promise<...>` 这一段。
- `panel/types.ts` 加宽 `IEditorPanelContext.createResource<T>` 返回 `Promise<IResource<T> | null>`；`IEditorPanel` 公共接口一字未动。
- 机械跟随：`Resource.request` 与 `PanelContext.createResource` 的声明返回类型同步加宽，方法体（`return this.store.readContent...` / `return this.resourceAccess.createResource...`）逐字未改。
- `EditorPanelHooks.onUpdateResource` 是加宽后生产源码里唯一会收到 `T | undefined` 的消费点，改为守卫式：`if (!resource) return;` → `const data = await resource.request();` → `if (data === undefined) return;` → `await this.panel.onUpdateResource(id, data);`；`onUpdateResourceList` 未动。
- 未实现 `injection` 空守卫，也未新增 logger 消息——那是计划 05.3-14 的范围。
