# Phase 05.3 Plan 06: 面板系统 Summary

**面板系统落地：一句话，编辑器以「工作区/模式」为单元，同一时刻只显示一个面板；面板能被注册、切换、释放，切换可撤回，资源更新与窗口焦点经统一入口触达面板。**

## Performance

- **Duration:** 9 min
- **Tasks:** 2
- **Files created/modified:** 5（4 新建 + 1 追加导出）

## 结果

把 `@motajs/editor-core` 的面板系统做出来，三件事：

1. **面板能被管理**：`PanelSystem` 负责注册（id 唯一）、按注册顺序初始化 / 逆序释放、同一时刻只有一个前台面板、并提供顶层要挂载的渲染根组件。切到另一个面板这一步会占一条撤回记录，所以「切错了」可以撤销回去。
2. **面板能拿到资源**：面板不直接碰资源系统，而是通过构造时拿到的 `PanelContext` 请求资源、创建/删除、加撤回；这些调用只是转交给底层的资源系统和撤回系统。
3. **资源更新能通知到面板**：资源系统只广播「某个 id/某类列表更新了」，由面板层的 `EditorPanelHooks` 重新申请最新内容再通知对应面板——这样资源层不会反向依赖面板层，不会形成环。

## 实际改动

- 新增 `packages/libs/editor-core/src/panel/panelContext.ts`：`export class PanelContext implements IEditorPanelContext`。
  - 字段 `private readonly resourceAccess: IResourceAccess`、`private readonly undoSystem: IUndoSystem`；构造器 `(resourceAccess, undoSystem)`。
  - `requestResource` / `requestResourceList` / `createResource` / `deleteResource` 直接转调 `IResourceAccess`；`addUndoContext(panel, context)` 直接转调 `IUndoSystem.addUndoContext`（D-31）。
  - `IResourceAccess` 从 `../resource/access`（非桶文件）导入，符合 D-35「读写口不进包根」。
- 新增 `packages/libs/editor-core/src/panel/editorPanelHooks.ts`：`export class EditorPanelHooks implements IResourceSystemHooks`。
  - 字段 `private readonly panel: IEditorPanel`、`private readonly context: IEditorPanelContext`；构造器 `(panel, context)`（D-45）。
  - `onUpdateResource(id)`：`const resource = await this.context.requestResource(id); if (resource) { await this.panel.onUpdateResource(id, await resource.request()); }`。
  - `onUpdateResourceList(type)`：`await this.panel.onUpdateResourceList(type, await this.context.requestResourceList(type));`。
- 新增 `packages/libs/editor-core/src/panel/panelSystem.ts`：`export class PanelSystem implements IPanelSystem`。
  - 字段 `currentPanel`、`undoSystem`、`resourceSystem`、`panels`、`hooks`、`pendingPanels`、`initialized`、`currentParam`、`panelStore = new Store<number>(0)`，以及稳定的 `subscribe` / `getSnapshot` 箭头字段、构造时创建一次的 `RootComponent`、`handleFocus` / `handleBlur` 箭头字段。
  - `registerPanel(creator)`：新建 `PanelContext`，`await creator(context)`，重复 id 抛错（D-28），入 `panels`，`resourceSystem.addHook(new EditorPanelHooks(panel, context))` 并记录控制器；已初始化则立即 `await panel.initialize()`，否则入 `pendingPanels`（D-30）。
  - `initialize()`：置 `initialized = true`，注册 `window` 的 focus/blur 监听（D-38），取出并清空 `pendingPanels` 逐个 `await panel.initialize()`；无未使用形参。
  - `switchTo(panel, param?)`：同当前面板直接返回；否则 `addUndoContext(this, { type: PanelUndoType.Switch, data: { from, fromParam, to, toParam } })` 后 `internalSwitchTo`。
  - `private internalSwitchTo(panel, param?)`：切出旧面板 → 更新 `currentPanel`/`currentParam` 并 `panelStore.setState(v => v + 1)` → 切入新面板；**不记录撤回**（D-32）。
  - `undo` / `redo`：单次 `as` 收窄为模块内 `IPanelSwitchData`，只调 `internalSwitchTo`。
  - `disposePanel(panel)`：先 `hooks.get(panel)?.unload()` 再 `await panel.dispose()`，删两张表；若是当前面板则置 null 并通知。
  - `dispose()`：移除 window 监听；`[...panels.values()].reverse()` 逐个 unload 钩子并 `await panel.dispose()`；清 `pendingPanels` 与两张表，`currentPanel = null`。
  - 渲染根拆成模块层 `PanelRoot`（在模块层调用 `useSyncExternalStore`）+ 构造时缓存的 `RootComponent`（仅 `createElement(PanelRoot, { subscribe, getSnapshot })`），文件保持 `.ts`、无 JSX。
- `packages/libs/editor-core/src/panel/index.ts`：**追加** `export * from './panelSystem';`、`export * from './panelContext';`、`export * from './editorPanelHooks';`（`export * from './types'` 未动）。
- 新增 `packages/libs/editor-core/src/panel/__tests__/panelSystem.test.ts`：
  - `FakeResourceInjection implements IResourceInjection` 内存后端；`FakePanel implements IEditorPanel` 记录各回调调用、`render()` 返回渲染自身 id 的稳定组件、`id` 可指定、`dispose` 可写入顺序数组。
  - 最小闭环 4 例（注册未初始化不调 initialize、initialize 补调、switchTo 切出/切入、render 返回函数、真实挂载后 switchTo 切换内容）。

### 自动修复

**1. [Rule 3 - Blocking] PanelContext 需要 IResourceAccess，但 PanelSystem 字段按计划类型为 IResourceSystem**
- **Found during:** Task 1（实现 PanelSystem）
- **Issue:** D-35 要求对外 `IResourceSystem` 不含读写方法（读写口 `IResourceAccess` 单独定义），但 `PanelContext` 需要 `IResourceAccess`；`registerPanel` 里 `new PanelContext(this.resourceSystem, ...)` 类型不通过（TS2345）。
- **Fix:** 字段与构造器保持计划指定的 `IResourceSystem`；`registerPanel` 对注入值做**单次** `as ResourceSystem` 收窄——`ResourceSystem` 同时实现 `IResourceSystem` 与 `IResourceAccess`，收窄后即可传给 `PanelContext`。未使用连续 `as`。（05.3-07 组装时 `new PanelSystem(undoSystem, resourceSystem)` 仍按 `IResourceSystem` 传入即可编译。）
- **Files modified:** `packages/libs/editor-core/src/panel/panelSystem.ts`
- **Verification:** typecheck 退出码 0；resource 桥接测试通过。
- **Committed in:** `d99411f`（Task 1 提交）

**2. [Rule 1 - Bug] 渲染根组件在 class 字段箭头内调用 hook 触发 react-hooks 误报**
- **Found during:** Task 1 lint 复核
- **Issue:** 计划要求 `render()` 返回构造时创建一次的 `RootComponent`；若把 `useSyncExternalStore` 直接写在 class 字段箭头里，`eslint-plugin-react-hooks` 判定为「class component 中调用 hook」，产生 1 条 `react-hooks/rules-of-hooks` error（该 red 计划未预期，且 05.3-08 不会消除）。
- **Fix:** 把真正使用 hook 的组件提升到模块层 `PanelRoot`（PascalCase 函数组件），`RootComponent` 只做 `createElement(PanelRoot, { subscribe, getSnapshot })`，仍只创建一次；文件仍为 `.ts`、仍用 `createElement`、无 JSX。
- **Files modified:** `packages/libs/editor-core/src/panel/panelSystem.ts`
- **Verification:** eslint 复核后该 rule 不再报错，仅剩 window 暂红；真实挂载重渲染测试通过。
- **Committed in:** `d99411f`（Task 1 提交）
