<objective>
Define the engine-agnostic adapter contract in core: the generic `ResourceDescriptor<T>`, the
`EngineDescription` input, the widened `EngineAdapter`, an aggregated-validating `defineEngine`, the
shared logical-id predicate, a pure preload-order helper, and the version constant — then export them
from the root `.` barrel and machine-assert the surface.

Purpose: this is the contract every engine (mota and a future non-mota engine) conforms to. It must be
source-agnostic (D-04: no `path`/`format`/handler on the generic descriptor) and pure (no registration,
no bus, no side effects), so that Phase 11's composition root can register descriptors without core ever
learning where content comes from.

Output: extended `lib/ports/engine.ts`, the shared `isValidResourceId` export on
`lib/resources/resourceRegistry.ts`, the root-`.` exports, `lib/__tests__/engineContract.test.ts`, and
extended `lib/__tests__/coreApiSurface.test.ts`. The mandatory `INTERFACE-NAME.md` + `COVERAGE.md` planning
artifacts already exist (pre-execution, materialized during planning); Task 1 verifies rather than creates
them, so no source edit can precede the naming gate.

Pre-execution gate (AGENTS.md §Project Rules): `INTERFACE-NAME.md` records every important name with its
purpose and the user confirms it at the per-plan briefing **before** this plan executes; the executor of
Task 1 asserts the artifacts exist and match the plans, and must not land any unconfirmed name.

Decisions implemented here — D-03: `defineEngine` lives in core and `EngineAdapter` evolves explicitly
by gaining `resources`. D-04: the generic descriptor has no `path`/`format`/handler instance. D-05: the
handler is expressed through the lazy `create(deps)` factory. D-07: parameters/templates never reach
core. D-09: the shared id predicate keeps `defineEngine` and `ResourceRegistry` on one grammar.

Reversibility (carried from CONTEXT): the descriptor shape and the widened `EngineAdapter` are `costly`
— they are the core's public adapter contract; a later change touches every adapter after Phase 12
freezes the surface (D-03/D-04).
</objective>

| extension author → `defineEngine` | An `EngineDescription` is authored by an adapter, possibly a third party; its ids and dependency edges are untrusted definition data that core validates before any resource is created. |
| future composition root → `ResourceRegistry` | A descriptor id validated by `defineEngine` is later used as a registry key; a grammar drift between the two would let an id through one gate and be rejected by the other. |
| core source → the engine-neutral boundary | Any path, extension, or engine word leaking into `ports/engine.ts` erodes the phase's whole purpose. |

## Assumptions & Flags

- **PORT-03 concurrency edge (edge-probe, was `unresolved`)** — resolved here: `defineEngine` and
  `resolvePreloadOrder` are synchronous and pure with no module-level mutable binding, so concurrent or
  repeated invocations over the same description share no state. Authored as a `must_haves.truths` entry.
- **PORT-04 (edge-probe, `unclassified`)** — flagged assumption: the probe did not classify a shape for
  it beyond content-source boundaries; resolved by the explicit "no `path`/`format`/handler on the
  generic descriptor" truth plus the file-backed class owned by Plan 05-03. No silent drop.
- **Open Question 2 (preload helper)** — resolved: core adds the pure `resolvePreloadOrder` (minimum
  that makes `preloadDependsOn` meaningful); it is exercised by engine B in Plan 05-03 and its real
  Phase-11 consumer is the composition root.
- **Open Question 4 (`preloadDependsOn` vs `preload` strategy validation)** — resolved: NOT validated
  this phase (no consumer/requirement). Recorded here so it is a decision, not an omission.
- **`ENGINE_ADAPTER_API_VERSION` (A3)** — proposed; the user may veto in favour of reusing
  `EDITOR_CORE_API_VERSION`. Recorded in `INTERFACE-NAME.md` §Plan 05-01.
- **`resources` required vs optional (A2)** — chosen required: no production implementer exists and an
  adapter with no resources describes nothing. Flagged because it is a "breaking" evolution (theoretical
  today). `Reversibility: costly`.
- **Pitfall F (subpath content label)** — decided NOT to change `coreExports.js` /
  `subpathStatus.json`: the `.` label `kernel+resources+edit-exports` still describes the surface and the
  added names are not individually enumerated. Revisit only if a reviewer wants a new label.
