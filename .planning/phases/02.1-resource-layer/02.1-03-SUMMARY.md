# Phase 02.1 Plan 03: 端到端 tracer + 共享测试替身 Summary

**注入内存文件系统后，「面板按路径读 / 写、核心把读写落到注入的文件系统上、返回原文」这条最短路径端到端跑通；同时把 editor-core 的实现文件从旧契约（类型号 / 列表接口 / 资源注入）迁到新契约，删掉「按类型列资源」整条链路，并使 editor-core 整包测试与 typecheck 恢复全绿**

## Accomplishments

- 新增共享内存文件系统测试替身 `FakeFileSystem`（按路径 Map 存储、`seed` 预置并自动登记父目录、带类型 `listDirectory`、`readBinary` / `writeBinary`、`failing` / `hanging` 开关、越界路径抛错）与装配工厂 `createCoreHarness`。
- 端到端 tracer 测试跑通：`seed → createCoreHarness → 注册面板 → context.requestResource(path) → Resource.request() 得原文 → Resource.write() 回写 → fs 内该路径内容更新`。
- `ResourceSystem` 改为**驱动注入的 fs**：`initialize(fs)`、`requestResource(path)`、`readContent`→`fs.readFile`、`writeContent`→按类型分流 `writeFile`/`writeBinary`、`createResource`/`deleteResource`/`moveResource`/`listDirectory` 委托后端；删除 `listCache`、`requestResourceList`、`updateResourceList` 与 `IResourceInjection`。
- `Resource` 收敛为 `ResourceContent`；`PanelContext` 按路径转发并新增 `listDirectory`、删除 `requestResourceList`；`EditorCore.initialize` 只向下传 `fs` / `ignore`；`ShellPanelHooks` 只保留 `onUpdateResource`。
- 迁移 `core.test.ts`、5 个 `shell/__tests__/*.test.ts` 与重写 `resourceSystem.test.ts` 到 fs 注入装配；editor-core 整包 **69 用例全绿**，`tsc -b` 退出 0。

## Decisions Made

- `ResourceSystem.initialize` **只接收 `fs`**（省略 `options`）：本计划不实现忽略模式（Plan 04），按 `AGENTS.md`「未使用的后置参数直接不填」不明写未用形参；接口 `initialize(fs, options?)` 仍成立（实现少参合法）。
- `readContent` 直接委托 `fs.readFile`（返回原文 string、不缓存不解析，D-08）；`writeContent` 按 `typeof data` 分流 `writeFile` / `writeBinary`，把二进制与文本路径分离（威胁 T-02.1-07）。
- `FakeFileSystem` 越界拒绝采用「任一路径段为 `..` 即抛错」，比计划描述的「以 `..` 开头」更严；作为「越界由实现负责」的可执行样例（T-02.1-06）。
- 目录条目由「已 seed 的文件路径 + 显式 `makeDirectory` 集合」推导，`seed` 即自动保证父目录可列，空目录由集合覆盖。
