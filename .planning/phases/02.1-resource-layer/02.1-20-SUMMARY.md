# Phase 02.1 Plan 20: 手动保存状态机 + 注释剥离记忆 + 列表实时同步 Summary

**把表格面板从「每次编辑立即写盘」改成手动保存（编辑先留内存并标「未保存」，点保存或切出 / 关栏 / 换表时才落盘），并让「删除注释」确认框同一文件只提示一次、「打开表格」列表在资源更新后实时同步——一次性收口 UAT 缺口 G-02.1-3 的 ⑤④⑦ 三项。**

## Performance

- **Duration:** ~45 min
- **Tasks:** 3
- **Files modified/created:** 5（1 新增测试，4 生产）
- **Commits:** 3（+1 计划元数据提交）

## Accomplishments

- **手动保存状态机**：`ITablePanelColumn` 新增 `unsaved` / `unsavedSchema` / `stripConfirmed` / `pendingStripText`；编辑路径（改值 / 新增 / 删除 / 代码编辑器写回 / 撤销重做）不再写盘，只改内存 + 置 `unsaved`（数据视图新增字段同时置 `unsavedSchema`）+ 登记撤销 + `applyData`；`TablePanel.refresh` 对有未落盘改动的栏不重读覆盖。
- **`TablePanel.save`**：该栏无未落盘改动时不动盘；有改动时经既有 `TablePanel.persist` / `TablePanel.persistSchema` 写回数据文件与需要写回的镜像 schema，成功后清标记、按被写路径刷新同面板依赖栏并发布「已保存」；写入失败沿用已发布的「写入失败，请重试。」并保留未落盘标记。
- **自动保存不丢改动**：`TablePanel.onSwitchOut` / `TablePanel.dispose` 调 `TablePanel.saveDirtyColumns`；`TablePanel.setTable` / `TablePanel.closeColumn` 在换目标 / 关栏前调 `TablePanel.flushColumn`（同步快照 → 异步写回）。
- **注释剥离只提示一次**：`TablePanel.refresh` 命中 `stripConfirmed` 且原文逐字未变时直接按剥离态打开；`TablePanel.confirmCommentStrip` 登记 `stripConfirmed` 并置 `unsaved`（确认即接受「保存后删注释」）；原文变化（含外部改写）即重弹。
- **列表实时同步**：新增 `TablePanel.refreshAwaitingPickers`，在面板内建 / 删（`TablePanel.createIntoColumn` / `TablePanel.deleteFromColumn`）、切入手（`TablePanel.onSwitchIn`）、资源更新通知（`TablePanel.onUpdateResource`）后重取处于打开 / 删除态栏的目录。
- **工具栏**：`TableToolbar` 渲染 `table-save`「保存」按钮（无改动或未传 `onSave` 时禁用）与 `table-unsaved`「未保存」标记；`TableGrid` 把 `unsaved` / `onSave` 透传给工具栏；`table.css` 追加 `.etable-toolbar-unsaved`。

## Decisions Made

- **`TablePanel.flushColumn` 写成异步方法**：其同步前缀完成「读取捕获值 + 清标记」，因此 `void this.flushColumn(i)` 在 `TablePanel.setTable` / `TablePanel.closeColumn` 改写目标之前就已快照，异步写回用的是捕获值而非被改写的栏状态；同时避免在函数内定义局部函数（AGENTS.md §Code style）。
- **剥离记忆以原文比对**：`stripConfirmed` 存「路径 → 确认时的原文」，只有逐字相同才免弹框——外部改写（含内容变化）必然重弹，符合 T-02.1-20-02 的降低误放行要求。
- **列表实时同步复用既有通道**：`TablePanel.onUpdateResource` 接 `refreshAwaitingPickers`，未新增 editor-core 接口（D-04 锁定）；`createResource` 不广播、`updateResource` 才广播的行为在测试中以「先 createResource 再 updateResource」体现。
