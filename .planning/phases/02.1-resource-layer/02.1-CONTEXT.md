# Phase 2.1: 资源层重构与表格文件管理 - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning
**Note:** 本阶段是插入的紧急阶段（Phase 2 之后、Phase 3 之前）。它**推翻**了此前资源层「按类型号 + 标识串认资源、只定义 fs 接口不实现」的前提，因此 Phase 3 素材讨论稿里受影响的决定需在本阶段一并收口（见 D-16）。

<domain>
## Phase Boundary

本阶段把编辑器的**资源层**重构为「**以文件路径为唯一标识**、**editor-core 真正接入文件系统**」的形态，并在此基础上给表格能力补上**打开 / 新建 / 删除表格**三个用户入口。

具体交付：
1. 资源标识从「类型号 + 标识串」改为**纯文件路径**；资源系统升级为**对项目建索引**（初始化递归扫描 + 增量更新），不再保留「按类型列资源」接口。
2. `editor-core` 的初始化**只注入文件系统实现**（读/写/列目录/建目录/移动/删除），原「资源注入接口」删除；文件系统增加二进制读写；core 不解析文件格式。
3. `editor-impl/table` 增加「打开表格」（列表：预设表 + 目录树）、「新建表格」、「删除表格」；表格目标改为**只给数据文件路径**，schema 路径按文件名约定推导。
4. 本阶段**全部收口**旧契约：修正 `CORE-01` 与门禁 `scripts/verify/coreFsSurface.js`、迁移表格命名（`table.xxx` → 路径约定）、回改 Phase 3 讨论稿受影响条目。

不含：素材/地图/代码/事件编辑器（Phase 3/4/5/6）、插件机制、`editor`（旧应用）自身的引擎适配接线。

</domain>

<decisions>
## Implementation Decisions

### A. 资源标识与资源系统

- **D-01:** `IResourceIdentifier` = **纯文件路径**（删除 `type` 类型号与 `id` 标识串）。资源「相等」即路径相等。 — **Reversibility:** costly — 标识形状是所有读写、面板目标、列表与索引的基础，后改要动全线调用点。
- **D-02:** 路径形态 = **相对项目根、以 `/` 分隔、不带前导斜线**（如 `tables/demo.json`）；越界（`..`）安全**由注入的文件系统 / 宿主负责**，core 只拼接不校验。
- **D-03:** 资源系统升级为**项目文件索引**：**初始化时递归 `readdir` 全扫项目建一棵内存文件树**，之后**新建 / 删除 / 移动时增量更新**；索引**只存结构**（路径、文件 / 目录），**不预读文件内容**。 — **Reversibility:** costly — 索引是面板浏览与「打开」入口的数据来源。
- **D-04:** **取消「按类型列资源」接口**（`requestResourceList(type)` 及其缓存）。列资源 = 读索引 / 列目录。 — **Reversibility:** costly — 这是一条已对外暴露的契约，Phase 3 素材曾依赖它。
- **D-05:** 支持**外部配置忽略项**：注入一个**模式列表**（字符串数组，可含通配），索引遇到匹配的**目录 / 文件**即跳过（如 `node_modules`、`.git`）。

### B. core 与文件系统

- **D-06:** 初始化**只注入文件系统实现**（`IEditorFileSystem`）；**删除 `IResourceInjection`**，`IEditorCoreInjection` 不再包含资源注入。 — **Reversibility:** one-way — 这是已发布的注入契约，删除后每个宿主（dev 宿主、未来 `@motajs/editor`）都必须改注入方式。
- **D-07:** 文件系统接口**增加二进制读写方法**（如 `readBinary` / `writeBinary`，`Uint8Array`），现有文本方法保留。 — **Reversibility:** costly — 面向所有宿主的接口扩充。
- **D-08:** **core 不解析文件格式**：资源层只提供**原文（string）/ 原始字节（Uint8Array）**；JSON / JSONC 的解析与序列化**由调用方自己做**。
- **D-09:** 资源内容读取带**缓存池**：设**总字节数上限**，**LRU 淘汰**；写入时同步更新缓存，新建 / 删除 / 移动时失效。（避免内存占用过大。）

### C. 表格 打开 / 新建 / 删除

- **D-10:** 「打开表格」= **一个列表**，分两块：**上半 = 预设表**（外部注入的快捷方式），**下半 = 目录树**（只列 `json` / `jsonc`，且**排除 `*.schema.json` / `*.schema.jsonc`**——它们是 schema 约定文件）。
- **D-11:** **预设表 = 外部注入的静态清单**（每项含显示名 + 数据文件路径）。
- **D-12:** 「新建表格」= 在**用户当前选中的目录**下**一次建一对**文件：`name.json`（数据，初始空对象）+ `name.schema.json`（schema，初始 `{ type: 'object', properties: {} }`）。
- **D-13:** 「删除表格」= 删**数据 + schema 一对**文件；删前**二次确认**；**不可撤销**（与 Phase 3 素材「删字节不可撤销」的方向一致）。 — **Reversibility:** costly — 不可逆的数据丢失路径，一旦放开需引入回收 / 屏障机制。
- **D-14:** 表格面板**目标 = 只给数据文件路径**；schema 路径一律按约定推导，不允许单独指定。 — **Reversibility:** costly — 替换 Phase 2 的 `ITablePanelTarget`（`{ data, schema }`）形状，迁移所有打开器 / 预设 / 测试。

### D. 约定与迁移

- **D-15:** schema 识别与推导 = **纯文件名约定**：数据 `xxx.json` / `xxx.jsonc`，schema `xxx.schema.json` / `xxx.schema.jsonc`（把 `.schema` 插在扩展名前）；文件名以 `.schema.json` / `.schema.jsonc` 结尾即视为 **schema 视图**。 — **Reversibility:** costly — 该约定同时决定表格与素材（Phase 3）的 schema 文件身份。
- **D-16:** **本阶段全部收口**旧契约：修正 `REQUIREMENTS.md` 的 `CORE-01` 与门禁 `scripts/verify/coreFsSurface.js`（原文要求「fs 接口只定义、core/impl 不得引用」，现须反转）；迁移表格命名；回改 `.planning/phases/03-asset/03-CONTEXT.md` 中受影响的条目（D-04/D-05/D-06 等）。

### the agent's Discretion

- 接口名 / 方法名 / 字段名 / 路径常量 / 文件名（索引 API 形状、文件系统完整方法集如是否加 `rename`、删除目录、缓存池上限的具体数值、打开列表做成面板还是弹窗、`coreFsSurface` 门禁改造后的形态）——由研究与规划阶段提出；**命名按项目规则先经用户确认（`INTERFACE-NAME.md`，每 Plan 一节）**。
- 索引与 UI 的关系（文件树面板何时出现、是否是独立面板类型）、导入 / 外部改动如何触发索引刷新——由规划阶段提出。

</decisions>

## Existing Code Insights

### Reusable Assets
- **`editor-impl/table` 表格引擎**（`TableGrid` / `TableRow` / 五类行内控件 / `model/validation` / `schemaPresentation` / 统一撤销提交）：新建 / 删除表格围绕它扩展，不重写。
- **`editor-impl/react` 能力接缝**（`ITablePanelOpener` / `ICodeEditorOpener` / `CapabilityProvider`）：打开列表、外部编辑器照旧经注入实现。
- **Phase 1 外壳**（`ShellSystem.registerPanelType` / `IEditorPanelType` / `onSwitchIn` / `onSwitchOut`）：打开列表与面板类型注册落点。
- **`editor-core` 撤销层**（`undo`）：表格字段编辑仍走统一撤销；表格文件的新建 / 删除按 D-13 不进撤销。
- **dev 宿主**（`packages/apps/editor-dev`）：本阶段改造成「文件系统注入」的验证宿主。

### Established Patterns
- 类先 `interface` 再 `implements`；`type` 别名写 jsDoc、类 / 接口不写；jsDoc 逐参；barrel `export *`；禁 `import type`（见 AGENTS.md §Code style，**注意其与本仓当前 `verbatimModuleSyntax` 配置的差别以 AGENTS.md 为准**）。
- `editor-core` 引擎无关、不解析引擎格式、数据经注入；`editor-impl` 是其默认实现，依赖 `editor-core`。
- 能力包只导出面板类型对象，顶层装配注册（Phase 1.1 D-05 / Phase 2 D-01）。
- 面板在 `onSwitchIn` 里重新请求数据（Phase 2 D-15 修订版 / D-31）。
- 外部能力经注入式接缝（`IXxxPanelParam extends Record<string, unknown>`、`ITableEditorCapabilities`）。
- 样式用 antd + 局部 CSS，不引入 PandaCSS。
- `editor-core` 有模块状态 / `document` 全局门禁（PORT-02）。

### Integration Points
- `EditorCore.initialize` 的注入形状（D-06）——dev 宿主与未来 `@motajs/editor` 都从这里接入文件系统。
- `IEditorPanelContext`（D-01/D-04）——面板读写资源的新入口（按路径）。
- `editor-impl/table` 的 `./table` 子路径导出：面板类型 + 打开的列表 UI + 预设表清单注入。
- schema 文件名约定（D-15）——表格与素材共用的 schema 身份规则。

<specifics>
## Specific Ideas

- 用户原话要点：「把资源层重构一下……文件改为使用路径作为唯一标识符，core 接入 fs 系统，不再是仅定义」「表格编辑需要一部分功能修改，添加打开表格、新建表格、删除表格的功能」「我又想了一下，没有类型号似乎更好，不要类型号了，否则复杂度会提高」「资源系统应该拓展，先对项目本身进行索引，用 readdir 索引，列出资源列表应该不再需要，类似于一个简易的文件资源管理器」「外部应可以配置忽略文件夹，避免索引 node_modules 这类文件夹」「添加缓存池，设定最大尺寸，避免内存占用过大」。
- 打开列表原话：「打开一个列表，列表内分为两个区域，上面是预设表，通过外部传入，是对应表的 shortcut。后面是目录树，过滤出 json jsonc，但是忽略 `.schema.json` `.schema.jsonc`，这些是 schema 约定文件」。
- 命名约定：数据 `xxx.json` / `xxx.jsonc`，schema `xxx.schema.json` / `xxx.schema.jsonc`；面板目标只给数据路径。

</specifics>
