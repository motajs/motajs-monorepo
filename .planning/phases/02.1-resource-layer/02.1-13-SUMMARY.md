# Phase 02.1 Plan 13: 空栏内联控件接口（仅类型）Summary

**把「表格面板空栏内联控件」的类型契约定下来——一个空栏内联视图枚举（三个按钮 / 打开 / 新建 / 删除）、视图状态里承载目录数据的四个可选字段，以及浏览器 / 新建表单 / 空栏控件三组 props 接口；只落类型、不写函数体、不碰任何调用点，editor-impl 保持全绿。**

## Accomplishments

- 在 `table/types.ts` 新增 `TableEmptyMode`（`const enum`，成员 `Buttons` / `Open` / `Create` / `Delete`，与同文件既有的 `TableEditMode` 同形）——它是「某一栏未设表格时当前展示哪个内联视图」的取值类型。放叶子模块 `types.ts` 是为了让面板、`TableGrid`、新的空栏控件都能引用而不引出环依赖。
- 在 `ITablePanelViewState` 追加四个可选只读字段：`emptyMode?`（缺省视作 `Buttons`）、`pickerDirectory?`（内联浏览器当前目录，根为空串）、`pickerEntries?`（该目录直接子条目）、`pickerError?`（目录读取失败提示）。四个字段全部可选，因此既有 `publish` / `publishCommentStrip` / `createColumn` 等构造点一处都不用改。
- 新建三个 `.tsx` 文件，各自只导出 props 接口、无组件函数体：`ITablePickerProps`（可复用表格浏览器）、`ITableCreateFormProps`（可复用新建表单）、`ITableEmptyStateProps`（空栏控件）。
- 用户要求「打开 / 删除两个组件可复用、差异只是有没有预设表」在类型上落为：`ITablePickerProps.presets?` 可选——打开态传入预设、删除态不传；而 `onSelect` 保持**必填**，删除态由空栏控件传一个空操作函数满足契约。

## Decisions Made

- **枚举放叶子模块**：`TableEmptyMode` 放 `table/types.ts` 而非 `tablePanel.ts`——`types.ts` 只 import `../react/types` 与 `json-schema-typed`，被 `tablePanel.ts` / `TableGrid.tsx` / 新的 `TableEmptyColumn.tsx` 同时引用不会成环。
- **四个空栏字段全为可选**：`ITablePanelViewState` 是既有接口，追加可选成员使既有构造点（`TablePanel.publish` / `publishCommentStrip` / `createColumn`）零改动即可通过类型检查——本计划是纯接口先行，不要求实现侧此刻就填这些字段（Plan 15 才接）。
- **`onSelect` 保持必填**：契约不因调用态而变，删除态由 `TableEmptyColumn` 传空操作函数满足（Plan 14 / Plan 15 据此实现），而非把 `onSelect` 降为可选。
- **`ITablePreset` 引入路径**：从 `../../react` 引入（与 `TableListPanelView.tsx` 一致），`IFileEntry` 从 `@motajs/editor-core` 引入，维持依赖方向 `table → react`。
- **仅类型文件也写文件级注释**：三个 `.tsx` 顶部在 import 之后写一句文件级 `//` 说明该契约用途，符合 AGENTS.md §Code style（文件级注释写在 import 之后、正式代码之前）。
