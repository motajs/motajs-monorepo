# Phase 02.1 Plan 04: 项目文件索引 + 内容缓存池 Summary

**初始化时递归全扫把项目建成一棵内存文件树、并给已读内容加一层带字节上限的 LRU 缓存池，两者接进资源系统后目录列举由索引驱动、读写经缓存、增删移同步更新**

## Accomplishments

- 新增 `FileIndex`（`IFileIndex` 实现）：`FileIndex.initialize` 从根递归 `IEditorFileSystem.listDirectory` 建成内存目录树，只存结构（路径 / 文件 / 目录）；按条目名匹配忽略模式（`*` 通配）；`FileIndex.insert` / `FileIndex.remove` / `FileIndex.move` 同事务式维护父目录与子树，`FileIndex.move` 递归重写子树路径并保留节点。
- 新增 `ContentCache`（`IContentCache` 实现）：总字节上限（缺省 `CONTENT_CACHE_MAX_BYTES`）+ LRU 淘汰；`ContentCache.get` 命中即刷新使用序、返回同一引用；`ContentCache.set` 计入字节并淘汰最旧；`ContentCache.invalidate` / `ContentCache.clear`；单条超上限不入缓存。
- 把索引与缓存接进 `ResourceSystem`：`ResourceSystem.listDirectory` 改由索引驱动；`ResourceSystem.readContent` / `ResourceSystem.readBinary` 命中缓存即返回、缺页回源写回；`ResourceSystem.writeContent` / `ResourceSystem.createResource` 写入后同步缓存；`ResourceSystem.createResource` / `deleteResource` / `moveResource` 同步更新索引与失效缓存；`ResourceSystem.dispose` 清空二者。
- editor-core 整包 **87 用例全绿**、`tsc -b` 退出 0；`coreImportType` / `coreModuleState` / `coreEngineNeutral` 三条门禁均退出 0。

## Decisions Made

- 忽略模式按**条目名（路径末段）**匹配、支持 `*` 通配（A3）；索引 / 缓存键为 `/` 规范化相对路径**精确比对**、暂不做大小写折叠（A5），契约由 `IEditorFileSystem` 注释保证。
- `ContentCache.set` 遇到**单条内容超过总上限**时**不入缓存**（择一并在代码注释写明），避免一条就撑满并挤掉全部其它条目。
- `ResourceSystem.readBinary` 做成**类上的公开方法**（不加入 `IResourceSystemAccess`）：本阶段面板上下文未暴露二进制入口，但计划要求「至少内部支持并在测试中覆盖」；不改 Plan 01 的公开类型形状。
- `ResourceSystem.updateResource` 在广播钩子前先 `this.cache.invalidate(id)`，恢复 D-09 的「外部更新后缓存失效」语义（否则 `ResourceSystem.requestResource` 会经 `Resource.readContent` 返回陈旧缓存）。

**1. [Rule 2 - Missing Critical] updateResource 未失效缓存导致外部更新后读到陈旧内容**
