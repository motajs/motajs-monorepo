## Decisions Made

- **`createTableHarness` 返回 `EditorCore`，不自行注册面板类型**：计划示例提到「注册 tablePanelType」，但 `tracer` 有一条用例断言「真实 `tablePanelType` 可注册进外壳」（`listPanelTypes()` 恰为 `['table']`）。若 harness 预注册任何 id 为 `table` 的类型，该断言必红。故 harness 只负责装配并初始化核心，面板类型注册仍留在各测试内——既保住该断言，又不新增对外命名（仅 `FakeFileSystem` + `createTableHarness` 两个已获确认的名字）。
- **seed 先于核心初始化**：文件索引在 `EditorCore.initialize` 时递归全扫建树，`fs.seed` 之后不再更新索引。为让存在性探测（schema 文件是否在列）与真实使用一致，所有预置都移到 `createTableHarness` 之前（与 editor-core 测试 `fs.seed(...) → createCoreHarness(fs)` 的既有约定一致）。
- **面板按「存在性」区分缺失与读取失败**：资源层按原文读取时，`fs.readFile` 对「文件不存在」与「读取失败」都抛错，无法区分；而表格需要「表可无 schema（缺文件 → 空 schema 态）」与「schema 存在但读不出（→ 错误态）」两种不同结果。故先经目录条目确认 schema 文件是否存在，再读取。
