<objective>
给开发宿主补一个**真正可用的代码编辑器**，让表格工具栏「更多 → 在代码编辑器中打开」不再点了没用——用户点开后能看到当前栏对应的文件原文（合规 `.jsonc` 就是「系统前缀注释块 + JSON 正文」），可以改一个值再确认写回，从而能用人眼核对「保存后系统前缀逐字保留」。

这是解决 UAT 缺口 `G-02.1-4` 的全部内容。缺口现状：`packages/apps/editor-dev/src/main.tsx` 只向 `CapabilityProvider` 注入了 `tablePanel` 打开器（还有 `tablePresets`），**没有**注入 `ITableEditorCapabilities.codeEditor`；`TableGrid` 见 `capabilities.codeEditor === undefined` 就把「在代码编辑器中打开」置为禁用，用户没有查看文件原文的入口，也就无法核对 Plan 18 的 `.jsonc` 系统前缀往返（该行为本身已有 `tableText.test.ts` 自动化覆盖，缺的只是开发宿主里的目视入口）。

**为什么本缺口不设「仅接口」第一步：** 项目规则「先接口、后实现」针对的是**接口 / 类型的设计**。本缺口所需的两处契约**都已在既有代码中存在**——接缝 `ICodeEditorOpener`（`packages/libs/editor-impl/src/react/capabilities.ts`）与 Provider props `ITableCapabilitiesProviderProps`（同文件）；本轮**不新增任何 interface / type**，只写宿主侧实现与注入，故不切出单独的接口计划。新增的唯一对外符号是开发宿主组件 `DevCodeEditorProvider`，其命名已登记在 `INTERFACE-NAME.md` 的 `## Plan 25`（Task 3 会把该段落的状态由「待用户确认」改为「已确认」，使登记状态与代码实际状态一致）。

Purpose: 把「在代码编辑器中打开」在开发宿主里接通，使 UAT 测试 2 的「前缀逐字往返」可目视验收。
