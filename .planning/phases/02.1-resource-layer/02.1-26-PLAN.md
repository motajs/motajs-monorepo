<objective>
把「新建表格」的确认入口从新建视图的**底部**移到**顶部**：用户点「新建表格」进入新建视图后，先看到的应是「新建表格」按钮（点开后变成名称输入），目录浏览器排在它下面——选完目录后不必再向下找按钮。

这是解决 UAT 缺口 `G-02.1-5`（severity minor，来自 UAT 测试 1）的全部内容。缺口现状：Plan 22 落地的 `TableCreateForm` 组件返回的 Fragment 顺序是「新建位置区（目录树）→ 确认入口（按钮 / 名称输入）→ 错误提示」，确认入口因此落在最底部；用户报告「打开新建表格界面，选完目录后我找了一小会才找到按钮在最底下，有点反直觉」。

**为什么本缺口不设「仅接口」第一步：** 项目规则「先接口、后实现」针对的是**接口 / 类型的设计**。本缺口只是一次**组件内部子元素顺序的调整**，`ITableCreateFormProps` 契约、`data-test-id`、class 名、props 全部不变，**不新增任何 interface / type / 对外符号**，故不切出单独的接口计划（同 Plan 25 对本轮缺口的判定）。

Purpose: 让新建表格的确认入口在视觉上位于顶部，消除「选完目录还要向下找按钮」的反直觉。
Output: `TableCreateForm` 一次子元素顺序调整 + 组件级与面板内两层可失败 DOM 顺序断言 + 三包 / 五门禁签核 + UAT `G-02.1-5` 收口登记。

**范围界定：** 不改 `ITableCreateFormProps`、不改 class 名 / `data-test-id`、不改 `TableEmptyColumn` / `TablePicker` / `table.css` / 任何面板代码；不改 `editor-core` / `editor-dev` 源码；不引入新依赖。
</objective>
