# Phase 02.1 Plan 10: 开发宿主接入（fs 注入 + 列表面板 + 预设表） Summary

**开发宿主从「资源注入后端」改成「文件系统注入宿主」：同一个内存对象既当文件系统又提供撤销步数，演示表与示例文件按真实路径 seed；「打开表格」列表面板在此注册，预设表演示表经能力接缝注入，打开 / 新建 / 打开新表 / 删除全程可在测试与浏览器里跑通。**

## Accomplishments

- `MemoryBackend` 重写为 `IEditorFileSystem` 的内存实现：按路径 `Map<string, string | Uint8Array>` 存内容、`seed(path, content)` 预置并登记父目录、带类型 `listDirectory`、二进制读写、`moveFile` 迁移子树；越界（含 `..` 段）路径抛错。旧的按类型分桶注入方法（`requestResource` / `requestResourceList` / `writeResource` / `createResource` / `deleteResource`）全部删除。
- `IMemoryBackend` 改为 `extends IEditorFileSystem`，只增 `maxUndoStep`（撤销注入）与 `seed` 两个成员——同一个对象既作文件系统、又作撤销注入。
- `main.tsx` 装配改为 `core.initialize({ fs: backend, maxUndoStep: backend.maxUndoStep, ignore: ['node_modules', '.git'] })`；注册演示 / 表格 / 列表三种面板类型；经 `CapabilityProvider` 注入 `{ tablePanel, tablePresets }`。
- 演示数据路径化：`TABLE_DEMO_DATA_PATH`（`tables/demo.json`）/ `TABLE_DEMO_SCHEMA_PATH`（`tables/demo.schema.json`）/ `DEMO_SAMPLE_PATH`（`demo/sample.txt`）替代原资源标识；数据 / schema 改以文本 `seed`；`TABLE_PRESETS` 暴露预设表清单；`openTableDemoPanel` 改为打开列表面板。
- 新增端到端用例：打开列表面板 → 预设打开演示表并渲染 schema 驱动行 → 在 `tables` 目录新建 `hero.json` + `hero.schema.json` → 打开新表 → 删除并确认后目录树与内存 fs 双双消失。

## Decisions Made

- **`MemoryBackend.moveFile` 迁移子树**：把源路径下的全部文件与已显式创建的目录按前缀整体搬迁（与 `FileIndex.move` 的子树语义一致），而非只搬单个文件；越界拒绝沿用「任一路径段为 `..` 即抛错」，与 `FakeFileSystem` 同形（承接 T-02.1-23）。
- **迁移测试直接打开表格面板**：`openTableDemoPanel` 按计划改为打开列表面板；对仍需断言表格渲染的既有用例，测试内新增本地 helper `openDemoTable(core)`，直接带 `{ target: { dataPath } }` 打开表格面板——不引入任何新的对外命名。
- **演示数据改为文本**：`TABLE_DEMO_DATA` / `TABLE_DEMO_SCHEMA` 由对象改为 `JSON.stringify(..., null, 2)` 文本，随 `seed` 进内存 fs；表格面板按 `.json` 严格 JSON 路径解析（Conforming）。测试经 `JSON.parse` 读回断言。
- **`DEMO_SAMPLE_CONTENT` 文案保持原值**（“来自内存后端的示例内容”），仅把寻址方式由资源标识改为路径。

- **Issue:** Task 1 提交的 `MemoryBackend.moveFile` 中，删除旧目录项的循环写成了 `for (const directory of directories) this.directories.delete(directory)`——把 `readonly [string, string]` 元组当成 string 传给 `Set.delete`，`typecheck` 报 `TS2345`；运行期也删不掉旧目录键。
