<objective>
用一条**端到端最短路径**把「核心驱动注入的文件系统」跑通：内存文件系统 → `EditorCore.initialize({ fs })` → 面板按路径读 → 写回原文；并借此把 editor-core 的实现文件从旧契约（类型号 / 列表接口 / 资源注入）迁到新契约，删掉「按类型列资源」整条链路，迁移既有测试，使整包恢复全绿。

Purpose: 这是本阶段架构的「子弹切片」——先用一条真实路径证明「路径即标识 + 核心驱动 fs」走得通，再在 Plan 04 长出索引 / 缓存、在 Plan 06 长出表格。同时 Wave 0 的共享 `FakeFileSystem` 是收敛迁移改动面的关键前置（RESEARCH §Pitfalls 7）。

Output: 可运行的 `FakeFileSystem` 与装配工厂、端到端 tracer 测试、路径化的 `ResourceSystem` / `Resource` / `PanelContext` / `EditorCore` / `ShellPanelHooks`，以及迁移后的 editor-core 既有测试。

**分期说明：** 本计划只实现「读 / 写 / 列目录委托 fs」与「删旧接口」；**不**实现索引树、LRU 缓存池、忽略模式（Plan 04 实现）。核心在这一步可直接委托 `fs`（无缓存 / 无索引）。
</objective>
