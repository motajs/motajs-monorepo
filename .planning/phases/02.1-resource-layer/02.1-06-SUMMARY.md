## Decisions Made

- **每栏单槽 `prefix` / `pendingStrip`**：一栏记住一个系统前缀、暂存一个待确认宽松值；确认 / 取消针对该栏**主文件**（数据视图为主数据文件、schema 视图为该 schema 文件）。写回时按该栏前缀逐字还原——遵循计划对 `column.prefix` / `column.pendingStrip` 的单值描述。
- **打开三段检测落在 `TablePanel.refresh`**：读原文后 `parseTableText` 分类；`NeedsCommentStrip` 不立即打开（暂存宽松值 + `commentStripPending=true`），`Invalid` 落 `Error`（不抛穿，D-29）。数据视图的镜像 schema 文件按同样规则宽松取 `value`（schema 侧非合规不单独弹框——单槽约束下的取舍，见下）。
- **确认框不是注入接缝**：`renderCommentStripModal` 直接在 `TableColumn` 视图内用 antd `Modal` 渲染，确认 / 取消经 `ITablePanelViewProps.onConfirmCommentStrip` / `onCancelCommentStrip` 转交 `TablePanel.confirmCommentStrip` / `cancelCommentStrip`；未新增 `IConfirmOpener` / `IConfirmRequest`，未改 `src/react/types.ts` / `src/react/capabilities.ts`。
- **外部代码编辑器返回文本改用 `parseTableText`**：打开内容现带系统前缀，纯 `JSON.parse` 会误判；改为 `parseTableText` 并只接受 `Conforming`，保留原「内容不是合法的 JSON，未写回」的严格性，同时把返回文本记住的前缀更新回该栏。

- **Issue:** 计划要求 `openCurrentViewInCodeEditor` 的打开内容改用带系统前缀的序列化文本，但未说明返回文本的解析方式。原实现用纯 `JSON.parse`（`parseJsonRecord`），带前缀的返回文本会被其判定为非法 JSON 从而永远无法写回——与「内容带前缀往返」直接冲突。
