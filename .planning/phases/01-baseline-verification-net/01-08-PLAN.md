<objective>
Adopt Prettier as the repository's single formatting authority — installed as pinned root devDependencies, configured to match the existing code style with quotes unified on single quotes, enforced through ESLint via `eslint-plugin-prettier`, and applied to the whole tree — so the lint gate that plan 01-06 delivered stops failing on formatting and generated output.

Purpose: the lint layer of the four-layer PR gate (D-01) cannot be green while the repo has no single formatting authority, and D-02 requires that gate to cover every workspace package — including the shared-root-config packages where the two `@stylistic/*` errors live. The user adopted Prettier and asked for exactly one quote style, all single. Today the repo has two competing authorities and no agreement between them: the root `@stylistic` config demands double quotes while the editor's own config has no quote rule at all, so `packages/apps/editor/src/blockly/registry/path.ts` uses single quotes and `packages/apps/editor/src/Workbench/modals/CheckboxSet/CheckboxSetModalContext.tsx` uses double quotes in the same codebase; a stale `packages/apps/editor/dprint.jsonc` (dprint's default is alwaysDouble) sits unused and would contradict a single-quote decision; and the baseline lint run reports `@stylistic/quotes` plus `@stylistic/no-multiple-empty-lines` as errors (2 of the 46) with 2 more coming from the PandaCSS-generated `styled-system` tree that is build output, not source. This plan removes the ambiguity, removes the 4 formatting/generated errors, and does it as a mechanical change with no production semantics touched.
Output: `.prettierrc.json`, `.prettierignore`, a `.gitattributes` line-ending policy, the three catalog-pinned devDependencies and two root scripts, a Prettier setup verifier, both ESLint configs rewired, a reformatted tree, and the documentation sync that keeps `CONVENTIONS.md` / `AGENTS.md` honest about the new quote convention.
