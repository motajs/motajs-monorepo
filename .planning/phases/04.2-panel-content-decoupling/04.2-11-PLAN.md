<objective>
让表格面板实现关闭三态：无脏直接允许关闭；有脏时在自己的视图里弹共享确认框；保存失败保持打开；选丢弃时清脏以抵消 `dispose` 的兜底保存。

Purpose: D-08…D-11 是关闭流程的完整语义，D-38 规定弹窗必须挂在面板自己的 DOM 上（外壳询问前已把标签切活动）。研究 §Q3.1 特别指出：只跳过 `onSwitchOut` 不够，`TablePanel.dispose` 还会再存一次，必须同时实现 `onDiscard`。**修订要点**：表格面板铺出多栏，每栏各有自己的 `ITablePanelViewState`（`TableColumn` 用 `getStore(columnIndex)` 订阅），因此弹窗开关**不能**放进栏级状态——否则要么三栏各弹一个框，要么只有第 0 栏能弹、取消也清不掉别的栏。本计划把「关闭弹窗」提升为**面板级一份状态**，在 `TablePanelView` 根上渲染一次（AGENTS.md「先接口、后实现」：`ITableCloseDialogState` 由 Plan 03 声明，本计划只引用）。
Output: `TablePanel.onRequestClose` / `TablePanel.onDiscard` + 面板级 `TablePanel.closeDialogStore` + 视图根上的三态弹窗，以及一组把四个分支钉死的测试。

**B1 修订影响：最小改动。**
- `ShellSystem.closeTab` 现在会 `await this.activateTab(tabId)` **再**询问面板（D-38 的「先切到目标标签」因此真正等到了切换完成），所以面板可以把三态弹窗挂在自己的 DOM 上再结算——本计划的实现方式不变。
- 关闭询问期间旧面板仍然挂载（B1），`TablePanel.onRequestClose` 里读 `TablePanel.isColumnDirty` / 组件 ref 是安全的。
- Task 2 第 (7) 条「普通切走仍然落盘」必须写成 `await act(async () => { await shellSystem.activateTab(别的标签) })`；不 `await` 会让断言跑在保存结算之前。
- **不要**新增第二个保存钩子（如 `onBeforeSwitchOut`）：关闭的保存仍走 `TablePanel.onRequestClose` 自己调 `TablePanel.save`，普通切走仍走 `TablePanel.onSwitchOut`。
</objective>

    - 有脏时把**面板级**弹窗状态置为「打开、无保存中、无错误」（写进 `TablePanel.closeDialogStore`），返回一个在用户选择前不结算的 Promise；用户点按钮时结算为对应枚举。Promise 的结算函数与「当前是否已结算」都由面板字段持有，重复点按只结算一次。
    - 用户选 `Save`：置 `saving: true`，逐栏 `await this.save(i)`；任一失败 → 把错误文案写进弹窗状态的 `error`、清 `saving`，并结算为 `Cancel`（D-09「保存失败保持打开」）；全部成功 → 清 `saving`、关闭弹窗，结算为 `Save`。
    - 用户选 `Discard`：关闭弹窗、结算为 `Discard`（真正的清脏在 `onDiscard`）。
    - 用户选 `Cancel`：关闭弹窗、结算为 `Cancel`。

    实现 `TablePanel.onDiscard(): void`：对每个挂载中的组件调 `ref.markSaved()`，并把各栏 `unsaved` / `unsavedSchema` / `draftDirty` 全部清掉、`column.draft` 设为 `null`，使随后 `dispose → saveDirtyColumns → isColumnDirty` 判为干净（空操作，D-10）。`onDiscard` 不得写盘、不得登记撤销。

    状态归属（这是本轮修订的核心）：**新增面板级 `closeDialogStore: Store<ITableCloseDialogState>`**，在构造期以 `{ open: false, saving: false }` 建一次；`ITableCloseDialogState` 用 Plan 03 声明的类型，**不要**往每栏一份的 `ITablePanelViewState` 上加 `closeDialogOpen` / `closeDialogSaving` / `closeDialogError`（那会让三栏各弹一个框、取消只能清掉被点的那一栏）。`ITablePanelViewProps` 追加两个成员：`readonly closeDialogStore: Store<ITableCloseDialogState>` 与 `readonly onCloseChoice: (choice: PanelCloseChoice) => void`（`onCloseChoice` 构造期绑定一次，稳定引用）——`ITablePanelViewProps` 是与组件同文件、不导出的私有 props，本次只加字段，**不新增任何具名形状**（成员类型全部来自 Plan 03 的 `ITableCloseDialogState` 与 Plan 02 的 `PanelCloseChoice`）。`TablePanelView` 用 `useStore(props.closeDialogStore)` 订阅，`open === true` 时在**多栏容器之后**渲染**一个** `PanelCloseDialog`（`saving` / `error` 原样透传、`onChoose={props.onCloseChoice}`），`open === false` 时不挂载（关闭后不在 DOM）。`TablePanel.render()` 把这两个成员一并传给 `TablePanelView`。`TableColumn` 与本计划无关地继续只订阅读它自己那份栏级状态。

    不要改 `TablePanel.onSwitchOut` 的语义（D-11），也不要给 `dispose` 加参数。
