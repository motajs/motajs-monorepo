## Pattern Assignments

### A1. 关闭三态：`IEditorPanel` + `ShellSystem.closeTab` / `ShellSystem.discardTab`

**Analog:** `packages/libs/editor-core/src/panel/types.ts:49-69`、`packages/libs/editor-core/src/shell/shellSystem.ts:595-628,768-802,809-812`

**接口现状（必须加法式扩展，不要改旧签名）** — `panel/types.ts:59-69`：

```ts
  /**
   * 当用户主动关闭承载此面板的标签时，外壳在释放面板实例前询问是否允许关闭
   *
   * 返回 `true` 表示允许关闭；返回 `false` 表示取消关闭，标签保留且实例不释放。
   * ...
   */
  onBeforeClose?(): Promise<boolean>;
```

新增成员应紧挨它，复用同一段 JSDoc 风格（逐参数 `@param`、换行块、说明「外壳何时调用 / 不调用」）。`PanelCloseChoice` 的 `const enum` 形态照抄 `fs/types.ts:1-6`：

```ts
export const enum EditorEntryKind {
  /** 普通文件 */
  File,
  /** 目录 */
  Directory,
}
```

**`ShellSystem.closeTab` 现状** — `shellSystem.ts:595-628`：

```ts
  async closeTab(tabId: string): Promise<void> {
    ...
    if (tab.instanceId !== null) {
      const instanceId = tab.instanceId;
      const instance = this.instances.get(instanceId);

      if (instance !== undefined && instance.onBeforeClose !== undefined) {
        // 询问前先把目标标签切成活动标签：面板的未保存对话框需要挂在自己的 DOM 上才可能 settle
        if (this.activeTabId !== tabId) this.activateTab(tabId);

        let allowed = false;

        try {
          allowed = await instance.onBeforeClose();
        } catch {
          // 钩子自身出错时按「取消关闭」处理：数据安全优先，绝不把异常抛给点击关闭的人
          logger.error('shell.beforeCloseFailed', this.instanceTypes.get(instanceId) ?? '');
          return;
        }

        if (!allowed) return;
      }
    }

    await this.discardTab(tabId);
  }
```

**`ShellSystem.discardTab` 现状** — `shellSystem.ts:768-802`：

```ts
  private async discardTab(tabId: string): Promise<void> {
    ...
    const tab = this.tabs[index];
    // 必须在这里重新判定：为询问而激活过的后台标签，调用方手里的旧值仍是「非活动」，会跳过切邻
    const wasActive = this.activeTabId === tabId;

    if (tab.instanceId !== null) {
      if (wasActive) await this.leaveActiveInstance(tab.instanceId);
      await this.closePanelInstance(tab.instanceId);
    }
    ...
  }
```

**关键陷阱（必须写进计划）** — `shellSystem.ts:809-812`：`leaveActiveInstance` 同时做「清记录」与「排切出」，`skipFlush` 不能连清记录一起跳过，否则邻居拿不到 `onSwitchIn`：

```ts
  private leaveActiveInstance(instanceId: string): Promise<void> {
    this.lastActiveInstanceId = null;
    return this.enqueueSwitchOut(instanceId);
  }
```

落点：
- `IEditorPanel.onRequestClose?()` / `IEditorPanel.onDiscard?()` 加在 `onBeforeClose` 旁；
- `ShellSystem.closeTab` 增加三态分支（`Save` / `Discard` / `Cancel`），`Discard` 先调 `IEditorPanel.onDiscard` 再 `discardTab(tabId, true)`；
- `ShellSystem.discardTab` 增加「跳过切出落盘但仍清 `lastActiveInstanceId`」选项；
- `unregisterPanelType` / `EditorCore.dispose` / `openPanelInTab` 三条路径**不得**调用 `onRequestClose` / `onDiscard`（保持 04.1 约定）。

### A2. 文件变化流：`IEditorFileSystem.watch?` + `ResourceSystem` + `IResourceSystemHooks.onResourceChange?`

**Analog:** `packages/libs/editor-core/src/fs/types.ts:15-69`、`resource/types.ts:177-183`、`resource/resourceSystem.ts:29-33,141-159`、`resource/fileIndex.ts:97-117`

**唯一通知入口** — `resourceSystem.ts:141-153`：

```ts
  async updateResource(id: IResourceIdentifier): Promise<void> {
    this.cache.invalidate(id);
```

**订阅 / 退订落点** — `resourceSystem.ts:29-33,155-159`：


**索引增删** — `fileIndex.ts:97-117`（`insert` 自动补父目录、`remove` 递归摘子树；**不做路径校验**，校验必须放在 `ResourceSystem.handleFileChange` 入口）：

```ts
  insert(path: string, kind: EditorEntryKind): void {
    if (path === '' || this.nodes.has(path)) return;
    ...

  remove(path: string): void {
    if (path === '' || !this.nodes.has(path)) return;
```

落点：
- `fs/types.ts` 新增 `EditorFileChangeKind`（`Add` / `Change` / `Delete`）、`IEditorFileChange`、`IEditorFileSystem.watch?`；
- `resource/types.ts` 在 `IResourceSystemHooks` 新增 `onResourceChange?(identifier, kind)`（**不预读内容**，删除事件才不会抛）；
- `resourceSystem.ts` 在 `initialize` 订阅、`dispose` 退订；`handleFileChange` 先校验路径（空 / 绝对 / 含 `..` 段），再 `index.insert/remove`、`cache.invalidate`，最后通知 hooks；**不做内容比较、不吞事件**（D-15）。

## Shared Patterns

### S1. 枚举 / 接口 / 可选成员

- 枚举一律 `const enum` + 数字 + 大驼峰成员；本阶段新增：`PanelCloseChoice`（`Save` / `Discard` / `Cancel`）、`EditorFileChangeKind`（`Add` / `Change` / `Delete`）、`ContentSaveStatus`（`Saved` / `Failed`）。
- 接口成员默认 `readonly`；只有外部确实要改的才不 readonly。
- `?.` 只允许「副作用调用」与「Required 化」两种场景；判断地图路径时先 `const mapId = capabilities.resolveMapPath?.(path)` 再判断，不要重复 `?.` + `!`。
- **禁止 `import type`**（`scripts/verify/coreImportType.js` 扫两个包全部 `*.ts` / `*.tsx`，含测试）；类型再导出用 `export type`。
- **禁止内联对象类型 / 对象联合类型**：props 用 `interface`，工厂返回参数用 `Record<string, unknown>` 是既有例外（`IEditorPanelType.createOpenParam`）。
- 不用字符串做键 / 特殊标识符；状态用 `const enum`。

### S2. 类 / 接口 / 工厂 / 桶

- **所有类必须先有 `interface` 再由类 `implements`**：现有 `TablePanel implements IEditorPanel, ITablePanel`（`tablePanel.ts:555`）、`AssetPanel implements IEditorPanel, IAssetPanel`（`assetPanel.ts:225`）是模板；`FileExplorerPanel` 也要先写 `IFileExplorerPanel`。
- 面板类型用 `Object.freeze({...})`（`tablePanelType.ts:45`、`mapPanelType.ts:54`、`assetPanelType.ts:60`）。
- 桶文件一律 `export *`，**不跨目录深路径转发**：`shared/index.ts` 只能 `export * from './fileBrowser'`，不能 `export * from './fileBrowser/FileBrowser'`。
- 新子路径 `./explorer` 加到 `packages/libs/editor-impl/package.json` 的 `exports`；**不要**把它加进 `src/index.ts` 根 barrel（`.dependencyCruiser.cjs:37-45` 的根 barrel 规则与「能力 subpath」约定）。

### S3. CSS / antd

- 复用 `--editor-*` 变量（含字面量 fallback），新表面不设主题。
- 弹窗样式优先复用 `.eimodal-*`（`react/modal.css`）；浏览器用新 `efb-*`；资源管理器用 `efx-*`；面板弹窗用 `edlg-*`。
- 行 / 面包屑 / 聚焦环：原生 `button` + `:focus-visible { outline: 2px solid var(--editor-accent); outline-offset: -2px }`（UI-SPEC 已定）。
- 不引入图标库；图标是内联 SVG 16px、`currentColor`、`aria-hidden`（`tablePanelType.ts:10-31` 是模板）。
- 路径 / 文件名一律 React 文本节点，绝不 `dangerouslySetInnerHTML`。

### S4. 测试

- 三包统一 `vitest run` + jsdom + `@testing-library/react`；`configure({ testIdAttribute: 'data-test-id' })`。
- 每个 `it` 之前一条单行注释说明覆盖内容（项目规则）。
- 共享测试替身**各持一份**：`editor-core/src/__tests__/fixtures.ts`、`table/__tests__/fixtures.ts`、`asset/__tests__/fixtures.ts`、`map/__tests__/fixtures.ts`。本阶段只给「本波真正需要发事件」的那一份加 `watch`（默认关闭）。
- 时序测试用 `act()` + 事件数组 + 可释放的 gate（`shellAutosave.test.ts`），不要靠 `setTimeout`。
- 迁移断言时保留 `notes.txt` 仍为 `null` 的用例（证明过滤不是「全收」）。

### S5. 门禁 / 边界

- 生效门禁：`coreEngineNeutral` / `coreModuleState` / `coreImportType` / `coreBoundaries` 必须 exit 0；`implExports` / `coreExports` **当前就是红的**，不要列入本阶段门禁（研究 §Q7.3）。
- `.dependencyCruiser.cjs:54-62` 的能力互斥正则要加 `explorer`，让「资源管理器直接 import 表格的 `isTableDataPath`」当场变红。
- `explorer` 不 import `table` / `map` / `asset`；`shared` 可被能力目录引用。
- **`.editor` 不进 `ignore`**：地图偏好依赖索引收录（`mapPanel.ts:683-690` 的 `hasProjectFile` 走 `listDirectory`）；资源管理器靠 `filter` 隐藏点开头路径段（F3 / R5）。

## Risks & Tensions（没有完美 analog 的地方）

1. **`FileBrowser` 受控 vs 自持状态**：`TablePicker` 是纯受控（目录 / 条目由面板给），研究提案的 `FileBrowser` 自持目录状态。选后者会让资源管理器很薄，但表格空栏的 `TableEmptyColumn` / `TablePanel` 需要改传 `loadChildren`；选前者则资源管理器要自己维护目录。**必须在接口计划定死，不能两波各写一半。**
2. **`EditableTable` 与 `TableGrid` 的边界**：现有 `TableGrid` 是 `memo` 包装、纯 props、大量测试直接断言 DOM。把 `TableGrid` 本身改成 ref 契约风险高；建议**新增 `EditableTable` 包住 `TableGrid`**（`TableGrid` 继续纯 props），但 `getData` 只能拿到「已 blur 提交」的输入（`TextareaInput.tsx:54-83`），切换标签时鼠标点标签会先 blur、键盘 / 程序化切换不会。不要为此改交互（D-22）。
3. **关闭三态与 `dispose` 兜底保存**：`TablePanel.dispose` 会 `saveDirtyColumns`（`tablePanel.ts:608-610`），只跳过 `onSwitchOut` 仍会写盘。必须同时用 `IEditorPanel.onDiscard` 清脏，否则「不保存关闭」做不到（研究 §Q3.1）。
4. **地图按路径打开**：`IMapEditorCapabilities` 没有路径概念（`map/types.ts:340-404`），演示宿主真实路径是 `content/map/<id>.json`（`mapFiles.ts:370-374`）。不补 `resolveMapPath`，资源管理器只能把地图从候选里排除（R3）。
5. **过滤口径**：F1 已确认 `.json` + `.jsonc`（含 schema），但这会反转 `tableEmptyColumn.test.tsx` / `openNewDelete.uat.test.tsx` 的 3 处断言；删除态必须保持「不含 schema」（F2 / Pitfall 8），否则用户能直接删任意 schema。
6. **外部变化与全局撤销**：`UndoSystem.undo` 只取栈顶、不看活动面板（研究 R2）。表格草稿下沉到组件后，**面板必须持有交回副本**，撤销对象是这份副本（`tablePanel.ts:1639` 的 `applyUndoRedo` 现从 `column.data` 现算，改动面可控）。
7. **`onSwitchOut` 前组件可能已卸载**：`ShellSystem.activateTab` 先 `notify()` 后排切出（`shellSystem.ts:630-641`、`:819-832`），ref 可能为 `null`。`EditableTable` 用 `useLayoutEffect` cleanup 交回草稿；外壳顺序防御是第二道保险（研究 R1 / A1）。
8. **`.editor` 可见性**：索引必须收录（地图偏好 `mapPanel.ts:683-690`），资源管理器 `filter` 隐藏点开头路径段；**不要**改 `ignore`（R5 / Pitfall 6）。
9. **`implExports.js` 是红的**：不要为了新增 `./explorer` 去修它或把它当门禁；如果将来修，必须同时补 `EXPECTED_SUBPATHS` + 恢复 `subpathStatus.json`（研究 §Q7.3）。
10. **`IMapEditorCapabilities.resolveMapPath` 的 `?.` 写法**：项目规则限制 `?.` 与 `!`；用「先取值再判断」，不要写成 `capabilities.resolveMapPath?.(path) !== undefined && capabilities.resolveMapPath!(path) !== null`（研究 §Q5.3 自己也提醒了）。
