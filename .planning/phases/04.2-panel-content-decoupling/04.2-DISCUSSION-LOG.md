## 内容归属

| Option | Description | Selected |
|--------|-------------|----------|
| 不需要实时同步 | 外部只传初始内容，保存时交最终内容 | ✓ |
| 每次改动通知外部 | 面板内部维护，但每次编辑发事件 | |
| 外部完全控制 | 受控组件，外部回传新内容 | |

**User's choice:** 不需要实时同步。
**Notes:** 随后用户进一步澄清：不存在「面板接收内容」这种模式。面板唯一知道路径，负责读文件并分配给组件；组件不接触路径，只接收内容，内部编辑，需要保存时发信号。

## 保存触发

| Option | Description | Selected |
|--------|-------------|----------|
| 按面板声明，默认自动 | 每个面板声明保存时机 | |
| 全部自动保存 | 切走 / 关闭统一自动写回 | |
| 全部手动保存 | 只有点保存才写 | |

**User's choice:** 自由文本修正。
**Notes:** `onSave` 是组件内部触发的保存信号，不是面板到点自动调用；组件同时暴露读取当前内容的接口，外部主动保存时拉取。切走时由面板主动 `getData()` 后保存，不走 `onSave`。

## 保存信号

| Option | Description | Selected |
|--------|-------------|----------|
| 带内容 + getData | `onSave(content)` 带快照，同时保留拉取接口 | ✓ |
| 裸信号 | `onSave()` 后再 `getData()` | |
| 只带内容 | 不提供拉取 | |

**User's choice:** 带内容，同时保留 `getData()`。

## 保存结果

| Option | Description | Selected |
|--------|-------------|----------|
| `onSave` 返回 Promise<结果> | 组件等待保存结果并显示成功 / 失败 | ✓ |
| 纯信号 + 面板回传结果 | 失败时通过额外通道告诉组件 | |
| 组件不显示保存结果 | 由面板自己的提示区展示 | |

**User's choice:** `onSave` 返回 Promise<结果>。

## 可能的保存时机（切走）

| Option | Description | Selected |
|--------|-------------|----------|
| 按面板类型决定 | 表格手动、地图自动 | |
| 一律强制保存 | 所有面板切走都保存 | |
| 一律不强制 | 只有点保存才存 | |

**User's choice:** 自由文本修正。
**Notes:** 组件不提供 `save()`；`onSave` 只由组件内部触发。切走时面板调用 `getData()` 自己保存；关闭时如果有未保存改动，提示并阻断关闭。用户指出这可能需要改 `editor-core`。

## 关闭流程

| Option | Description | Selected |
|--------|-------------|----------|
| `onBeforeClose` 返回三态 | 保存关 / 丢弃关 / 取消；丢弃跳过 `onSwitchOut` | ✓ |
| `onBeforeClose` 返回 `{ allow, save }` | 两个布尔值表达 | |
| 不改 core，面板设标记 | 依赖面板自觉 | |

**User's choice:** 三态。
**Notes:** 讨论中发现当前关闭流程在 `onBeforeClose` 之后仍会调用 `onSwitchOut` 落盘，导致「不保存关闭」无法实现；因此 core 必须支持跳过落盘。用户曾提出 `onForbidClose` / `onForbidSwitchOut` 方案，讨论后改为三态。

**User's choice:** 保存并关闭 / 不保存关闭 / 取消。

## 改造范围

| Option | Description | Selected |
|--------|-------------|----------|
| 只拆表格，接口做成通用的 | 风险最小 | |
| 表格 + 素材 + 地图全部拆 | 一次到位 | ✓（分波次） |
| 只拆表格，接口只服务表格 | 不提前抽象 | |

**User's choice:** 04.2 内分波次全拆。
**Notes:** 用户澄清不是「整个面板做成一个组件」，而是面板里的每个功能区都可以是独立组件。例如地图区、素材区各自是组件；素材面板类似；表格每栏是组件。

**User's choice:** 分波次全拆（通用契约 → 表格 → 资源管理器 → 地图区 / 素材区）。

## 文件变化同步

| Option | Description | Selected |
|--------|-------------|----------|
| 资源层写后通知 + 宿主 watch 补充 | 两个宿主都覆盖 | |
| 只靠宿主 watch | service-worker 无 watch | |
| 只靠面板保存后手动通知 | 容易漏 | |

**User's choice:** 先选「资源层 + 宿主 watch」，随后进一步讨论。
**Notes:** 用户指出新版宿主大概率是纯 Node 端并会加 chokidar；浏览器宿主可能不提供。最终决定：先假定外部一定传入 watch，资源层不在 write 后自己通知，core 只监听宿主这一条通道；去重放在面板 / 组件层。旧开发宿主不在本期适配范围。
