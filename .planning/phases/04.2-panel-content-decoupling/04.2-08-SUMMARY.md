## Decisions Made

- **草稿必须同时进渲染态。** 计划写的「内部状态五样」里只有 `draftRef`，但只写 ref 不会触发重渲染：第一次编辑靠脏标记从 `false` 变 `true` 侥幸重算行树，第二次编辑（已经脏）就停在旧行树。因此新增一个渲染态草稿，`writeDraft` 同时写 ref 与渲染态，ref 仍是句柄 / cleanup 的唯一读取源。
- **面板发布不读组件 ref。** `TablePanel.publish` 改用 `publishedDocument`（草稿副本优先，否则面板基线）。若沿用 `currentDocument`（读 ref），载入 / 外部刷新时会把组件里尚未重置的旧草稿当作新内容发回去，版本号递增就形同虚设。
- **取数顺序按「谁更新」而不是「谁在挂载」。** `TablePanel.currentDocument` 改为「组件脏 → 组件 ref；否则 → 面板草稿副本；否则 → 组件 ref；否则 → 面板基线」。组件干净时它的内容就是面板上一次发布的基线，此时面板侧（兼容薄壳、撤销）刚算出的新值更新，必须优先。
- **写盘前同步快照目标与前缀。** `persist` / `persistSchema` / `writeData` 改为接收 `saveDocument` 入口拍下的 `target` 与 `prefix`；否则「新增字段后换表」会把镜像 schema 写到新表的 schema 路径上。
- **无待写内容时不覆盖基线。** 脏只来自组件尚未同步的标记时（面板 `unsaved` / `unsavedSchema` 都为假），`saveDocument` 直接返回 `Saved`，既不写盘也不改写面板基线。
