# Phase 04.2 Plan 11: 表格面板关闭三态 Summary

**表格面板点 ✕ 时按栏判脏：没脏直接关，有脏在面板自己的视图里弹唯一一份三态确认框，保存失败保持打开，选丢弃则清脏以抵消 `dispose` 的兜底保存。**

## Accomplishments

- `TablePanel.onRequestClose` 用 `TablePanel.isColumnDirty` 逐栏判脏：全不脏直接返回 `PanelCloseChoice.Save`（外壳跳过落盘、不弹框）；有脏才打开面板级弹窗并返回一个等用户选择的 Promise。
- 保存分支逐栏走 `saveColumn`（与 `onSwitchOut` 同一条写盘入口），任一栏失败就把该栏错误文案写进弹窗状态并结算为 `Cancel`，标签保持打开；全部成功才结算 `Save`。
- `TablePanel.onDiscard` 对每个挂载中的组件调 `markSaved()` 并清掉 `unsaved` / `unsavedSchema` / `draftDirty` 与草稿，使随后的 `dispose → saveDirtyColumns` 成为空操作，不写盘、不登记撤销。
- 关闭弹窗状态只存在于面板级 `TablePanel.closeDialogStore`（`Store<ITableCloseDialogState>`），`TablePanelView` 在多栏容器之后只挂一处 `PanelCloseDialog`；`ITablePanelViewState` 上没有新增任何 `closeDialog*` 字段。
- 新增 `closeChoice.test.tsx` 九条用例，断言口径为「标签是否存在 + 磁盘内容 + 写盘次数 + 弹窗数量」，而不是只看枚举值。

## Decisions Made

- 弹窗状态提到面板级 `closeDialogStore`，栏级 `ITablePanelViewState` 保持只有内容 / 提示 / 空栏字段——否则三栏会各弹一个框，取消也只清被点的那一栏（D-38）。
- 脏判定只经 `TablePanel.isColumnDirty`，四来源合并判断，避免「刚编辑过但组件草稿被重置」被误判干净（D-05）。
- 关闭的保存仍在 `onRequestClose` 内完成，没有新增第二个保存钩子；`onSwitchOut` 实现逐字未变（D-11）。
- 丢弃只清内存标记（含 `markSaved()`），不写盘、不登记撤销，与 `dispose` 的兜底保存叠加成「不写盘」（D-10）。
