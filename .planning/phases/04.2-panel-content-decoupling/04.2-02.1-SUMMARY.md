# Phase 04.2 Plan 02.1: 切标签签名可等待化（纯接口） Summary

**`IShellSystem.activateTab` 的返回类型从 `void` 改为 `Promise<void>`，写清「外壳先等旧面板切出保存、再通知 React」的目标时序；实现类只加 `async` 与返回类型，方法体一字不改，零行为改动。**

## Accomplishments

- `IShellSystem.activateTab` 变成可等待的保存点：返回 `Promise<void>`，JSDoc 写明「外壳会**先 `await` 即将离开的面板 `IEditorPanel.onSwitchOut` 结算完成**，再修改活动标签并通知 React 重渲染——因此保存期间旧面板的组件仍然挂载」，并明确「`IEditorPanel.onSwitchOut` 是唯一的切出保存点，不存在第二个保存钩子」。
- `ShellSystem.activateTab` 声明为 `async activateTab(tabId: string): Promise<void>`；方法体（校验标签存在 → 求 `nextInstanceId` → `enqueueDeparture` → 改 `activeTabId` → `notify()` → `syncActiveInstance()`）与 Plan 04 交付时逐字一致，既有那条「先排切出再通知重渲染」的注释原样保留，只额外加了一条说明 B1 目标时序的 `//` 注释。
- 只为 `04.2-04.1` 提供签名前置：它在这条签名之上把方法体改成「先 `await` 切出保存、再改状态并通知」，并给四处调用点补 `await` / `void`——本计划刻意不提前做。

- 不在本计划写任何时序：B1 的「先 `await` 保存」属于 `04.2-04.1`，本计划只把「可等待」这件事写进类型与 JSDoc。过渡窗口（文档已承诺、实现尚未跟上）是接口先行的必然结果，已在计划 objective 中写明并接受。
- 不新增 `onBeforeSwitchOut` 一类第二个保存钩子；`IEditorPanel.onSwitchOut` 的签名、JSDoc 与「唯一落盘点」定位全部不变。
