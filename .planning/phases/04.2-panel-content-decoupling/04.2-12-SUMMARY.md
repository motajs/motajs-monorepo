## Decisions Made

- 候选判定严格同时要求 `canOpen` 与 `createOpenParam` 存在（D-33），缺一不进入候选。
- `selectCandidate` 与 `cancelCandidate` 都先同步清空 `pendingPath` 与 `candidateTypeIds`，再执行打开或直接返回；弹窗挂载条件只看 `candidateTypeIds.length >= 2`，所以不会复活。
- 视图完全复用 Plan 03 的 `IFileExplorerViewProps` / `IPanelCandidateModalProps`，未在 `.tsx` 内新增 props interface。
- 资源管理器总是通过宿主 `openPanel` 新开标签，不 import table / map / asset。

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `@tanstack/store` 的 `setState` 不接受局部对象**
- **Found during:** Task 2（面板类实现）
- **Issue:** 本版本 `Store.setState` 的可用重载只接受完整状态或更新函数，传入 `{ error: ... }` 等局部对象导致 TS2769。
- **Fix:** 所有状态发布改为 `setState((state) => ({ ...state, ...patch }))`，语义不变。
- **Files modified:** `packages/libs/editor-impl/src/explorer/fileExplorerPanel.ts`
- **Verification:** `pnpm --filter @motajs/editor-impl typecheck` exit 0。
- **Committed in:** `7581761`（Task 2 提交）

**2. [Rule 2 - Missing Critical] 面板类型工厂的验证正则命中注释文字**
- **Found during:** Task 2 的 `<verify>`
- **Issue:** 工厂文件注释里出现 `canOpen` / `createOpenParam` 字样，导致计划验证脚本的文本正则误判为「声明了这两个能力」。
- **Fix:** 改写注释措辞，不使用这两个标识符；实现本身从未声明它们。
- **Files modified:** `packages/libs/editor-impl/src/explorer/fileExplorerPanelType.ts`
