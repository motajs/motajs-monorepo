# Phase 1 — UI Design Contract

> Visual and interaction contract for the browser-like editor **shell** (`@motajs/editor-core`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This contract covers the shell **only** — menu row, tab row, content area, blank-tab type list — not the content of any panel. Panels (table/asset/map/code/event) arrive in Phases 2–6.
>
> **Scope note:** legacy editor UI (`packages/apps/editor/src/Workbench/**`) is a *parity reference*, not a template. Verbatim user instruction: 「旧代码仅做参考，不代表新的代码也要这么写」.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (plain React 19 + core-owned CSS) |
| Icon library | none in core — caller supplies a `ReactNode`/component; core never resolves icon names (resolves RESEARCH Assumption A4) |
| Font | inherits host `font-family`; core sets no font-family of its own (host/editor app owns it) |

**Why no shadcn / no UI framework (resolved, not deferred).** `@motajs/editor-core` is the engine-agnostic core: `packages/libs/editor-core/package.json` depends only on `react` + `@tanstack/store`, and architecture constraint forbids pulling the editor's PandaCSS/antd/Semi stack into core. shadcn (Tailwind + Radix, plus a build toolchain) is therefore **declined** for this package. The shell is plain and simple by explicit user decision (CONTEXT.md `the agent's Discretion`). This resolves RESEARCH Assumption A3 in favour of **core-owned plain CSS** (see "Styling Approach" below).

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a tab's icon and its label; gap between adjacent tabs; inline icon gap |
| sm | 8px | Tab inner horizontal padding; gap between blank-tab list rows; menu-item horizontal padding |
| md | 16px | Blank-tab list item padding; menu row horizontal padding; blank-tab list icon-to-name gap |
| lg | 24px | Blank-tab list outer padding; content-area padding; empty-state vertical padding |
| xl | 32px | Menu row height; tab row height baseline |
| 2xl | 48px | Reserved (not used this phase) |
| 3xl | 64px | Reserved (not used this phase) |

**Component sizing (all multiples of 4):**

| Element | Size |
|---------|------|
| Menu row height | 32px |
| Tab row height | 36px |
| Tab inner horizontal padding | 8px |
| Tab close glyph / `+` glyph | 16px |
| Tab close / `+` hit target | 24px square (icon-only interactive exception) |
| Blank-tab list max-width | 480px |
| Blank-tab list row min-height | 40px |
| Panel-type icon | 16px |

Exceptions: icon-only controls (`×` on tabs, `+`) use a **24px hit target** — an intentional compact desktop size, not the 44px touch target (this is a desktop editor; no touch surface is in scope).

## Typography

Exactly **3 sizes / 2 weights**. Font family is inherited from the host (core declares none).

| Role | Size | Weight | Line Height | Used by |
|------|------|--------|-------------|---------|
| Body | 14px | 400 | 1.5 | Blank-tab list item labels; empty-state body |
| Label | 13px | 400 | 1.4 | Menu item titles; tab labels; secondary text |
| Heading | 16px | 600 | 1.2 | Blank-tab list heading; empty-state heading |

Weights: **regular (400)** for all text, **semibold (600)** for headings only. No other weights.

Text behaviour: all shell text is single-line and truncates with `text-overflow: ellipsis` (`white-space: nowrap; overflow: hidden;`) — tab labels, menu-item titles, and blank-tab list names. Full text is exposed via the element's `title` attribute.

## Color

Light values are the contract. They **reuse the editor app's existing CSS variable names** (`packages/apps/editor/src/css/editor.css`) so that when the editor app mounts this shell, theme parity is automatic; core consumes the variables with literal fallbacks.

| Role | Value | Usage |
|------|-------|---------|
| Dominant (60%) | `#f5f6f8` (`--editor-bg`) | Content area background behind panels |
| Secondary (30%) | `#ffffff` (`--editor-toolbar-bg` / `--editor-surface`) | Menu row surface; tab row surface; blank-tab list surface |
| Accent (10%) | `#1677ff` | **Reserved — see list below** |
| Destructive | `#d00` (existing `.warnText` red) | Reserved for explicit destructive confirms only; **no destructive action is registered in Phase 1** |

**Accent reserved for (exhaustive):**
1. The active tab's label text and its 2px bottom indicator bar.
2. The `:focus-visible` ring on tabs, the `+` button, the `×` close control, and menu items.
3. The `+` control's `:hover` text color.
4. Focused/hovered blank-tab list item border.

Accent is **never** applied to default text, default borders, the tab-row background, or "all interactive elements".

Supporting neutrals (from the same token set):

| Token | Value | Usage |
|-------|-------|-------|
| `--editor-fg` | `#202124` | Primary text |
| `--editor-muted` | `#656d76` | Inactive tab/menu labels; secondary text |
| `--editor-border` | `#d0d7de` | Row separators, tab-row bottom border, list-item borders |
| `--editor-selected` | `#dbeafe` | Active-tab background tint |

**Dark variant (host override, parity set):** `--editor-bg #242424`, `--editor-surface #303035`, `--editor-toolbar-bg #2b2b30`, `--editor-fg #d4d4d4`, `--editor-muted #9da5b4`, `--editor-border #4b4b52`, `--editor-selected #163a5f`. Core does not set theme; it reads variables. A host may override `--editor-accent` too, defaulting to `#1677ff`.

## Shell Composition & Interaction Contract

> The shell *is* the deliverable of this phase, so its structure and state machine are part of the design contract.

### Layout (top → bottom)

```
┌────────────────────────────────────────────────────────────┐
│ Row 1  MENU ROW        32px, surface bg, bottom border      │   ← menu items (title + onClick), external
├────────────────────────────────────────────────────────────┤
│ Row 2  TAB ROW         36px, surface bg, bottom border      │
│   [ 标签A × ][ 标签B × ] …                              [ + ] │   ← tabs + × ; + rightmost
├────────────────────────────────────────────────────────────┤
│ CONTENT AREA           fills remaining height, --editor-bg  │
│   active tab is blank  → blank-tab type list (or empty copy) │
│   active tab has inst. → render that instance               │
└────────────────────────────────────────────────────────────┘
```

- The shell fills its container (`width/height: 100%`), column flex; content area is the only region that scrolls.
- Menu row always renders, even with zero menu items (empty row, D-06).
- Tab row always renders, even with zero registered types (holds `+` and the default blank tab, D-06).

### Tab model & interaction (from D-02…D-05)

| Behaviour | Contract |
|-----------|----------|
| On load | Exactly **one blank tab** open by default (auto-created by core on initialize). |
| Multiple blank tabs | Allowed; each is independent. |
| New blank tab | `+` (rightmost) appends a blank tab and makes it active. |
| Open a panel | Clicking a type in a blank tab **replaces that tab in place** with a new instance of the type (the tab is no longer blank). |
| Multiple instances | Same type may be open in several tabs; instances are independent. |
| Close a tab | `×` → `dispose()` the instance → remove the tab → **auto-activate an adjacent tab** (prefer the tab to the left; else the tab to the right). |
| Close last remaining tab | If no tabs remain after closing, **create one fresh blank tab** (never a zero-tab state). |
| Tab activation | Clicking a tab makes it active. No confirmation, no animation. |
| Navigation in undo history | **Not recorded** (resolves RESEARCH Assumption A2: tab navigation is not a document edit). |
| Keyboard | `+`, tab, and `×` are real `<button type="button">` elements, so Tab/Enter/Space work. `×` must not trigger tab activation (stop propagation). No custom shortcut keys in this phase. |

### Blank-tab type list (D-04; plain & simple per discretion)

- Rendered **inside the content area** as a centered block (`max-width: 480px`, `lg` outer padding).
- Heading 「选择面板类型」 (Heading role).
- One row per registered type, in **registration order**. Each row:
  - **Icon** — the caller-provided `ReactNode` rendered at 16px, then a `md` gap, then the **name** (Body role). If the caller supplies no icon, core renders a neutral 16px bordered-square placeholder (see Flagged Decisions).
  - Row is a single `<button>` (full-row click target), `min-height: 40px`, `sm` vertical / `md` horizontal padding.
  - **Hover:** `--editor-selected` background tint; **focus-visible:** accent outline; **active (mousedown):** slightly darker tint.
- Clicking a row opens that type in the current tab (see tab model).
- Zero registered types → the empty-state copy above (heading + body), no rows.
- Many types → the list scrolls vertically within the content area; no pagination, no columns.

### Menu row (D-12)

- One clickable item per externally registered menu item, in registration order.
- Each item is a `<button type="button">` (Label role, `sm` horizontal padding, full row height).
- Hover → subtle neutral background; focus-visible → accent ring. Menu items carry **no icon** (D-12: title + click callback only).
- Overflow: horizontal overflow is clipped with the row not wrapping; items keep their intrinsic width. (No overflow menu this phase.)

### Accessibility & content safety

- Every interactive control is a native `<button>` with an accessible name; icon-only controls (`+`, `×`) carry `aria-label`.
- Panel **type names and menu titles are rendered as text only** — never via `dangerouslySetInnerHTML` (React default escaping; XSS mitigation from RESEARCH Security Domain).
- The caller-provided icon is rendered as a React node; core does not build HTML strings from it.

## UI Considerations

> Resolved UI element/state coverage for the shell (checker-approved, probe cross-checked). plan-phase lifts each `resolved (explicit)` row into `must_haves.truths` as a plain string, and each `resolved (backstop)` row as a flat `{ statement, verification: backstop }` marker. Not-applicable probes are recorded with reasons (no silent drops).

**Applicable considerations:** 19 resolved (18 explicit, 1 backstop), 0 unresolved.

### Resolved — explicit

- Menu row (nav) · empty: with zero registered menu items, the row still renders as an empty fixed-32px surface so the shell shape is stable (D-06).
- Menu row (nav) · populated: one clickable button per registered menu item, in registration order (D-12).
- Menu row (nav) · overflow: horizontal overflow is clipped with no wrap; items keep their intrinsic width.
- Menu row (nav) · long-text: menu titles truncate with single-line ellipsis and expose the full text via the `title` attribute.
- Tab row (nav) · empty: the zero-tab state is unreachable — closing the last tab recreates one blank tab (D-05).
- Tab row (nav) · populated: renders 1..N tabs identically; each tab shows the type name and a `×` close control.
- Tab row (nav) · zero-one-many: 1..N render identically; 0 is unreachable.
- Tab row (nav) · long-text: tab labels truncate with single-line ellipsis and expose the full text via the `title` attribute.
- Content area / panel host · loading: while a newly created panel instance is initializing (its `IEditorPanel.initialize()` is pending), the content area shows a centered, muted loading line; the tab is already present and active.
- Content area / panel host · error: when instance creation throws or the instance's `IEditorPanel.initialize()` rejects, the tab shows the error copy 「面板打开失败」 + 「请关闭此标签页后重试，或联系该面板的提供方。」; the tab stays open and closable.
- Blank-tab type list (list) · empty: zero registered types renders heading 「暂无可用面板」 + body 「尚未注册任何面板类型。」.
- Blank-tab type list (list) · populated: one row per registered type in registration order; each row is a full-row button showing the caller icon + type name.
- Blank-tab type list (list) · partial: types register atomically (id + name + icon + factory); a partial registration is rejected, so the list never renders a half-row.
- Blank-tab type list (list) · overflow: many types scroll vertically within the content area; the list block stays `max-width: 480px`.
- Blank-tab type list (list) · zero-one-many: 0 renders the empty copy; 1 and many render the identical row list with unchanged spacing.
- Blank-tab type list (list) · long-text: type names truncate with single-line ellipsis and expose the full text via the `title` attribute.
- `+` control · populated: an always-rendered icon-only button with `aria-label` 「新建标签页」.
- `×` control · populated: a per-tab icon-only button with `aria-label` 「关闭「{面板名}」」; closes immediately with no confirmation per D-05.

### Resolved — backstop

- Tab row (nav) · overflow: { statement: "When many tabs exceed the tab-row width, the tab strip clips with no wrap and the `+` control stays pinned right and always reachable.", verification: backstop }

### Not applicable (recorded reasons)

- Menu row (nav) · loading / error / partial: menu items are registered synchronously from an in-memory list; atomic registration, no async source.
- Menu row (nav) · zero-one-many: no singular/plural copy in Chinese; layout is identical at any count.
- Tab row (nav) · loading / error / partial: tabs are derived synchronously from the in-memory tab state machine.
- Content area / panel host · empty / partial / zero-one-many / long-text / overflow: these are properties of a panel's own content, owned by Phases 2–6, not the shell.
- Blank-tab type list (list) · loading: the type registry is synchronous in-memory; no loading state applies.
- `+` / `×` controls · empty / loading / error / overflow / long-text: icon-only controls have no text, no async source, and always render.

## Styling Approach (resolved — requires two companion changes)

**Decision: core-owned plain CSS.** A single co-located, kebab-case stylesheet shipped with `editor-core` (e.g. `packages/libs/editor-core/src/shell/shell.css`), imported by the shell root, styled exclusively through the CSS variables in the Color section. This matches the project's existing convention (kebab-case, co-located CSS — see `packages/apps/editor/src/Workbench/**/*.css`), adds **zero runtime dependencies**, and keeps hover/focus/active states in CSS instead of JS.

**Two companion changes are REQUIRED for this to build/package correctly:**

1. **`packages/libs/editor-core/package.json`** currently has `"sideEffects": false`. Change to `"sideEffects": ["./src/**/*.css"]` (CSS is a required side effect; otherwise bundlers may tree-shake the stylesheet and the shell renders unstyled).
2. **CSS module declaration.** `editor-core` has no ambient `*.css` declaration and its base tsconfig only adds the `typescript-plugin-css-modules` editor plugin, which does **not** satisfy `tsc -b` for a plain `import './shell.css'`. Add a one-line ambient declaration (e.g. `declare module '*.css';` in a new `src/global.d.ts`) so `pnpm --filter @motajs/editor-core typecheck` stays green. No dependency added.

**Fallback if the user rejects either companion change:** switch the shell to inline `style` objects for static layout plus a minimal JS hover/active state; this avoids touching `package.json`/ambient types but moves interactive visual states into JS and is harder to theme. Documented so the executor has a defined path.

> Flagged for the planner: these two edits are part of the shell implementation, not optional polish; the `coreModuleState`/`coreImportType`/`coreEngineNeutral`/`coreBoundaries` gates do not forbid them (a `.d.ts` and a `package.json` field are outside their scan surfaces).
