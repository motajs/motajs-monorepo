# Phase 05.2 Plan 02: editor-impl 接口层整改 Summary

**把 editor-impl 资源层的两个类型文件合成一个 `resources/types.ts`、删掉 `interfaces.ts`、给该只读的接口成员补 `readonly`，并把接口头上的 jsDoc 按规范改掉——一行运行逻辑都没动。**

## Accomplishments

- `resources/types.ts` 成为资源层**唯一**类型出口：原 `interfaces.ts` 的 13 个导出（`ReadonlySignal` + 12 个接口）整体并入，与既有的 `Content`/`FileContent`/`PersistenceIntent`/`ExecutorStatus`/`PersistFailure` 合为一个文件。
- 删除 `resources/interfaces.ts`；两包内对它的引用清零（全量 grep 无结果）。
- `types.ts` 只 import 底层包的 `IFsPort`，不 import 任何实现文件——`coreBoundaries.js` 的真实树 `no-circular` 0 违规为证。
- `PersistenceIntent.{kind,execute}`、`PersistFailure.{path,error}` 补 `readonly`；其余契约的数据成员逐个复核，已全部 `readonly`。

- `packages/apps/editor` 零改动。

- **Fix:** Task 1 内把资源层/编辑层全部生产消费方的 import 一并改指 `./types`，再删文件；计划 Task 2 的 `<files>`（combinators 等）因此提前完成，Task 2 转为测试侧 import + readonly 复核 + 全量门禁。
