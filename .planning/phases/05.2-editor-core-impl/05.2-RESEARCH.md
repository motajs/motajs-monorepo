# Phase 05.2: editor-core/impl 代码风格整改 - Research

**Researched:** 2026-09-29
**Domain:** TypeScript library code-style compliance sweep (no behaviour change) over `@motajs/editor-core` + `@motajs/editor-impl`
**Confidence:** HIGH on the inventory and gate impact; MEDIUM on the enum-conversion decisions (they collide with the out-of-scope editor)

## Summary

Phase 05.1 fixed the *structure*. This phase aligns the *code style* of the two packages with `AGENTS.md` §Code style (`[VERIFIED: AGENTS.md:542-576]`). I read every tracked source and test file in both packages (66 `.ts`/`.tsx` files, `[VERIFIED: git ls-files packages/libs/editor-core/lib packages/libs/editor-impl/lib]`) and produced a file-by-file violation inventory (see `## Violation Inventory`). The violations are pervasive but shallow: they are almost entirely (a) file/class/interface-level JSDoc that must be removed, (b) barrels that list names instead of `export *`, (c) string unions instead of numeric enums, (d) types scattered outside `types.ts`, and (e) non-`readonly` interface members.

**The one finding that can change the phase's shape:** the mandated "string union → numeric enum" conversion is *safe* only for `DiagnosticSeverity`. `PreloadStrategy`, `ActionType`, and every discriminant-union tag (`Content.status`, `ExecutorStatus.status`, `PersistenceIntent.kind`) are written as **string literals by `@motajs/editor`** — which this phase declares out of scope and behaviour-frozen. Converting them to numeric enums makes the editor fail `tsc`/typecheck unless the editor is edited. Concretely: `packages/apps/editor/src/adapter/motaEngine.ts:55` writes `preload: 'eager',`, `motaFloor.ts:51` writes `preload: 'on-demand',`, and `Workbench/TowerPanel/index.tsx:128` writes `['change', buildFieldPath([...path]), slot.value]`. This must be resolved with the user **before** the plans are frozen (see Open Questions 1 and 2).

**Primary recommendation:** split into an interface-layer wave first, then an implementation-layer wave, exactly as D-12 requires. Convert `DiagnosticSeverity` to a numeric enum unconditionally; for `PreloadStrategy`/`ActionType`/status tags, either (i) apply the "usage site requires a string" exception and keep them as string unions, or (ii) convert and accept one minimal, mechanical, editor-side follow plan. Do **not** attempt `export *` barrels until the `./table` subpath/gate conflict is decided (Open Question 3): `implExports.js` hard-codes `./table` as an `empty-barrel`, while D-08 mandates `table/index.ts` export everything in its folder.

## User Constraints

### Locked Decisions (from 05.2-CONTEXT.md, verbatim)

> **D-01:** 本阶段的权威规范是 `AGENTS.md` §Code style（2026-09-29 新增）。它只采用 `dev.md` 的**代码风格**部分；`dev.md` 的项目结构/架构类规则**不适用**。
>
> **D-02 注释对象**：**类与接口本身不写 jsDoc**；**类型别名（type）要写** jsDoc。**取代**此前「接口本身写用途注释」的做法（05.1 的 D-09 由此修正）。
>
> **D-03 注释风格**：公共方法用**换行风格** jsDoc、写清**每个参数的用处**、返回值仅在必要时写；成员用**单行** jsDoc（一行写不下才换行）；**私有方法与受保护成员必须写完整注释**；其余注释一律**单行 `//`**（不得用多行注释或 jsDoc）。
>
> **D-04 空行与顺序**：函数之间必须空行；成员之间视情况空行；**成员声明必须写在方法声明之前**。
>
> **D-05 函数**：函数内尽量不定义新函数（需要时改为类）；**裸函数改为类实现**（点名 `createEditorCore`、`createDiagnosticBus` 等）。
>
> **D-06 枚举**：**不用字符串枚举，用数字枚举**；除非使用处要求字符串。点名：`PreloadStrategy`、`DiagnosticSeverity` 等（现为字符串联合/字符串枚举）。
>
> **D-07 类型集中**：所有**导出的类型**（interface/type）都写到该层的 `types.ts`；现散落者如 `DiagnosticBus`/`Diagnostic`/`CapabilityRef`/`RegisterCapabilityOptions`/`RegisterCapabilityResult`/`ResourceDependencies`/`ResourceDescriptor`/`EngineDescription`/`IEngineAdapter`/`IFsPort`/`IHostPort`/`IPreviewAdapter` 等要迁入。
>
> **D-08 桶文件**：一律用 **`export *`**，不逐个列导出名；默认导出该文件夹下所有带 `export` 的内容；**不得**写 `export * from './xxx/yyy'`（不跨目录深路径转发）。
>
> **D-09 空值约定**：空字面量用 `undefined`；空对象用 `null`；空数组用 `[]`。
>
> **D-10 接口 `readonly`**：接口成员**默认 `readonly`**；只有外部确实需要直接修改的才非 readonly（理应非常少）。类实现时内部需要修改的可去掉 `readonly`，对外拿到的仍是 readonly。
>
> **D-11 其他沿用**：LF、单引号、两包禁 `import type`、成员显式类型、方法注释换行/成员不换行。
>
> **D-12:** 第一批计划**只做接口层**整改（D-02/D-06/D-07/D-10 属接口层）；**之后**才排实现层计划（D-03/D-04/D-05/D-08/D-09）。**严禁**接口整改与实现整改放进同一计划。
>
> **D-13:** 重要命名（新增数字枚举成员名、迁移后的类型位置等）先入本阶段 `INTERFACE-NAME.md`，经用户确认才落盘。

## Common Pitfalls

### Pitfall 1: Converting `PreloadStrategy`/`ActionType` and discovering the editor is red
**What goes wrong:** a numeric enum makes `preload: 'eager'` and `['change', …]` TS2322 in `@motajs/editor`, which this phase froze.
**Why:** the enum's consumers are not all inside the two packages.
**How to avoid:** decide Open Questions 1–2 before writing the enum plan; if converting, budget the editor follow-edit explicitly.
**Warning signs:** `pnpm typecheck` failing in `packages/apps/editor` with TS2322 on `preload`/`change`.

### Pitfall 2: `export *` deep-path trap
**What goes wrong:** rewriting `lib/index.ts` to `export * from './kernel/types'` violates D-08; exporting nothing is worse.
**Why:** D-08 forbids `./xxx/yyy` but the types live in a subfolder.
**How to avoid:** add a per-folder `index.ts` first, then the parent does `export * from './kernel'`. Never three segments.
**Warning signs:** a new lint/review note about `export * from './x/y'`.

### Pitfall 3: `./table` gate conflict
**What goes wrong:** making `table/index.ts` non-empty turns `implExports.js` and `subpathStatus.json` red.
**Why:** 05.1 deliberately kept it `empty-barrel`.
**How to avoid:** update both in the same commit as the barrel change (Open Question 3).
**Warning signs:** `implExports: subpathStatus.json 的 "./table" content 应为 "empty-barrel"`.

### Pitfall 4: Dropping the D-18 aliases
**What goes wrong:** `EngineAdapter`, `FsPort`, `HostPort`, `PreviewAdapter`, `LoadableResource`, `PatchableResource`, `ResourceView`, `RecoverableResource`, `OperationHistory` are imported by the editor and by the other package.
**Why:** they cannot be produced by `export *`.
**How to avoid:** keep explicit alias lines (sanctioned exception); run the editor typecheck after each plan.
**Warning signs:** editor errors on `import { EngineAdapter } from '@motajs/editor-core'`.

### Pitfall 5: Type-move cycles
**What goes wrong:** merging `interfaces.ts` into `types.ts` while files still import `./interfaces` (or a new `types.ts` importing a value that imports it) creates a cycle.
**Why:** `no-circular` is an error rule.
**How to avoid:** move all imports to `./types` in one shot, then delete `interfaces.ts`; run `coreBoundaries.js`.
**Warning signs:** cruise `no-circular` violation.

### Pitfall 6: Gate file-count floors
**What goes wrong:** deleting `ports/{fs,host,preview}.ts` lowers the scanned file counts.
**Why:** `coreBoundaries.js` MIN 8 (core production) and `coreEngineNeutral.js` MIN 30 (both packages' production) and `coreImportType.js` MIN 55 (all sources) are non-empty-turn guards.
**How to avoid:** the floors are far below current counts (core production ≈12; both ≈41; all ≈66) and new barrels/types offset deletions — but verify after the move.

### Pitfall 7: `DiagnosticSeverity.Error = 0` truthiness
**What goes wrong:** `0` is falsy; any `if (severity)` / `severity ? …` silently misbehaves.
**Why:** numeric enums default to 0.
**How to avoid:** either assign `Error = 1, Warning = 2, Info = 3`, or grep and prove no truthiness test exists on `severity` (I found none, but the plan must re-verify).
**Warning signs:** a diagnostic being treated as absent.

### Pitfall 8: Retyping comments twice
**What goes wrong:** D-02 (targets) in wave 1 and D-03 (style) in wave 2 both touch the same comment lines, producing churn and review noise.
**Why:** D-12 splits them across waves.
**How to avoid:** in wave 1, only delete interface/class blocks and add type-alias docs; leave member/method style to wave 2. If the user prefers one pass, get explicit approval to deviate from D-12.

### Pitfall 9: `ContentUtils` class conversion breaking call sites
**What goes wrong:** making `ContentUtils` a class with instance methods breaks `ContentUtils.map(...)` used by the editor through shims.
**Why:** the existing form is an object of callable members.
**How to avoid:** use `static` methods so `ClassName.method(...)` is unchanged.

### Pitfall 10: Adding a CI job to run `implExports.js`
**What goes wrong:** `ci-workflow.js` asserts exactly 4 jobs; adding a step is fine but adding a job/`paths`/`secrets` is not.
**Why:** required-status-check contract.
**How to avoid:** keep running `implExports.js` manually; do not restructure `ci.yml` (the phase needs no CI change).

## Open Questions

> Per `AGENTS.md` §Project Rules ("提问前先描述清楚"), each question below is prefaced with the problem in plain language and concrete evidence; the planner should relay these to the user with the evidence, not just the option labels.

1. **`PreloadStrategy` → numeric enum: does the editor get a minimal follow-edit, or does the string stay?**
   - What we know: the user named `PreloadStrategy`; it is declared `PreloadStrategy = 'eager' | 'lazy' | 'on-demand'` (`ports/engine.ts:74`). `@motajs/editor` writes those exact literals against `ResourceDescriptor.preload` in two adapter files (`motaEngine.ts:55…`, `motaFloor.ts:51`). A numeric enum makes both files fail `tsc`.
   - What's unclear: whether this phase may touch `@motajs/editor` (its CONTEXT says the editor is out of scope), or whether `PreloadStrategy` qualifies for the "usage site requires a string" exception.
   - Recommendation: apply the exception and keep `PreloadStrategy` a string union **unless** the user approves a single mechanical editor follow-plan (mirroring 05.1 Plan 08).

2. **`ActionType` → numeric enum: same question, but the editor blast radius is large.**
   - What we know: actions are `['change'|'add'|'delete', path, value]`; the editor constructs them in ~10 component/command files plus property tests, and keeps its own parallel `TableAction` union.
   - Recommendation: keep as a string union (exception) so the editor stays frozen; if the user wants it numeric, budget an editor-side plan.

3. **`./table` barrel: update the gate, or keep it empty?**
   - What we know: D-08 says `table/index.ts` must `export *`; `implExports.js` and `subpathStatus.json` require `empty-barrel`.
   - Recommendation: update the label in both (e.g. `table-exports`) in the same commit as the barrel change; this supersedes 05.1 Plan 05's deliberate restriction, and the dependency-cruiser rule already permits `./table` from the root barrel.

4. **Are D-18 alias lines an allowed exception to "don't list export names"?**
   - What we know: `export *` cannot create `EngineAdapter` from `IEngineAdapter`; the editor imports the old names.
   - Recommendation: yes — treat alias lines as a sanctioned exception (they add bindings, they don't enumerate the surface).

5. **Does the interface-layer comment change (D-02) run in the same plan as the style change (D-03), or across the two waves as D-12 maps?**
   - What we know: D-12 maps D-02 to the interface wave and D-03 to the implementation wave, but both touch the same lines.
   - Recommendation: follow D-12 (limits churn scope per plan) and accept one re-touch of member/method comment lines in wave 2.

6. **`statusFor`/`getter` and `_`-prefixed parameter cleanups**
   - What we know: `FileHandlerManager.get size()` is a getter (`fileHandlerManager.ts:179`); `FileHandler.delete(_force)` uses an `_`-prefixed param (`fileHandler.ts:103`). dev.md discourages getters and forbids `_`-prefixed unused params, but `size` is part of `IFileHandlerManager` and the editor may read it.
   - Recommendation: keep `get size()` (contract) and treat the `_force` case as a small fix in the implementation wave; verify no editor caller depends on either shape.
