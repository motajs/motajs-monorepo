# Phase 05.2 Plan 03: 其余数字枚举 + 编辑器最小跟随 Summary

**把资源预加载策略 `PreloadStrategy` 与表格动作类型 `ActionType` 从字符串联合改成数字枚举，并机械地把编辑器里所有构造这两处的字符串字面量换成枚举成员——功能、UI、宿主协议零变化。**

## Performance

- **Duration:** 约 30 min
- **Tasks:** 3/3
- **Files touched:** 37 个文件次（三个任务分别 4 / 18 / 15）
- **Plan head before:** `7f27da7`
- **commits (measured):** 3

## Accomplishments

- `ActionType`（`editor-impl/lib/table/types.ts`）改为数字枚举 `Change=0`/`Add=1`/`Delete=2`；`Action = [ActionType, string, unknown]` 形状不变；impl 根 barrel 以**值**导出它（`Action` 仍是类型）。
- `PreloadStrategy`（`editor-core/lib/ports/types.ts`）改为数字枚举 `Eager=0`/`Lazy=1`/`OnDemand=2`；`defineEngine` 的 preload 校验改为与枚举成员比较，非法值负例（`'always'`）仍被 `EngineDefinitionError` 拒绝。
- 编辑器机械跟随（D-14）：`utils/action.ts` shim 把 `ActionType` 由类型转发改为值转发；`TableAction` 改用 `ActionType`；由 `pnpm --filter @motajs/editor typecheck` 的 TS2322 驱动，15 个生产文件 + 8 个测试文件的动作元组与 2 个 adapter 的 preload 全部改用枚举成员。
- 判别值由字符串变数字是**有意**的枚举化；`applyAction` 的删除/写入分支、`DataStore` 的改值/新增/删除三条回调、`applyActionsWithInverse` 的逆动作生成结果均不变（属性测试与全量测试为证）。
- 纯 UI 的 `EditMode`（分段控件）、菜单 `key: 'delete'`、`ImageAssetResource` 的 `kind: 'delete'`、`prefabCommands` 第 25/117 行独立的 `kind: 'add'|'change'|'delete'` 联合一律未动。
