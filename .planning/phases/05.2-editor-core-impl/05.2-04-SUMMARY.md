# Phase 05.2 Plan 04: 裸函数改类 + 小清理 Summary

**把两个「有状态工厂」（`createEditorCore`、`createDiagnosticBus`）改成类、把 `ContentUtils` 从方法对象改成静态方法类、把 `defineEngine` 里的内嵌 `visit` 挪到模块级，并落实 D-17 的 getter 改方法与死参数清理——行为完全不变。**

## Performance

- **Duration:** 约 45 min
- **Tasks:** 3/3
- **Files touched:** 18 个文件（含 1 个规划文件 `deferred-items.md` 追加）
- **Plan head before:** `81dcd9f`
- **commits (measured):** 4（3 个任务 + 1 个 Prettier 连带）

## Accomplishments

- `createEditorCore(config)` → `export class EditorCoreKernel implements EditorCore`（`kernel/core.ts`）。装配顺序（诊断总线 → `entries` Map → `teardowns` → `disposed` → `config.install` → 末尾必需注册核对）逐字保留；构造失败仍逆序拆除并抛 `EditorCoreStartupError`；`keyOf`/`drainTeardowns`/`noop` 为私有方法，`registerCapability`/`getCapability`/`getCapabilityOrThrow`/`snapshotCapabilities`/`dispose` 为方法；类内无内嵌函数。
- `createDiagnosticBus()` → `export class DiagnosticBusImpl implements DiagnosticBus`（`kernel/diagnostics.ts`）。历史数组与订阅者集合变实例字段，`dispatch` 私有；「订阅者抛错只追加一条历史、不再派发」的隔离语义逐字保留。
- `ContentUtils` 由 `Object.freeze({…})` 方法对象改为 `export class ContentUtils { static … }`；impl 内部（`combinators.ts`/`dataHandler.ts`/`fileResource.ts`/`engineB.ts`）与经 shim 的编辑器调用点 `ContentUtils.map(...)` 一字未改。
- `defineEngine` 内嵌箭头 `visit` 挪为模块级私有纯函数 `visitDependency`（参数 `id`/`byId`/`settled`/`onStack`/`problems`）；环检测问题顺序与结果不变。
- D-17：`FileHandlerManager.get size()` → `size()`（`IFileHandlerManager` 同步为 `size(): number`）；`FileHandler.delete(_force)` → `delete()`（删掉下划线参数与 `void _force;`），`FileHandlerManager.delete(path, force)` → `delete(path)`。删除容错的 `try/catch` + `isFileNotFoundError` 原样保留。
- 两包根 barrel 与相关测试同步（`createEditorCore`→`EditorCoreKernel`，`createDiagnosticBus`→`DiagnosticBusImpl`；五份 core 测试由 `createEditorCore({…})` 改为 `new EditorCoreKernel({…})`；`implApiSurface` 的 `typeof ContentUtils` 由 `'object'` 改 `'function'`）。
