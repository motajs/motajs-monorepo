# Phase 05.2: editor-core/impl 代码风格整改 - Context

**Gathered:** 2026-09-29
**Status:** Ready for planning

<domain>
## 这个阶段要做什么

把 `@motajs/editor-core` 与 `@motajs/editor-impl` **两个包**（含测试）按项目的**代码风格**规范整改一遍。规范已写入 `AGENTS.md` 的 **§Code style / 代码风格** 节（本阶段的权威依据；只采用 `dev.md` 的代码风格部分，其项目结构/架构类规则不适用）。

**一句话**：上一阶段（05.1）把结构做对了，但代码风格没对齐——这一阶段专门把风格改齐。

**范围**：`packages/libs/editor-core/**` + `packages/libs/editor-impl/**`（含 `__tests__`）。
**不在范围**：`@motajs/editor`（编辑器）不动；不新增功能、不改行为。

**流程**：按「先接口、后实现」——第一批计划只做**接口层**整改（`readonly`、类型迁 `types.ts`、字符串枚举改数字枚举），之后才排实现层计划。

</domain>

<decisions>
## Implementation Decisions

### A. 规范依据
- **D-01:** 本阶段的权威规范是 `AGENTS.md` §Code style（2026-09-29 新增）。它只采用 `dev.md` 的**代码风格**部分；`dev.md` 的项目结构/架构类规则**不适用**。

### B. 要整改的风格问题（逐条，来自用户反馈）
- **D-02 注释对象**：**类与接口本身不写 jsDoc**；**类型别名（type）要写** jsDoc。**取代**此前「接口本身写用途注释」的做法（05.1 的 D-09 由此修正）。
- **D-03 注释风格**：公共方法用**换行风格** jsDoc、写清**每个参数的用处**、返回值仅在必要时写；成员用**单行** jsDoc（一行写不下才换行）；**私有方法与受保护成员必须写完整注释**；其余注释一律**单行 `//`**（不得用多行注释或 jsDoc）。
- **D-04 空行与顺序**：函数之间必须空行；成员之间视情况空行；**成员声明必须写在方法声明之前**。
- **D-05 函数**：函数内尽量不定义新函数（需要时改为类）；**裸函数改为类实现**（点名 `createEditorCore`、`createDiagnosticBus` 等）。
- **D-06 枚举**：**不用字符串枚举，用数字枚举**；除非使用处要求字符串。点名：`PreloadStrategy`、`DiagnosticSeverity` 等（现为字符串联合/字符串枚举）。
- **D-07 类型集中**：所有**导出的类型**（interface/type）都写到该层的 `types.ts`；现散落者如 `DiagnosticBus`/`Diagnostic`/`CapabilityRef`/`RegisterCapabilityOptions`/`RegisterCapabilityResult`/`ResourceDependencies`/`ResourceDescriptor`/`EngineDescription`/`IEngineAdapter`/`IFsPort`/`IHostPort`/`IPreviewAdapter` 等要迁入。
- **D-08 桶文件**：一律用 **`export *`**，不逐个列导出名；默认导出该文件夹下所有带 `export` 的内容；**不得**写 `export * from './xxx/yyy'`（不跨目录深路径转发）。
- **D-09 空值约定**：空字面量用 `undefined`；空对象用 `null`；空数组用 `[]`。
- **D-10 接口 `readonly`**：接口成员**默认 `readonly`**；只有外部确实需要直接修改的才非 readonly（理应非常少）。类实现时内部需要修改的可去掉 `readonly`，对外拿到的仍是 readonly。
- **D-11 其他沿用**：LF、单引号、两包禁 `import type`、成员显式类型、方法注释换行/成员不换行。

### C. 流程
- **D-12:** 第一批计划**只做接口层**整改（D-02/D-06/D-07/D-10 属接口层）；**之后**才排实现层计划（D-03/D-04/D-05/D-08/D-09）。**严禁**接口整改与实现整改放进同一计划。
- **D-13:** 重要命名（新增数字枚举成员名、迁移后的类型位置等）先入本阶段 `INTERFACE-NAME.md`，经用户确认才落盘。

### D. 研究暴露的开放点（用户 2026-09-29 已拍板）
- **D-14:** `PreloadStrategy`、`ActionType` 等**改数字枚举**；因编辑器把它们写成字符串字面量，**允许对 `@motajs/editor` 做最小跟随改动**（把字符串字面量改成枚举成员）。**本阶段范围因此包含这些编辑器文件的机械改动**（仅此一类）。
- **D-15:** `./table` 桶文件改为 **`export *`**；同步修改 `scripts/verify/implExports.js` 与 `subpathStatus.json` 里 `./table` 的 `empty-barrel` 标签（同一次提交）。
- **D-16:** 05.1 的**旧名别名**（`EngineAdapter`/`FsPort`/`LoadableResource`/`OperationHistory` 等，编辑器仍在用）无法用 `export *` 表达，作为 `export *` 规则的**例外**保留显式别名行。
- **D-17:** 注释/空行/成员顺序等属**实现层**，按「先接口后实现」放到**实现波**；`FileHandlerManager` 的 `get size()` 改为方法；`_force` 参数按规则去掉。
- **D-18:** 因编辑器开着 `erasableSyntaxOnly` 且会编译两包源码，`enum` 会被禁止。用户 2026-09-29 确认：**关掉编辑器 `tsconfig.app.json` 的 `erasableSyntaxOnly`（`true → false`）**，两包用**真正的数字 `enum`**；并把 `pnpm --filter @motajs/editor typecheck` 纳入「声明枚举的计划」的验证。（与 D-14 一样，属对编辑器的最小机械改动。）

### 待解决开放点（planner）
- 数字枚举的**成员命名**（如 `PreloadStrategy` 的 eager/lazy/on-demand 对应数字）与 `ActionType` 等是否也数字枚举（它被字符串路径用，需判断「使用处是否要求字符串」）。
- `DiagnosticCode` 现由常量表推导——是否改为数字枚举、还是保留机器码字符串（它是对外契约）。
- `types.ts` 的**分层**（core 的 `lib/kernel/types.ts`/`lib/ports/types.ts`？impl 的各层 `types.ts`）与桶文件的 `export *` 如何与「不跨目录转发」共存。
- `createEditorCore`/`createDiagnosticBus` 类化后的**类名与工厂**（是否需要工厂、命名待确认）。

### the agent's Discretion
- 上述开放点的具体形状与命名，均须先入 `INTERFACE-NAME.md` 并经用户确认。
