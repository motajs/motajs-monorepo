### `packages/apps/editor-dev/src/main.tsx` (entry / composition root, request-response)

**Analog A (mount):** `packages/apps/editor/src/main.tsx` (lines 1-2, 11, 15-23)
```tsx

```
> Note: the editor app renders JSX (`<StrictMode>...`). The dev host may render with `createElement` directly (as RESEARCH's example does) since `shellSystem.render()` returns an `FC` — both are fine; keep `StrictMode` optional.

**Analog B (assembly):** `packages/libs/editor-core/src/core.ts` (lines 19-41)
```ts
constructor() {
  this.undoSystem = new UndoSystem();
  this.resourceSystem = new ResourceSystem();
  this.shellSystem = new ShellSystem(this.undoSystem, this.resourceSystem);
}

async initialize(injection: IEditorCoreInjection): Promise<void> {
  if (this.disposed) { logger.error('core.initializeAfterDispose'); return; }
  if (this.initialized) { logger.warn('core.duplicateInitialize'); return; }
  this.initialized = true;
  const arr = [this.undoSystem.initialize(injection), this.resourceSystem.initialize(injection)];
  await Promise.all(arr);
  await this.shellSystem.initialize(injection);
}
```

**Resulting shape** (RESEARCH Code Example "组合根"):
```tsx
const core = new EditorCore();
const backend = new MemoryBackend();
backend.seed(/* 示例资源 */);

core.shellSystem.registerPanelType(DEMO_PANEL_TYPE); // D-05：顶层直接注册
await core.initialize(backend);         // 注入内存后端 + 外壳注入
const Root = core.shellSystem.render(); // 自订阅根组件
createRoot(document.getElementById('root')!).render(createElement(Root));
```

**Rules / notes:**
- Top-level `await` is available (`"type": "module"`, `target: ESNext`).
- Order: construct → `core.shellSystem.registerPanelType(DEMO_PANEL_TYPE)` (registration may happen before `initialize`) → `initialize(injection)` → `render()`. `registerPanelType` does **not** depend on initialized state (`shell/shellSystem.ts:378`).
- **Do not drive a store from the host.** `ShellRoot` self-subscribes via `useSyncExternalStore` (`shell/shellSystem.ts:291`) and `ShellSystem` notifies through an internal `versionStore` (line 344). `initialize()` auto-opens a blank tab when none exist (`shell/shellSystem.ts:371`) — "open and see a blank tab" is free (acceptance ①).
- Startup try/catch to a message node (mirroring `editor/src/main.tsx:13-31`) is optional but cheap and matches the editor convention.

### `packages/apps/editor-dev/src/backend/memoryBackend.ts` (service, CRUD)

**Analog (exact shape to mirror):** `packages/libs/editor-core/src/__tests__/core.test.ts` → `class FakeEditorInjection` (lines 19-68)

**Seeding + list maintenance pattern** (lines 31-45) — **this is the critical part**:
```ts
// 向内存后端预置一个资源内容及其所属的资源列表
seed(id: IResourceIdentifier, value: unknown): void {
  let byId = this.content.get(id.type);
  if (!byId) {
    byId = new Map();
    this.content.set(id.type, byId);
  }
  byId.set(id.id, value);

  const ids = this.list.get(id.type) ?? [];
  ids.push(id);
  this.list.set(id.type, ids);
}
```

**Five injection methods** (lines 47-67):
```ts
async requestResource<T>(id: IResourceIdentifier): Promise<T> {
  return this.content.get(id.type)?.get(id.id) as T;
}
async requestResourceList(type: number): Promise<readonly IResourceIdentifier[]> {
  return this.list.get(type) ?? [];
}
async writeResource(id: IResourceIdentifier, content: unknown): Promise<void> {
  this.content.get(id.type)?.set(id.id, content);
}
async createResource(id: IResourceIdentifier, content: unknown): Promise<void> {
  this.seed(id, content);
}
async deleteResource(id: IResourceIdentifier): Promise<void> {
  this.content.get(id.type)?.delete(id.id);
}
```

**Why the list matters (Pitfall 2 — the #1 runtime trap):** `ResourceSystem.requestResource` checks the list first and returns `null` if the id is absent (`resource/resourceSystem.ts:51-56`):
```
const list = await this.requestResourceList(id.type);
const found = list.some((item) => item.type === id.type && item.id === id.id);
if (!found) return null;
```
So the backend must **maintain both `content` and `list`** — if it only writes content, every panel reads `null` and the phase fails acceptance ③. `writeResource` updates content only; `createResource` / `deleteResource` are what refresh the list.

**Rules:**
- `class MemoryBackend implements IEditorCoreInjection` — project style requires an interface + `class ... implements ...`; add `readonly maxUndoStep: number = 100` (from `IUndoInjection`, `undo/types.ts:22-25`).
- Do **not** import the test file. Copy the structure only.
- Full interface to satisfy: `IEditorCoreInjection extends IUndoInjection & IResourceInjection & IShellInjection` (`types.ts:5`); `IResourceInjection` methods at `resource/types.ts:68-100`; `IShellInjection` is an **empty** interface (`shell/types.ts:4`).
- Class member order / jsDoc per project Code style (members before methods; every member/method gets a jsDoc).
- No `import type` (project rule); use plain `import { IEditorCoreInjection, IResourceIdentifier } from '@motajs/editor-core'`.

**Full member surface to implement** (lines 71-134):

```ts
class FakePanel implements IEditorPanel {
  readonly id: string;
  private readonly component: FC = () => null;

  async initialize(): Promise<void> { /* ... */ }
  async dispose(): Promise<void> { /* ... */ }

  async onSwitchOut(): Promise<void> { return; }
  async onUpdateResource<T>(id: IResourceIdentifier, data: T): Promise<void> { /* ... */ }
  async onUpdateResourceList(type: number, list: readonly IResourceIdentifier[]): Promise<void> { /* ... */ }
  async undo<T>(context: IUndoContext<T>): Promise<void> { return; }
  async redo<T>(context: IUndoContext<T>): Promise<void> { return; }

```
> Pitfall 4: `IEditorPanel extends IUndoable` requires 12 members (`panel/types.ts:39-92`). Implement every one; make the not-needed ones (`onFocus` / `onBlur` / `onSwitchIn` / `onSwitchOut` / `undo` / `redo`) `async` no-ops.

**Factory + resource read pattern** (RESEARCH Code Example; kernel at `panel/types.ts:94-118` + `shell/shellSystem.ts:576`):
```ts
readonly create: EditorPanelFactory = ({ context, instanceId }) => new DemoPanel(instanceId, context);

// 面板 initialize() 内：
const resource = await this.context.requestResource<string>(DEMO_ID); // IResource | null
const data = await resource?.request();                                // string | undefined
```

**Signature trap:** the panel-context `requestResource` returns `Promise<IResource<T> | null>` (`panel/types.ts:10`) and you then call `IResource.request()` — this is **different** from the injection-layer `requestResource` which returns `T` directly (`resource/types.ts:73`). Don't mix them up.

**Rules:**
- `EditorPanelFactory` is **synchronous** — no `Promise` return. Async setup goes in `IEditorPanel.initialize()`.
- `IEditorPanelType.create` is read-only; `icon` is a `ReactNode` (core does not parse icon names) — `null` is acceptable.
- Project style: `class DemoPanel implements IEditorPanel`; store `id`, `context`, render `FC`; getters/setters discouraged.

## Shared Patterns

### React version pin (avoids two React copies) — **TRAP #1**
**Source:** `packages/libs/editor-core/package.json:19` (`"react": "19.3.0"`)
**Apply to:** `packages/apps/editor-dev/package.json`, optionally `vite.config.ts`
- Pin `react` and `react-dom` to **exact `19.3.0`** (identical to `editor-core`). Catalog `react` is `^19.2.3` (→ `19.2.3`); a mismatch yields two realpaths → "Invalid hook call".
- Optional hardening: `resolve.dedupe: ['react', 'react-dom']` in `vite.config.ts`.
- Verify after install with `pnpm why react` (should show one version).

### Injection contract — **the only thing the host must satisfy**
**Source:** `packages/libs/editor-core/src/types.ts:5`, `resource/types.ts:68-100`, `undo/types.ts:22-25`, `shell/types.ts:4`
**Apply to:** `memoryBackend.ts`, `main.tsx`
- `IEditorCoreInjection = IUndoInjection & IResourceInjection & IShellInjection`.
- Non-empty content: `maxUndoStep` + five resource methods. `IShellInjection` is empty.
- **The backend must maintain the resource LIST, not just content** (Pitfall 2) — otherwise `requestResource` returns `null`.

### Shell self-subscription (no host state)
**Source:** `packages/libs/editor-core/src/shell/shellSystem.ts:291,344,362-363,371,540-542`
**Apply to:** `main.tsx`
- Mount `core.shellSystem.render()` (a cached one-shot `FC`, lines 540-542).
- Do **not** duplicate tab/panel state or write a store — `ShellRoot` uses `useSyncExternalStore`; `initialize()` auto-opens a blank tab.
- `ShellSystem` owns blank-tab/close-switch logic (Phase 1, tested) — don't reimplement.

### tsconfig / alias bases
**Source:** `packages/libs/config/tsconfig.app.base.json:1-31`, `packages/libs/config/resolvePlugin.js:25-34`
**Apply to:** `tsconfig.json`, `vite.config.ts`
- Extend `@motajs/config/tsconfig.app.base.json` (gives `jsx: react-jsx`, `@/*` → `src/*`, `strict`, `moduleResolution: bundler`).
- Use `resolvePlugin` for `@/` in Vite (importer-relative), same as the editor app.

### dev-only boundary — **TRAP #5 (don't build the dev host as a product target)**
**Source:** root `package.json:17` (`build: pnpm -r run build`), `packages/apps/editor/package.json:9`
**Apply to:** `package.json`
- `private: true`, **no `build` script** (only `dev` / `typecheck` / optional `test`).
- `pnpm -r run build` skips packages without a `build` script; no staging/release script references this package.

## Project Rules Checklist (apply to every new source file)

- **No `import type`** — use plain imports (type re-exports use `export type`). `verbatimModuleSyntax: false` in the dev tsconfig makes this valid.
- **Every class has an `interface` and `implements` it** (or implements an existing core interface like `IEditorCoreInjection` / `IEditorPanel`).
- **Barrel files** use `export *`, no comments; no cross-directory deep re-export.
- **jsDoc:** every member and method; multi-line for methods with `@param`; single-line for members; no jsDoc on classes/interfaces/enums themselves; type aliases **do** get jsDoc.
- **Member declarations before methods**; private methods before their callers.
- Single-line `//` only for: file-level comment (after imports), in-function comments, `// TODO:` / `//#region` / `//#endregion`.
- Prefer `enum` (`const enum` + number, PascalCase members) over string keys; `null` for empty objects, `undefined` for empty literals, `[]` for empty arrays.
- Prettier of record: single quotes, semicolons, 2-space, trailing commas, 120 cols.
- No local functions inside functions; pure functions stay bare, stateful factories become classes.
- The root `eslint.config.js` already covers `packages/apps/editor-dev/**` (the `ignores: ['packages/apps/editor/**']` block is editor-app-only) — **no local eslint config needed**; `prettier/prettier: error` is enforced.
