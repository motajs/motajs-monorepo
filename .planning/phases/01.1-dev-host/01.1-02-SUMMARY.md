## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] 演示面板工厂参数隐式 any（TS7031）**
- **Found during:** Task 1（实现 `demoPanel.ts`）
- **Issue:** 计划写的 `Object.freeze({ ..., create: ({ context, instanceId }) => ... })` 中，`Object.freeze` 的返回类型（`Readonly<T>`）不会把 `IEditorPanelType` 的上下文类型传回对象字面量，导致 `context` / `instanceId` 隐式 any，`tsc` 报 TS7031。
- **Fix:** 从 `@motajs/editor-core` 额外导入既有类型 `IEditorPanelFactoryParam`，给工厂参数显式标注该类型（保留计划的 `Object.freeze` 意图）。
- **Files modified:** `packages/apps/editor-dev/src/demo/demoPanel.ts`
- **Verification:** `pnpm --filter @motajs/editor-dev typecheck` 退码 0。
- **Committed in:** `2046737`（Task 1 提交）

**2. [Rule 3 - Blocking] 测试运行时缺 `Map.prototype.getOrInsertComputed`**
- **Found during:** Task 2（首次跑冒烟测试；用例三报 `this.contentCache.getOrInsertComputed is not a function`）
- **Issue:** `editor-core` 的 `ResourceSystem.readContent` 使用 `Map.prototype.getOrInsertComputed`（浏览器原生 Baseline 2026，Node 24 无）；`editor-core` 单测靠 `setupFiles` 加载 `src/__tests__/mapPolyfill.ts` 提供，dev 宿主的 vitest 配置缺该 `setupFiles`，读内容路径崩。
- **Fix:** 新建 `packages/apps/editor-dev/src/__tests__/mapPolyfill.ts`（照 editor-core 的垫片实现），并在 `vitest.config.ts` 加 `setupFiles: ['src/__tests__/mapPolyfill.ts']`。生产入口**不**垫片（浏览器原生）。
- **Files modified:** `packages/apps/editor-dev/src/__tests__/mapPolyfill.ts`（新增）、`packages/apps/editor-dev/vitest.config.ts`
- **Verification:** `pnpm --filter @motajs/editor-dev test` 3/3 通过。
- **Committed in:** `6d7f2d0`（Task 2 提交）
