## 背景（为什么插入本阶段）

用户提出：「现在的编辑器无法打开验证，这可能导致很多潜在问题……就目前来看，编辑器 editor-core 理应可以打开，是否应当提供一个专门用来测试的最小顶层整合方便运行测试？」→ 决定**插入一个新阶段（1.1），排在 Phase 2 之前**，交付一个开发专用的最小可运行整合。用户另补充跨阶段约定：**此后每个 `editor-impl` 能力阶段完成后，都要把对应能力接入这个宿主**（已写入 ROADMAP §Cross-cutting Constraints）。

---

## A. 宿主落点与启动形态

| Option | Description | Selected |
|--------|-------------|----------|
| 新建 dev-only 工作区包 | 在 `packages/apps/` 下新建独立 Vite 应用，装配 editor-core + 注册面板 | ✓ |
| 复用 `@motajs/editor` 加 dev 入口 | 但它目前编译失败、且与产品宿主耦合 | |
| 放进 `editor-impl` 内 | editor-impl 定位是库，不应自带 app | |

**User's choice:** 新建 dev-only 工作区包

---

## B. 数据后端

| Option | Description | Selected |
|--------|-------------|----------|
| 本地 dev fs（读样例工程真实文件） | 参照 `vite-plugin-mota-server.ts` | |
| 内存假数据 | in-memory 资源后端 + 少量示例数据 | ✓ |
| 两者都留 | 默认内存、可切本地 | |

**User's choice（自由文本）:** 「由于这个编辑器改造的目的是为了适应新引擎，旧引擎只是顺带适配，所以不能直接用 mota-js 那个外部项目来读。暂且使用内存假数据进行，后续等新引擎的数据存储部分完工后再接入本地 fs」
