# Phase 1.1: 编辑器开发宿主 - Context

**Gathered:** 2026-10-12
**Status:** Ready for planning

<domain>
## Phase Boundary

交付一个**最小的、开发专用**的顶层整合（dev host），把 `editor-core` 的外壳（以及后续 `editor-impl` 的能力）真正跑起来，供人工 / 目视验收与手动测试。**不随产品发布。**

不含：产品级宿主（`@motajs/editor` 的最终装配，属后续）、插件加载机制、任何具体编辑能力（Phase 2–6）、本地 fs 后端（待新引擎数据存储完工）。

</domain>

<decisions>
## Implementation Decisions

### A. 宿主落点与形态

- **D-01:** 新建一个 **dev-only 工作区包**（放在 `packages/apps/`，拟名 `editor-dev`），独立 **Vite** 应用。装配流程：构造 `EditorCore` → 注册面板类型 → `initialize(injection)`（注入内存后端 + 外壳注入）→ 渲染 `shellSystem.render()`。 — **Reversibility:** reversible — 纯新增 dev 包，删除即可。

### B. 数据后端

- **D-02:** 使用**内存假数据**后端（in-memory 资源后端 + 少量示例数据）。
- **D-03:** **不读 `mota-js` 外部工程**——本改造面向**新引擎**（旧引擎只顺带适配，`packages/external/mota-js` 不作为宿主数据源）。本地 fs 后端**推迟**到**新引擎的数据存储部分完工后**再接入（后续阶段）。

### C. 起步面板 + 接入机制

- **D-04:** 起步注册**一个占位 / 演示面板**（证明外壳可注册 / 开实例 / 关闭）。
- **D-05:** 接入机制——**每个能力 subpath 导出一个「安装函数」**（installer / register），宿主统一调用它们完成注册。解耦、可复用，也贴合未来真实宿主的做法。

### D. 产物边界

- **D-06:** 该包 **`private: true`**、**仅本地 `dev`**、不接入任何产品构建 / 发布链路；依赖放 devDependencies，不随产品发布。

### the agent's Discretion

- 包名、「安装函数」的形状 / 名称、演示面板名、示例数据形状、内存后端如何满足 `ResourceSystem` 的注入形状、Vite 配置细节——由研究 / 规划提出；**命名按项目规则先经 `INTERFACE-NAME.md` 确认**。

</decisions>

## Existing Code Insights

### Reusable Assets
- `EditorCore`（`packages/libs/editor-core/src/core.ts`）：构造即组装 `UndoSystem`/`ResourceSystem`/`ShellSystem`；`initialize(injection)`；`shellSystem.render()` 返回外壳根组件。
- 工作区基建：`@motajs/config` 的 `resolvePlugin`、各 tsconfig 基、Vite。

### Established Patterns
- 工作区包的既有结构（`package.json` + `tsconfig` + Vite 应用）。
- 项目代码风格（禁 `import type`、interface+implements、jsDoc 规则、barrel `export *`）。

### Integration Points
- 宿主调用各能力的「安装函数」完成注册；把面板类型注册进 `ShellSystem`；把内存后端注入 `ResourceSystem`；把 `shellSystem.render()` 挂到 DOM。

</code_context>

<specifics>
## Specific Ideas

- 用户原话要点：「现在的编辑器无法打开验证，这可能导致很多潜在问题……是否应当提供一个专门用来测试的最小顶层整合方便运行测试？」「由于这个编辑器改造的目的是为了适应新引擎，旧引擎只是顺带适配，所以不能直接用 mota-js 那个外部项目来读。暂且使用内存假数据进行，后续等新引擎的数据存储部分完工后再接入本地 fs」「独立 private 包 + 仅本地 dev」「各能力自带安装函数，宿主统一调用」。

</specifics>
