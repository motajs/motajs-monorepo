<objective>
把「内核 + 端口」两处物理搬进底层目录 `lib/core/`，并让机器门禁守住两件事：底层**不依赖上层**、
底层**不读文件**。行为零变化，只改位置、import 路径、门禁常量与门禁规则。

Purpose（说人话）：现在这些代码混在一起，分不清「谁是底层、谁是上层功能」。这一步先把装机器的
「操作系统」（内核、端口）搬进 `lib/core`，再用自动检查把门关死：以后谁想在底层里读文件、或者让
底层反过来依赖表格/地图那些功能，机器立刻报错，不靠人自觉。

Decisions implemented here — D-01 (two layers with a one-way dependency), D-02 (the bottom layer only
*defines* file IO and never calls it), D-10 (module-state exemption path rename), D-14 (LF), D-15
(dev.md conventions where touched).

**Open decisions resolved here (research flagged them; names are provisional pending the user's briefing):**
- **File IO disposition (D-02):** `lib/resources/fileHandler.ts` / `fileHandlerManager.ts` /
  `persistExecutor.ts` / `persistenceMonitor.ts` / `binaryFileHandler.ts` / `fileResource.ts` all **stay
  in `lib/resources/`** (the package default-implementation layer). The bottom layer keeps exactly one
  file-IO artefact: `lib/core/ports/fs.ts` (`IFsPort`) — the interface only. The bottom layer must never
  call it; Task 3 makes that a two-polarity gate.
- **`ResourceRegistry` home (research open decision c):** it **stays in `lib/resources/`** (default
  implementation), not the bottom layer. Rationale: it registers content views (`IResourceView`), and D-03
  forbids the bottom layer from knowing anything about edited content. The bottom layer's registration
  mechanism is `EditorCore.registerCapability` (already there). The only change this plan makes is the
  direction of the shared logical-id predicate: `isValidResourceId` becomes bottom-owned and
  `resourceRegistry.ts` imports it from the bottom layer (default impl → bottom). The user may veto and
  ask for the generic-registry variant instead.
- **`lib/ports/engine.ts` (Phase 5 core content):** moves to `lib/core/ports/engine.ts` unchanged in shape
  (it is a pure contract file); `lib/resources/fileResource.ts` stays; the `engineB` fixture stays as a
  test and only follows import paths.

Spec-less probe: `phase_req_ids` is null for this inserted phase — the probe visibly skips; acceptance is
grounded in `05.1-CONTEXT.md` D-01..D-19.

Output: `lib/core/**` (moved kernel + ports), an updated root barrel, three machine gates updated together,
and a new bottom-layer IO-zero assertion with two-polarity proof.
