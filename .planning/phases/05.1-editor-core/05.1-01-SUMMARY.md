# Phase 05.1 Plan 01: 底层撤销接口定义 Summary

**底层撤销契约以纯类型落地：一个可撤销操作只暴露 `meta` 与 `apply()`（自带逆操作），一个撤销管理器只暴露 `execute`/`undo`/`redo`/`clear`/`store`；全程无快照语义，并保留 D-18 过渡别名 `EditorOperation`。**

## Decisions Made

- **候选 A（操作自带逆）**：`IEditorOperation.apply()` 成功时通过 `AppliedOperation.inverse` 交出逆操作；管理器不实现每个操作的 `undo`/`redo`。与仓库现有 `AppliedOperation.inverse`、组合操作「按已成功子操作的逆序回退」同构。
- **无快照语义（D-05）**：`OperationMeta.paths` 成为历史条目路径的唯一诚实来源，取代旧 `OperationTarget.path`。
- **不接入公开面（本计划刻意）**：不修改 `lib/index.ts`，避免公开面测试变红；由 Plan 03/07 收口。
- **别名写法**：采用同文件 `export type ... = ...` 声明而非 `export type { X as Y } from './types'`，规避 dependency-cruiser 的 `no-circular` 自环。
