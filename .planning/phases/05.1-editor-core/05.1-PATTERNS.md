### `lib/kernel/undoManager.ts` — 撤销操作栈管理器（新，service/管理器）

**Analog A（管理器骨架）：** `lib/edit/operationHistory.ts` — `OperationHistory` 类，含 `Store`、串行队列、容量 100、`changed` 判断、inverse 应用。
**Analog B（操作 + 逆序回滚）：** `lib/edit/operations.ts` — `EditorOperation.apply() → AppliedOperation.inverse` 与 `CompositeOperation` 的失败回滚。

**要抄的骨架（去掉快照后留下的部分）：**
```ts
// lib/edit/operationHistory.ts:100-149（类字段 + per-instance Store + 串行 enqueue）
export class OperationHistory {
  private nextId = 1;
  private pending = 0;
  private queue: Promise<void> = Promise.resolve();
  private readonly capacity = 100;
  /** per-instance 的 Store（D-11）。挂到实例而非模块级，既过 D-10 门禁，也让 hook 能订阅。 */
  readonly store = new Store<OperationHistoryState>({ entries: [], current: 0, busy: false });

  private enqueue<T>(task: () => Promise<T>): Promise<T> {
    this.pending += 1;
    if (this.pending === 1) this.store.setState((state) => ({ ...state, busy: true }));
    const result = this.queue.then(task, task);
    this.queue = result.then(() => undefined, () => undefined);
    return result.finally(() => {
      this.pending -= 1;
      if (this.pending === 0) this.store.setState((state) => ({ ...state, busy: false }));
    });
  }
}
```

**要抄的 execute/undo/redo 语义（删掉 checkpoint 采集/恢复后的净形状）：**
```ts
// lib/edit/operationHistory.ts:175-236 的语义骨架（去 captureSystems/restoreSystems/applyWithCheckpoint）
execute<T>(operation: EditorOperation<T>): Promise<T> {
  return this.enqueue(async () => {
    const applied = await operation.apply();          // 不再先采集快照
    if (!applied.changed) return applied.value;       // no-change 不入历史
    this.store.setState((state) => {
      const entries = state.entries.slice(0, state.current);  // redo 分叉截断
      entries.push({ id: this.nextId++, label: operation.meta.label, timestamp: Date.now(), paths: [...],
                     operation: applied.inverse });
      if (entries.length > this.capacity) entries.shift();
      return { ...state, entries, current: entries.length };
    });
    return applied.value;
  });
}
undo(): Promise<void> {
  return this.enqueue(async () => {
    const state = this.store.state;
    if (state.current <= 0) return;
    const index = state.current - 1;
    const entry = state.entries[index];
    const applied = await entry.operation.apply();    // 存的是 inverse，调它的 apply = 撤销
    this.store.setState((currentState) => {
      const entries = [...currentState.entries];
      entries[index] = { ...entry, operation: applied.inverse };
      return { ...currentState, entries, current: index };
    });
  });
}
// redo 对称：index = state.current，调 entry.operation.apply()，current = index + 1
```

**要抄的失败回滚**（`lib/edit/operations.ts:80-97`）——D-13 明确保留，撤销失败时按已成功子操作的 inverse 逆序回退；不要新加快照事务层（RESEARCH「Don't Hand-Roll」）：
```ts
} catch (error) {
  const rollbackErrors: unknown[] = [];
  for (const result of [...applied].reverse()) {
    if (!result.changed) continue;
    try {
      await result.inverse.apply();
    } catch (rollbackError) {
      rollbackErrors.push(rollbackError);
    }
  }
  if (rollbackErrors.length > 0) {
    throw new AggregateError([error, ...rollbackErrors], `${this.meta.stage} failed and semantic recovery failed`);
  }
  throw error;
}
```

**明确删除、不要抄：** `lib/edit/undoSystem.ts` 整份（`UndoSystem.capture/restore`）、`OperationTarget`/`dataResourceTarget`/`operationPathTarget`、`operationHistory.ts:5-98` 的 `OperationCheckpoint`/`SystemSnapshot`/`captureTargets`/`restoreTargets`/`captureSystems`/`restoreSystems`/`systemsBefore`/`systemsAfter`。

## Shared Patterns

### 编码规范三件套（D-10/D-11/D-08）— 套到 editor-core 全部文件

**来源：** `lib/ports/fs.ts`（首行 import 的正面样例）、`lib/resources/interfaces.ts`（类型集中）、`lib/ports/index.ts`（`export type` 正确用法）。

- **文件第一行必须是 `import`**，禁止文件头块注释；注释只能在所有 import 之后（`dev.md:55`）。
- **禁 `import type`**：用普通 `import`（core 未开 `verbatimModuleSyntax`，类型会被擦除）；**类型再导出仍用 `export type`**（D-11 只禁 `import type`，Pitfall 4）。
- **对外类型集中到 `types.ts`**；实现文件只 import 类型。
- 现存文件头注释（`lib/kernel/core.ts:1-16`、`lib/edit/action.ts:1-5`、`lib/resources/interfaces.ts:1-3`）需按 D-10 上移或删除。

### 类与接口配对（D-07/D-12）

**来源：** `lib/resources/interfaces.ts` + `dataHandler.ts:23` + `fileHandler.ts:22` + `combinators.ts:29`。

- 每个类必须 `implements` 对应接口，不能有裸类（现 `lib/edit/operations.ts:58,111` 的 `CompositeOperation`/`ResourcePatchOperation` 是反例）。
- 会被 `implements` 的接口加 `I` 前缀。
- 有状态/可实例化的用类；只有「与实例无关的纯工具」（路径解析、等待工具）才留裸函数（D-12）。`waitUntil`（`lib/resources/waitUntil.ts`）是允许的裸函数样板。

### 注释（D-09 + `dev.md` §注释规范）

**来源：** `lib/kernel/diagnostics.ts:7-12`（模块说明写在 import 后的 JSDoc）、`lib/ports/fs.ts:21-26`（成员 `ClassName.member` 形式 JSDoc）。

- 接口写「它是干什么的」中文注释；公共成员注释写在**源头（声明处）**；私有/受保护成员也写；所有成员显式类型。
- 注释只在源头出现；继承/`implements` 的成员不重复注释（`dev.md:75`）。
- 类上的方法在注释/文档里写 `ClassName.methodName`（AGENTS.md）。

### 行为关键 `try/catch`（D-13，保留）

**来源：** `lib/edit/operations.ts:80-97`（撤销回滚）、`lib/kernel/core.ts:89-105`（拆除隔离）、`lib/kernel/diagnostics.ts:71-85`（订阅者隔离）、持久化失败隔离（`persistExecutor.ts`/`persistenceMonitor.ts`）。只在**新写/整理**代码时不新增 `try/catch`；既有行为路径的四类必须留。

### 模块无副作用 + 无模块级可变状态（D-10 / 门禁）

**来源：** `lib/kernel/core.ts:107-117`（状态全在闭包/实例）、`lib/resources/resourceRegistry.ts:14,60-61`（实例字段 `Map`）。

- 所有模块只有声明，无顶层执行、无导出的可变绑定；容器用 `Object.freeze(...)` / `as const` 或放进实例闭包。
- 组合根是 D-10 唯一豁免的生产文件（`lib/kernel/core.ts:15`）。
- 门禁：`coreModuleState.js` + `eslint.config.js` Block B（见上）。

### Barrel 唯一公开面（D-06 / no-circular）

**来源：** `lib/index.ts:1-12,13-17`、`lib/ports/index.ts:1-11`。

- 一律具名再导出（不用 `export *`）；值与类型分开；不得 export 不属于当前包/文件夹的内容（`dev.md:52`）。
- barrel 是叶子，不能被内部文件 import（`no-circular`）。

### 门禁两极性（Phase 2 教训 / RESEARCH 门禁清单）
