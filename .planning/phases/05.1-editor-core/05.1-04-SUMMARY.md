# Phase 05.1 Plan 04: 撤销重构实现 Summary

**把撤销从「存前后快照」换成「存操作」：core 新增无快照的 `UndoManager`（串行队列 + 容量 100 + 逆操作栈），editor-impl 删除 `UndoSystem`/`OperationTarget` 等全部快照残骸，并以旧名别名保持 `OperationHistory`/`EditorOperation`/`PatchableResource` 可用。**

## Accomplishments

- **core 落到无快照的撤销管理器**：`UndoManager implements IUndoManager` 只调操作自己的 `apply()`，把返回的逆操作记进历史；撤销/重做只调历史里那个操作的 `apply()`。Store/队列/容量全在实例字段上，模块级零可变绑定。
- **快照残骸清零**：删除 `undoSystem.ts`、`operationHistory.ts` 及其不变量测试；`operations.ts` 去 `targets`、去 `OperationTarget`/`dataResourceTarget`/`operationPathTarget`，两类改 `implements IEditorOperation`，**逐字保留**组合失败逆序回滚与 `commandStage`（D-13）。
- **公开面以旧名别名保持兼容**：`UndoManager`（值）+ `OperationHistory`（值别名）+ `EditorOperation`（类型别名，来自 `types.ts`）；`IPatchableResource` + `PatchableResource` 别名；`useOperationHistory` 参数改 `IUndoManager`，`paths` 改由 `OperationMeta.paths` 提供。
- **不变量测试重写**：容量 100（第 101 次 undo 为空操作）、逆操作 undo/redo、redo 分叉截断、无改动不入历史、组合失败按逆序回退并标 `commandStage`；target/snapshot 用例 0 条。

## Decisions Made

- **内部条目收窄而在管理器内**：对外 `store` 仍是 `Store<OperationHistoryState>`（`entries: readonly OperationHistoryEntry[]`）；操作本体由私有的 `ManagedEntry`（`extends OperationHistoryEntry` + `operation`）承载，仅在 `undo`/`redo`/`execute` 写读处收窄，公开面不泄漏操作对象。
- **组合失败回退的测试落点**：因 core 不得 import impl，核心不变量测试用一个与 `operations.ts` 的 `CompositeOperation` 同契约的**本地组合替身**，证明「按逆序 inverse 回退 + `commandStage`」契约；生产 `CompositeOperation` 的实现被逐字保留（D-13），由 impl typecheck 与公开面测试保证可编译可达。
- **Rule 3 阻塞修复的范围**：Task 1 删文件后，Task 2 才负责的 `editor-impl` 根 barrel / hook / 公开面测试会悬空报错，故 Task 1 内做最小编译跟随，Task 2 只补 core 值导出与别名；两任务提交边界因此与计划所列文件略有交叉（见 Deviations）。
