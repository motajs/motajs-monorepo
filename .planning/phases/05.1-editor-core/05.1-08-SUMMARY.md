## Decisions Made

- **`OperationHistory` 留在 core**：`editor-impl` 不再导出该值别名（它是 core 的 `UndoManager` 别名），故 `appInstances.ts` 必须按符号把 import 拆成两条（impl 取 `FileHandlerManager`/`PersistenceMonitor`，core 取 `OperationHistory`/`FsPort`）。
- **`operations.ts` shim 双向归属**：值面（`compositeOperation`/`patchResourceOperation`）→ impl，类型面（`AppliedOperation`/`EditorOperation`/`OperationMeta`）→ core；这样在删除两条已消失再导出的同时仍保持 forward-only 结构。
- **tracer 反馈门**：Task 1 的 `<automated>`（静态残留扫描）通过，`human_verify_mode=end-of-phase` 且自动验证通过——记录 `⚡ Tracer verified end-to-end — expanding`，不设检查点，继续执行。

**1. [Rule 3 - Blocking] 编辑器 tsconfig 关闭 `verbatimModuleSyntax`**
- **Found during:** Task 2（`pnpm --filter @motajs/editor typecheck`）
- **Issue:** D-11 要求两个源码直出库（`editor-core`/`editor-impl`）禁用 `import type`（普通 import，类型再导出用 `export type`）。编辑器把两库源码并入自己的 `tsc -b` 程序，而编辑器开 `verbatimModuleSyntax: true`，于是库源码报 TS1484（如 `undoManager.ts`/`edit/operations.ts`/`react/index.ts`/`resources/interfaces.ts`）。这是计划未预见的；计划 Task 2 只列了 TS2305/TS2339/TS6133。若改成在库里写 `import type` 则违反 D-11、并与 05.1-07 的新门禁（两包 `import type` 必须为 0）直接冲突。
- **Fix:** 在 `packages/apps/editor/tsconfig.app.json` 把 `verbatimModuleSyntax` 由 `true` 改为 `false`，并加注释说明缘由。编辑器自身代码仍一律用 `import type`（该开关只影响「强制」，不影响既有写法）。
- **Files modified:** `packages/apps/editor/tsconfig.app.json`
- **Verification:** `pnpm --filter @motajs/editor typecheck` 与全仓 `pnpm typecheck` 均 exit 0；反向验证：把该开关临时改回 `true` 会重新出现 11 条 TS1484，关闭后消失。
- **Committed in:** `72d0e0a`（Task 2 提交）
