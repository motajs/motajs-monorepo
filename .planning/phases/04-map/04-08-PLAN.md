<objective>
把四个「会丢改动」的入口接上未保存确认：切地图、新建地图、新增图层、关闭标签；并把新建地图 / 新增图层的弹窗与最近使用图块的持久化做出来。

Purpose: 地图改的是内存，宿主的新建 / 加层会返回整份新文档，把内存直接盖掉。今天不把这四个入口拦住，用户画十分钟后点一下「新增图层」就全没了。最近使用则是纯体验：不落盘就每次重开都空。

Output: 三个受控弹窗（新建地图 / 新增图层 / 未保存确认）、面板侧的 `createMap` / `addLayer` / `requestUnsavedDecision` / `requestDiscard` / `onBeforeClose`，以及最近使用的读 / 写 / 清空。

> **探测口径（flagged assumption）：** UI-SPEC 的状态探测里，「未保存确认」有一条 `unclassified` 行（中文需求文本无法被确定性探测归类）。本计划按「模态交互控件」处理：固定三个动作、没有空态 / 列表态、没有部分数据态与溢出态；加载与失败由保存中 / 保存失败两条覆盖。这不影响任何用户可见行为，但记为一条**明确的假设**而不是「探测通过」。
</objective>

| 最近使用文件（可被手工改坏）→ 面板 | 任意 JSON |
| 关闭标签 → 未保存确认 | 对话框是最后一个能阻止数据丢失的位置 |
