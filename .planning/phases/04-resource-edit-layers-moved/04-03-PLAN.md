<objective>
Move the generic edit layer into `packages/libs/editor-core/lib/edit/`, replace the hard-coded viewport
coupling with the per-instance `UndoSystem` registry, and keep every editor behaviour identical through
shims and one retained zero-arg React hook.

Purpose: this is the phase's deepest seam. Today `operationHistory` reaches straight into the editor's
viewport provider and stores `beforeViewport`/`afterViewport` on each entry. Core may not know viewport
or material semantics (D-03), so it must instead capture a snapshot from every registered `UndoSystem`
and restore them in reverse order — while still reproducing the existing characterization tests exactly.

Output: five core `lib/edit/` modules, one editor-relocated viewport-operations module, the editor's
single `operationHistory` instance with the viewport system registered, a `./react` hook, and the split
invariants test.

Decisions implemented here — D-02: `history/viewport.ts` and `history/materialOperations.ts` stay in
the editor, and `RestoreViewportOperation`/`NavigateFloorOperation`/`navigateFloorOperation` are
relocated to `src/project/history/viewportOperations.ts` rather than moved to core. D-03: core's edit
layer provides the per-instance `UndoSystem` registry; every registered system is captured on every
`OperationHistory.execute` and restored in reverse registration order, so core never learns viewport or material
semantics. D-04: `Action`, `applyActionsWithInverse` and the `PatchableResource<T>`-based
`patchResourceOperation` move into `lib/edit`, while `commandOperations.ts` stays in the editor. D-06:
`OperationHistory` is de-singletonised. D-07: the editor's single `operationHistory` instance and its
viewport-system registration live in `src/appInstances.ts`. D-09: `lib/edit/*` is an internal directory
exported from the root `.` entry. D-10: the four new shims carry the `// SHIM(phase4)` marker. D-11:
the store moves onto the `OperationHistory` instance and `useOperationHistory` lands on the `./react`
entry with a zero-arg editor wrapper. D-13: the nine pure invariants move to core while the
submodule-coupled reactivity describe stays in the editor.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI command → `OperationHistory.execute` → targets/systems | Untrusted-ish control flow: every edit intent enters here. Ordering bugs (capture timing, restore order) corrupt editor state rather than throwing. |
| core edit layer → editor `UndoSystem` implementations | Core calls back into editor-owned code by id only; a system whose `capture()` is asynchronous breaks the invocation-time snapshot guarantee silently. |
| undo history → two editor instances | The registry and the store are per-instance; shared state would leak one editor's undo stack into another. |
