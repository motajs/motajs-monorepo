#   `clientWidth` 算出 count 并只为 0..count-1 建栏，面板本身不知道 count。本计划让视图经一个回调把 count
#   回报给面板（`onLayout`），面板保存 `visibleColumnCount`（至少 1），`openSchemaPanel` 据此在 0..count-1 中找
#   `target === null` 的栏。备选（不采用）：面板直接读 `window.innerWidth` 自算——会把视图几何耦合进模型且更难测。
# - P5 明说用 `window.innerWidth`。注意表格栏容器通常略窄于窗口（外壳菜单/标签栏不占宽，但滚动条等），
#   若每栏硬写 `window.innerWidth / N` 会撑破容器、反而出现横向滚动（与 P6 冲突）。本计划按「栏数由
#   `window.innerWidth` 决定、可视栏**在容器内等分**」落地：N = max(1, floor(innerWidth / 栏宽))，可视栏各占
#   容器的 1/N（容器铺满窗口时即等于 innerWidth/N）。这样既满足「栏数公式 / 末栏不偏宽」，又满足「不出现横向滚动条」。
# - P9 的分隔线：当前是 `.etable-column { border-left }`，高度随该栏内容（含其 `overflow:auto`）变化，导致两侧不等高时
#   分隔线覆盖不全。本计划改为覆盖整列高度（`align-self: stretch` + `min-height: 100%`，或改为容器上的独立竖线）。

<objective>
修复 UAT 的分栏机制与「编辑 Schema」入口（G-02-LAYOUT / G-02-BEHAVIOR 的 P5 / P6 / P9 / P2 / P1）：栏数改为按 `window.innerWidth` 计算、各栏等宽、窄窗不出现横向滚动条；栏分隔线覆盖整列高度；默认栏宽 400 → 500；「编辑 Schema」优先把 schema 表放进当前面板的一个空栏，没有空栏才新开面板。

Purpose: UAT 里分栏宽度不合理（末栏偏宽）、窗口变窄时冒出横向滚动条、栏分隔线跟着较短的一侧截断；默认栏宽偏窄；且「编辑 Schema」总是新开面板，忽略了当前面板本就空着的栏。修复后分栏与旧编辑器观感一致，并让 schema 就近显示。

Output:
1. `tablePanel.ts`——按 `window.innerWidth` 计算栏数与等宽；视图回报可视栏数；`TablePanel.openSchemaPanel` 复用空栏。
2. `table.css`——等宽分栏、无横向滚动、整列高的栏分隔线。
3. `layout.uat.test.tsx`——改用 `window.innerWidth` 驱动并覆盖上述行为。

**新增 / 改动命名提案（逐条待用户按「重要命名先确认」门禁确认后才可落实现）：**
- `resolveColumnCount(windowWidth: number, columnWidth: number): number`（函数，`tablePanel.ts`，**非导出**）：按 `max(1, floor(windowWidth / columnWidth))` 计算可视栏数。备选名 `computeColumnCount` / `calcColumnCount`。
- `ITablePanelViewProps.onLayout: (columnCount: number) => void`（**非导出** interface 成员，`tablePanel.ts`）：视图把它当前铺出的可视栏数回报给面板。备选名 `onColumnCountChange`。
- `TablePanel.findEmptyColumnIndex(): number`（**非导出**方法，`tablePanel.ts`）：在 `0..visibleColumnCount-1` 中返回第一个未设目标栏的序号；无空栏时返回 -1（供 `openSchemaPanel` 复用空栏）。
