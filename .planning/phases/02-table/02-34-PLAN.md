<objective>
把折叠（分组）行的默认状态从「展开」改为「折叠」，并让一个分组行在**首次进入视野**时自动展开——打开时先做一次初始可见性判定，之后滚动到的分组才逐个展开。

Purpose: P29 的性能问题主要在 schema 表（折叠项多、一次性渲染元素多）。根因是首屏把整棵树（含全部折叠子行）一次性挂载。**默认折叠 + 可见才展开**后，首屏只挂载顶层可见行，折叠子行不进 DOM，大幅降低首屏挂载量；滚动到的内容仍照常显示（用户感知不变）。方向由用户明确指定（02-UAT P29），并保持既有「折叠可点、折叠状态不进入撤销」的语义（D-24 / D-16 / D-27）。

Output:
1. `components/GapRow.tsx`——默认折叠、首次可见自动展开（自持 `IntersectionObserver`，默认视口 root，依赖祖先滚动容器裁剪）、无观察器时退化展开、点击仍可切换且用户点击后不再被自动展开。
2. `__tests__/lazyReveal.uat.test.tsx`（新）——受控 `IntersectionObserver` 桩下的四条回归。

**浏览器全局门禁（重点）：** `IntersectionObserver` **不是**被禁全局——门禁（`coreModuleState.js`）只禁 `fetch` / `document` / `navigator` / `localStorage` / `XMLHttpRequest`，且 D-38 起 `window` 亦解禁；`ResizeObserver` 已按此在产品代码里直接使用（`tablePanel.ts`）。因此本计划沿用**同一既有模式**直接使用 `IntersectionObserver` + `typeof … === 'undefined'` 守卫 + effect 清理 `disconnect()`，**无需注入观察器、无需绕行**。满足门禁的关键只有两条：不触碰那 5 个被禁全局；不新增模块级状态（观察器只建在组件 effect 闭包内）。

**接口变更：无。** 不改 `IGapRowProps` / `GapRow` 签名、不新增对外导出，故**无需单独的接口计划**。惰性**子元素创建**（把 `children: ReactNode` 改为工厂）会改 `IGapRowProps` 形状，属接口变更，本轮**明确不做**（挂载量已由默认折叠解决；见 prohibitions）。

**新增命名（见文末）：** 新测试文件 `lazyReveal.uat.test.tsx`、测试内受控桩类 `ControlledIntersectionObserver`。产品代码**无新增非导出 / 导出符号**。
