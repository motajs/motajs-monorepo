# Phase 2 Plan 23: Dev-host demo data (~100) and undo/redo buttons Summary

**Dev host now seeds a ~100-field demo table for exercising vertical scrolling, and shows top-level 「撤销」/「重做」 buttons wired to the editor's undo/redo system**

## Accomplishments
- Demo table data grew from 4 fields to 100, generated by a count constant + generator functions, so the dev host renders a realistically tall table whose body scrolls vertically.
- Added two flat top-level menu buttons 「撤销」/「重做」 in the dev host that call `core.undoSystem.undo()` / `redo()` — no editor-core/editor-impl interface or implementation change, no new shell sub-menu mechanism.
- Extended the dev-host test to 9 cases covering row count, the scroll container, menu registration, click-to-undo/redo, and an end-to-end undo of an edited value.

## Decisions Made
- Kept `title` / `level` / `position` in the generated demo data + schema so the existing demo assertions (descriptions, nested `position-x`/`position-y`) remain meaningful, while appending ~97 numeric `fieldNN` fields to reach ~100 rows.
- Represented undo/redo as two flat top-level menu items (the shell only renders a flat menu row) rather than adding a shell sub-menu; buttons call the existing `IUndoSystem`.
- Because jsdom does not apply the external CSS, the scroll test asserts the `.etable-body` scroll container exists (the element the CSS declares `overflow: auto`), matching how editor-impl's own `layout.uat.test.tsx` handles jsdom's empty computed styles.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added a `ResizeObserver` stub + zeroed `window.innerWidth` to the dev-host test polyfill**
- **Found during:** Task 1 (before writing code — running the existing suite for a baseline)
- **Issue:** `pnpm --filter @motajs/editor-dev test` failed 3 tests with `ReferenceError: ResizeObserver is not defined`; antd controls used by the table panel need `ResizeObserver`, which jsdom lacks. editor-impl's test setup already stubs it, but the dev host's `mapPolyfill.ts` did not. Without this, no dev-host test that renders the table could pass, so the plan's exit-0 acceptance was unreachable.
- **Fix:** Mirrored editor-impl's stub into `packages/apps/editor-dev/src/__tests__/mapPolyfill.ts` (a no-op `ResizeObserverStub` plus `window.innerWidth = 0` so the table renders single-column in tests).
- **Files modified:** `packages/apps/editor-dev/src/__tests__/mapPolyfill.ts`
- **Verification:** `pnpm --filter @motajs/editor-dev test` now green; `typecheck` exit 0.
- **Committed in:** `15cdf85` (Task 1 commit)

**2. [Rule 1 - Bug] Fixed a pre-existing broken assertion in the dev-host test**
- **Found during:** Task 1
- **Issue:** The existing first case asserted `screen.getByText("['position']")`, but the group row renders its short field name (`position`), not the full bracketed path — so the assertion could never match (it was masked earlier by the `ResizeObserver` crash). Editor-impl's tests likewise assert `getByText('nested')`.
- **Fix:** Changed the assertion to `screen.getByText('position')`, preserving the intent (the `position` group row is present).
- **Files modified:** `packages/apps/editor-dev/src/__tests__/devHostTable.test.tsx`
- **Verification:** Case passes; all 9 dev-host table cases green.
- **Committed in:** `15cdf85` (Task 1 commit)
