# Flagged assumptions for this plan
# - P14 现状：`.etable-body`（table.css:123-127）已是 `flex:1 1 auto; min-height:0; overflow:auto`，理论上就是滚动容器；
#   但 `.etable`（:1-12 `height:100%`）与 `.etable-column`（:21-27 `min-height:100%`、无 height / overflow）在宿主
#   高度不确定时会让内容撑高整链，于是外层 `.editor-shell-content`（shell.css:155-164 `overflow:auto`）接管了滚动，
#   表现为「整个面板一起滚」。修复思路：给每栏一个**受限的确定高度**（`.etable-column { height:100%; min-height:0; overflow:hidden }`）
#   并让 `.etable` 填满该栏（`.etable { position:absolute; inset:0 }`，`.etable-column` 已是 `position:relative`），
#   使 `.etable-body` 必然成为唯一滚动容器，工具栏 / 提示行留在其外。
# - P17 现状：`.etable-toolbar`（:187-194）为 `display:flex; gap:8px`，左对齐；有表打开时 `.etable-toolbar-title`
#   `flex:1 1 auto` 撑开把按钮推到右端；无表打开时没有 title，按钮就贴左。修复：无标题时渲染一个 `flex:1` 的
#   占位元素（或等价 CSS），把控件推到右端；不新增对外命名。
# - P25 现状：`.etable-header, .etable-row` 的 `grid-template-columns: 24px 2fr 2fr 4fr 1fr`（:39-44），末列
#   （操作）为 `1fr`；改为 `1.5fr`。已有用例断言表头四列类名（layout.uat.test.tsx:296-315），列数以类名判定，不受宽度影响。
# - 依赖 02-24：本计划与 02-24 都改 `TableToolbar.tsx`（02-24 加类型成员），故 wave 17 晚于 02-24。

<objective>
修复每栏的滚动与几处布局观感（G-02-UAT2 的 P14 / P17 / P25）：让各栏**各自独立滚动**且只有内容区滚动、顶部工具栏与提示行固定；未打开表的栏把顶部控件**右对齐**；「操作」列宽改为当前的 **1.5 倍**。

Purpose: 现在整块面板一起滚，工具栏与提示行会被滚走，多栏对照时很不方便；空栏的顶部按钮贴在左侧、与有表栏的右对齐不一致；「操作」列偏窄。修复后多栏各自滚动、控件位置一致、操作列不再拥挤。

Output:
1. `table.css`——每栏受限高度 + 内容区独立滚动；操作列 1.5×。
2. `TableToolbar.tsx`——无标题时的右端占位。
3. `layout.uat.test.tsx`——上述行为的用例。

**本计划不新增对外命名。** 工具栏占位若引入新 CSS 类名，按「非对外命名」在计划里登记备查（不作为需要用户确认的重要命名）。

</objective>
