Purpose: UAT 发现表格接入后的观感 / 交互问题（需要多栏布局、按实例的标签标题、新增行有确定顺序）。按项目规则「先接口、后实现」，本计划先把接口定下；实现块与开发宿主打开器注入块随后各自成计划。三块中本计划为第 1 块。

Output:
1. `packages/libs/editor-impl/src/table/types.ts`——三处类型改动：
   - `ITablePanel.setTable(target: ITablePanelTarget, columnIndex?: number): void`（原为单参 `setTable(target)`）。
   - `ITablePanelParam` 增加 `columnWidth?: number`（缺省约 400px）。
   - `ITableSchemaNode` 增加扩展键 `x-order`（同级字段的顺序提示，例如 `readonly string[]`）。
2. `packages/libs/editor-core/src/panel/types.ts`——一处**最小** core 接缝：`IEditorPanel` 增加可选方法 `getTitle(): string | undefined`。

**为什么「按实例标签标题」需要 core 接缝（评估结论）：** 标签名目前由 editor-core 的 `resolveTabName(tab, panelTypes)`（`shellSystem.ts:116-122`）解析，它只有 `IEditorTab`（`id` / `typeId` / `instanceId`）与静态的 `IEditorPanelType[]`，取的是**类型级**的 `IEditorPanelType.name`——同类型的多个实例共享同一个名字，且没有任何「按实例」的数据通道。editor-impl 无法影响 core 的标签渲染。因此「标签显示 `表格 table.demo` 这类按实例标题」**必须**在 core 上开一个接缝。选择**可选方法** `IEditorPanel.getTitle?()`：它是「面板实例的显示身份」，归属 `IEditorPanel` 最自然；可选即对现有实现零破坏（`TablePanel`、开发宿主的演示面板、测试替身都无需改动），满足本计划「只改类型、typecheck 仍绿」的硬约束。外壳在构建标签时读取 `getTitle?.()`、缺席回退 `IEditorPanelType.name`；该读取与刷新属后续实现块。

**新增命名提案（逐条待用户按「重要命名先确认」门禁确认后才可落实现）：**
- `x-order`（JSON Schema 扩展键，`ITableSchemaNode['x-order']`）：给同级字段一个显式顺序；新增行据此插在双击行之后。备选名 `x-property-order` / `x-field-order`。
- `columnWidth`（`ITablePanelParam` 成员）：每栏像素宽，缺省约 400。
- `columnIndex`（`ITablePanel.setTable` 第二参）：目标栏序号，0 基，省略为 0。
- `getTitle`（`IEditorPanel` 方法）：按实例的显示标题；备选名 `getDisplayName` / `title`。
