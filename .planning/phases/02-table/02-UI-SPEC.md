# Phase 2 — UI Design Contract

> Visual and interaction contract for the **schema-driven table panel** (`@motajs/editor-impl/table`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** This contract covers the table **panel content** only — grid / header / row presentation, the panel toolbar, inline-edit affordances, each input control, fold / expand, add / delete affordances, the 「编辑 Schema」button, the schema presentation mode (D-10), and the empty / loading / error states. The shell (menu row / tab row / content area) is Phase 1 and is **not** re-specified here; this panel renders *inside* the shell's content area and reuses the shell's `--editor-*` variables.
>
> **Parity note (user instruction).** The legacy editor table (`packages/apps/editor/src/components/Table/**`, `packages/apps/editor/src/components/SchemaTable/**`) is a **behaviour / visual parity reference**, not a copy template. Verbatim user instruction: 「旧代码仅做参考，不代表新的代码也要这么写」. Where this contract says *parity*, it means the user-observable behaviour and look of that table, re-expressed in the new tokens and component structure.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn — this is an antd-based library package, `@motajs/editor-impl`) |
| Preset | not applicable |
| Component library | **antd 6.2.1** — already a `peerDependency` of `@motajs/editor-impl` (catalog-pinned `antd: 6.2.1`) |
| Icon library | none required — the table body uses **text-labelled controls** for parity (编辑 / 折叠 / 展开 / 注释 / 复制). The panel-type `icon: ReactNode` for the Phase-1 shell is a self-contained inline SVG (see Flagged Decision F1) |
| Font | inherited from the host `font-family`; the panel declares no font-family of its own |

**Why no shadcn (resolved, not deferred).** `@motajs/editor-impl` is a workspace library whose peer stack is fixed by the milestone constraint (`antd` + `@motajs/editor-core`). CONTEXT D-08 locks styling to **antd components + local CSS**, no PandaCSS, no new runtime dependency. shadcn (Tailwind + Radix + build toolchain) is therefore **declined**. The design system is antd; the styling layer is co-located plain CSS.

## Typography

Exactly **4 sizes / 2 weights**. Font family is inherited from the host (the panel declares none).

| Role | Size | Weight | Line Height | Used by |
|------|------|--------|-------------|---------|
| Display | 16px | 600 | 1.2 | Panel empty-state / error-state heading; schema-mode banner |
| Heading | 14px | 600 | 1.3 | Column headers (条目 / 注释 / 值 / 操作); toolbar title |
| Body | 13px | 400 | 1.4 | Cell text; field names; input values; row-action button labels |
| Label | 12px | 400 | 1.4 | Comment text; field-path labels; inline validation / helper text |

Weights: **regular (400)** for all body/label text, **semibold (600)** for headings only. No other weights.

Multi-line content (JSON values, comments) renders in the value/comment cell with wrapping or a scrollable textarea — see the Interaction Contract.

## Table Panel Composition & Interaction Contract

> The panel *is* the deliverable of this phase, so its structure and interaction model are part of the contract. It is delivered by `@motajs/editor-impl/table`, which exports **both** a registrable panel type (into the Phase-1 `ShellSystem`) **and** the underlying React table component (D-01).

### Panel instance model (D-02)

- Each panel instance holds its **target table internally**; there is **no global "current table"** in the editor.
- The target is set externally through an **extra panel method** (working name `ITablePanel.setTable(...)`) that sits **outside** Phase 1's `IEditorPanel` (the exact name is confirmed in `INTERFACE-NAME.md`).
- The panel reads **both data and schema through the `editor-core` resource layer** (D-03): a data table is resource `table.<name>`; its schema is `table#schema.<name>` (D-04).
- Consequence for the UI: the panel has **no table-picker of its own**; it renders whichever resource its target points at (or the loading / empty / error state for that resource).

### Layout (top → bottom)

```
┌───────────────────────────────────────────────────────────────┐
│ TOOLBAR   32px, --editor-subtle surface, bottom border         │
│   [ 编辑 | 添加 | 删除 ]                    [ 编辑 Schema ]      │
├───────────────────────────────────────────────────────────────┤
│ TABLE REGION   fills remaining height, scrolls vertically      │
│   header row:   条目   |  注释   |  值       |  操作            │
│   gap row:      ----   |  ----   | ['field'] |  [折叠/展开]     │
│   leaf row:     name   | comment | [input]   | [注释][编辑][复制]│
│   …                                                            │
└───────────────────────────────────────────────────────────────┘
```

- The panel fills the shell content area (`width/height: 100%`), column flex; the **table region is the only region that scrolls**.
- The toolbar always renders while a target table is loaded. During loading / error, the toolbar is rendered disabled (or omitted) and the table region shows the state copy.
- The `<table>` is a real HTML table (parity): `<thead>` header row, `<tbody>` data rows, `border-collapse: collapse`, `table-layout: fixed`.

### Toolbar

| Control | Contract |
|---------|----------|
| Edit-mode `Segmented` | 编辑 / 添加 / 删除 (values `change` / `add` / `delete`), controlled, default **编辑**. This is the parity add / delete affordance (see "Add / delete"). Small size, leftmost. |
| 「编辑 Schema」`Button` | Primary (`type="primary"`), small size, rightmost. Hidden when the panel's target is itself a schema (D-05). Opens a **new** panel instance targeting `table#schema.<name>` (D-06). |
| Toolbar title | Optional muted text at the left showing the table resource name; uses Label role and truncates with ellipsis. |

### Column model & widths (parity)

Four fixed-proportion columns, `table-layout: fixed`:

| Column | Width | Content |
|--------|-------|---------|
| 条目 | 24% | Field name (`shortField`), single-line ellipsis, `title` = full field path |
| 注释 | 19% | Short comment, single-line ellipsis, `title` = full comment |
| 值 | 32% (no padding) | The inline input control (see below) |
| 操作 | 25% | Row-action buttons, centered |

### Row types

**Header row** — `条目 | 注释 | 值 | 操作`, semibold (Heading role), muted text, `--editor-subtle` background, 1px `--editor-grid` bottom border. Not interactive.

**Gap row** (a non-leaf node with children) — parity `GapRow`:
- Cells render `---- | ---- | ['<field>'] | [折叠/展开]`.
- The 4th cell holds a **折叠/展开** toggle button (parity `--etable-fold-btn-*` tint). Label is **「展开」** while collapsed and **「折叠」** while expanded (reads/inverts as in the legacy component).
- Expanded: child rows render immediately below (indented by nesting depth via a left border + `sm` left padding). Collapsed: children are removed from the DOM.
- Fold state is **panel-local UI state** (not part of document history; not undoable) — it must survive re-renders but need not persist.

**Leaf row** (an editable value) — parity `TableRow`:
- Cells render `name | comment | [input] | [actions]`.
- Zebra stripes: odd rows `--editor-surface`, even rows `--etable-zebra` (`#fafafa`); 1px `--editor-grid` borders on all cells.
- Hover: the 值 cell shows the `--etable-hover-value` border + glow; the 条目 / 注释 cells show the `--etable-hover-meta` border + glow (parity). Hover highlight is decorative and must not imply edit state.
- Clicking a row is a **select-to-act** gesture in 添加 / 删除 mode (see "Add / delete"); a single click does nothing in 编辑 mode.
- **Double-click** (implemented as two clicks within 500 ms, to also support touch — parity) triggers the mode-sensitive action: 编辑 → open external editor; 添加 → add-child prompt; 删除 → delete confirmation.

### Inline edit affordance & input controls (D-07 parity)

Every leaf row's **值** cell is an inline editor. The control is chosen by the field's schema type (`_type`), matching the legacy mapping exactly:

| Field type | Control | Commit trigger | Notes |
|------------|---------|----------------|-------|
| (default / `textarea`) | `antd` `Input.TextArea` (or styled native `textarea`) rendering the value's **JSON** | **on blur** | JSON-parsed on commit; a parse failure reverts the display to the last valid value (parity `TextareaInput`). `indent` from config controls formatting. `_type: 'disable'` → read-only. |
| `select` | `antd` `Select` (small) with `_select.values` options | on change | Option values are the configured values; strings show verbatim (parity `SelectInput`). |
| `checkbox` | `antd` `Checkbox` | on toggle | Boolean value. Centered in the cell. |
| `checkboxSet` | Inline `antd` `Checkbox` set with `_checkboxSet.key` / `.prefix` labels | on toggle | Value is an array of selected keys; unknown keys are appended as extra members. Cell is vertically scrollable (`max-height: 250px`) — parity. |
| `color` | `antd` `ColorPicker` (`size="small"`, `showText`, `format="rgb"`, `disabledFormat`) | on pick | Value is `[r,g,b]` or `[r,g,b,a]`; alpha preserved only when the source had 4 channels (parity `ColorInput`). |
| `event` / `material` / `point` / `popCheckboxSet` | Read-only JSON text in the cell + the 操作 column's **编辑** button | via external editor | Editing happens in the external editor (below), not inline. |

- The input sits flush in the cell (the cell's inner wrapper is absolutely positioned to fill it — parity `etableInputDiv`), so textareas fill the row height and never shift the grid.
- On commit, the value is written through `editor-core`'s unified undo path as **one reversible operation** (D-09); persistence is asynchronous via the resource layer (memory-first, eventually consistent).
- **Validation**: before commit, the field's `_range` expression is checked. On failure the change is rejected, the field shows the destructive error border/text, and the copy 「{字段} : 输入的值不合要求，请鼠标放置在注释上查看说明」 is surfaced (parity).

### Add / delete affordances (parity: edit modes + double-click)

Add and delete are **mode-driven**, exactly as in the legacy table — there are no per-row `+` / `−` buttons:

| Mode | Single-click / double-click behaviour |
|------|---------------------------------------|
| 编辑 (`change`) | Double-click → open the field's external editor. Inline edits are always active regardless of mode. |
| 添加 (`add`) | Double-click a row → prompt 「请输入新项的名称」, validate via the existing id validator, then add a child under the row's parent path. Success copy 「添加成功，刷新后生效。」 |
| 删除 (`delete`) | Double-click a row → confirm 「确定要删除吗？」; rejection when the field may not be `null` → 「{字段} : 该值不允许为null，无法删除」. Success copy 「删除成功，刷新后生效。」 |

- The selected edit mode is visible in the toolbar `Segmented`; the accent highlight marks the active segment, the destructive tint marks 删除.
- All add / delete operations flow through the unified undo path (D-09) and are undoable / redoable.

### 「编辑 Schema」button (D-05, D-06)

- Rendered as the toolbar's rightmost primary button, label 「编辑 Schema」, tooltip 「编辑当前表格的 Schema」.
- Clicking opens a **new table-panel instance** whose target is the current table's schema resource (`table#schema.<name>`) — it does **not** navigate the current tab in place.
- The button is **hidden** when the panel's own target is already a schema (a schema has no schema — no `table#schema#schema`, D-05).
- While the schema resource is loading / missing, the button may be shown **disabled**; it is never a no-op that silently fails.

### Schema presentation mode (D-10)

Schema tables reuse the **same engine** (same grid, header, rows, inputs, fold, edit modes) with a **schema-specific presentation mode** switched on when the target is a schema. The presentation rules are **engine-built-in / injectable**, never described by a schema.

Differences from the regular mode (canonical rule set — see Flagged Decision F2):

1. **Paired fields on one row.** Fields that form a numeric bound pair (`min` + `max`) render as **one row** with two small `InputNumber`s side-by-side (left / right), instead of the two separate rows a regular table would show. The row's 条目 cell carries the combined label (e.g. 「数值范围」).
2. **Compact scalar fields.** `step` / `integer` and similar schema scalars render as single small controls (`InputNumber` / `Checkbox`) on their own row.
3. **No 「编辑 Schema」button** (D-05) — the toolbar shows only the edit-mode control.
4. **Schema-mode banner.** A slim, muted one-line banner above the grid signals schema editing (Display/Heading role), e.g. 「正在编辑表格结构（Schema）」, so the user can tell the two modes apart at a glance.
5. All other parity behaviour (inline edit, fold, add / delete modes, external editor) is unchanged.

> The exact grouped-field rule set and labels are `the agent's Discretion` and must be confirmed in `INTERFACE-NAME.md` before implementation (F2).

### External editor integration (parity)

- The 操作 column's **编辑** button (and a 编辑-mode double-click) opens the field-type-appropriate external editor: code editor (`textarea`), event editor (`event`), material picker (`material`), point picker (`point`), or checkbox-set modal (`popCheckboxSet`).
- `select` / `checkbox` / `checkboxSet` / `color` / `disable` types show no 编辑 button (parity `shouldShowEditButton`); `disable` additionally shows a **复制** button; `popCheckboxSet` labels the button **多选框编辑**.
- A **注释** button appears only when a short comment exists; it reveals the full comment.
- Returned values re-enter through the same validated, undoable commit path.

### States

| State | Presentation |
|-------|--------------|
| **Loading** | Table region shows a centered, muted `Spin` + Label 「正在加载表格…」; toolbar disabled. |
| **Empty** | No rows to render → centered Display heading 「暂无表格数据」 + Label body 「该表格当前没有可显示的字段，或内容为空。」 (schema target: 「尚未定义任何字段。」). The toolbar stays available except where a target is required. |
| **Error** | Resource request fails → centered destructive heading 「表格加载失败」 + Label body 「请检查该表格资源是否存在，或稍后重试。」 + a **retry** button. The panel stays open and the tab closable. |
| **Target not set** | No target yet → the empty state with a muted hint that a target table must be set by the host. |
| **Partial** | A schema tree where some fields are missing config renders those fields with the default textarea control; an individual field that fails validation shows the destructive error treatment without taking down the grid. |

### Overflow & long text

- **Vertical**: the table region scrolls; the toolbar stays pinned (not part of the scroll).
- **Horizontal**: with `table-layout: fixed` and percentage widths, no horizontal scroll is expected; a value wider than its cell is clipped by the input (textareas scroll internally).
- **Long field names / comments**: single-line ellipsis + `title` attribute with the full text.
- **Long / multi-line values**: the value cell renders a scrollable textarea; the grid row grows to fit up to a max height, then the textarea scrolls internally.
- **Many rows**: plain vertical scroll; no virtualization is contracted in this phase.

### Accessibility & content safety

- Every interactive control is a real focusable element (button / input / antd control) with an accessible name; the fold toggle carries its 「折叠」/「展开」 label.
- Focus order follows the grid: toolbar → header → rows (fold toggle → cell input → row actions), left-to-right, top-to-bottom.
- **All cell content (field names, comments, values, schema labels) is rendered as text via React** — never `dangerouslySetInnerHTML` (XSS mitigation; the legacy `htmlEscape` behaviour is achieved by React default escaping). The `title` attributes are set as plain strings.
- `data-test-id` attributes are preserved from parity for E2E: `data-table`, `data-table-grid`, `table-row-<field>`, `table-input-<field>`, `table-edit-<field>`, `table-edit-mode`.

## Styling Approach (resolved)

**Decision: antd components + co-located plain CSS** (CONTEXT D-08). Component structure and interactive controls come from `antd@6.2.1` (already a `peerDependency`); layout, the grid, and the parity decoration come from a **single co-located kebab-case stylesheet** shipped with the table module (working name `packages/libs/editor-impl/src/table/table.css`, imported by the panel/table root). The panel styles exclusively through the Phase-1 `--editor-*` variables (with literal fallbacks) plus the panel-scoped `--etable-*` parity variables documented in `## Color`. No PandaCSS, no Tailwind, no new runtime dependency.

**Companion change REQUIRED for this to build/package correctly (same class as Phase 1):**

1. `packages/libs/editor-impl/package.json` currently has `"sideEffects": false`. It must become `"sideEffects": ["./src/**/*.css"]` so bundlers do not tree-shake the table stylesheet. If the package instead inlines styles, document that and skip this change.

> The panel-type registration icon (`icon: ReactNode`) is a separate concern — see F1.
