# Flagged assumptions for this plan
# - P24 现状：`TextareaInput`（TextareaInput.tsx:47-69）用 `Input.TextArea` + `autoSize={{ minRows:1, maxRows:6 }}`（:58）。
#   `autoSize` 会按内容设**行内 height**，因此视觉更像单行、且与右下角原生拖拽互相冲突（拖拽后会被 autoSize 覆盖），
#   用户报告「看起来不像文本域、不能拖拽调整大小」。
# - 修复取向（用户明确：autoSize 可接受，但更希望能拖拽）：**去掉 autoSize**，改为显式 `rows` —— 计算文本行数、
#   夹在 [1, 6]，`rows` 超过可视行时浏览器原生给出内部滚动条；再由 CSS `.etable-input-textarea { resize: vertical }`
#   开启右下角纵向拖拽。这样默认高度 = 内容行数（≤6），且可拖拽（拖拽设置的行内 height 不会被 React 重置，因为
#   React 只控制 `rows` 属性、不控制 height）。
# - 现有 CSS：`.etable-input-textarea`（table.css:292-299）有 `max-height:160px; overflow:auto`；`max-height` 会限制拖拽上限，
#   故放宽 / 去掉（或改大到足以容纳拖拽），并保留 `width:100%`。
# - 既有断言：`layout.uat.test.tsx:275-294` 只断言该元素是 antd `Input.TextArea`（类名 `ant-input` / `etable-input-textarea`），
#   不以 autoSize 为准，故去 autoSize 后该断言仍成立，仅需新增行数 / 拖拽用例。
# - 依赖 02-26：本计划与 02-25 / 02-26 都改 `table.css`，故 wave 19 晚于它们；同样与 02-25 共用 `layout.uat.test.tsx`。

<objective>
修复 `string` 值文本域的高度与可调整性（G-02-UAT2 的 P24）：默认高度按内容的行数显示（最多 6 行、超出用内部滚动条），并允许**拖拽调整大小**；仍沿用 antd `Input.TextArea` 与既有提交 / 校验语义。

Purpose: 现在的文本域用了 `autoSize={{ minRows:1, maxRows:6 }}`，看起来像单行、没有右下角拖拽手柄、也拖不动，多行编辑很不方便。改为按行数的默认高度 + 可纵向拖拽后，多行值一眼可见、需要时还能拉大。

Output:
1. `inputs/TextareaInput.tsx`——按内容行数（上限 6）设定 `rows`，去掉 `autoSize`。
2. `table.css`——文本域可纵向拖拽、放宽最大高度限制。
3. `layout.uat.test.tsx`——默认行数 / 上限 / 可拖拽的用例。

**新增命名提案（逐条待用户按「重要命名先确认」门禁确认后才可落实现）：**
- `resolveTextareaRows(text: string): number`（**新增**非导出函数，`components/inputs/TextareaInput.tsx`）：把文本行数夹在 `[1, 6]`，作为文本域的默认 `rows`。

</objective>
