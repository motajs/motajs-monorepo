<objective>
修复 schema 编辑视图的两个关键字问题（G-02-UAT2 的 P21 / P22）：把 `x-order` 的**纯重排**从「误报非法」改为**接受**（并保留其文本域编辑），并让 `type` 关键字提供 **7 个合法 JSON Schema 取值**的选择、挡住 `textarea` 之类的非法值。

Purpose: 现在在 schema 表里给 `x-order` 调换顺序会被判非法，实际是把数组值拿去按字符串校验；而 `type` 被当普通字符串，用户填 `textarea` 看似生效实则不是合法 JSON Schema type。修复后 schema 编辑既能正确接受合法重排，又能把 `type` 约束到合法集合。

Output:
1. `model/schemaPresentation.ts`——`x-order` / `type` 的关键字配置（校验与控件）。
2. `schemaMode.test.tsx`——上述行为的用例。

**新增命名提案（逐条待用户按「重要命名先确认」门禁确认后才可落实现）：**
- `SCHEMA_TYPE_VALUES`（**新增**模块级常量，`model/schemaPresentation.ts`，`readonly string[]`，非导出）：JSON Schema 的合法 `type` 取值集合（`string` / `number` / `integer` / `boolean` / `object` / `array` / `null`），供 `keywordConfig('type')` 构造 `enum`。

</objective>
