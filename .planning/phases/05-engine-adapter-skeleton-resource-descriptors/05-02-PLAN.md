## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| core contributor → core source | Any engine word that enters core production source re-couples core to one engine; the gate is the boundary that must reject it. |
| CI config author → the gate suite | An edit that loosens the verifier's scope, term list, or exclusion rule silently disables the boundary; a rule that cannot fail is indistinguishable from no rule. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Tampering (gate bypass) | `scripts/verify/coreEngineNeutral.js` scope/regex | high | mitigate | The verifier carries a two-polarity self-proof (synthetic fixture must fail, `Math.floor` and false friends must stay clean), asserts a non-zero file count, and is wired inside the pre-existing `lint` job; `ci-workflow.js` independently guards the four-job shape. |
| T-05-07 | Information Disclosure / design erosion | Vocabulary leak enabling engine lock-in | medium | mitigate | The gate scans RAW source including comments, so a leak cannot hide in a `//` comment; the term list is written in the verifier, not derived, so it cannot be silently emptied. |
| T-05-08 | Repudiation | A weakened verifier presented as active | medium | mitigate | Task 2 asserts the fixture's clean and dirty cases both behave; a scope or term-list change that makes the fixture vacuous reds the two-polarity assertion. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | This phase installs no package. The verifier is plain Node ESM and imports only `node:fs`/`node:path`/`node:process`. Any proposed dependency halts for the Package Legitimacy Gate. |
</threat_model>
