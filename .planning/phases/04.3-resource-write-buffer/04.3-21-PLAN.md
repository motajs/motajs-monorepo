<objective>
把「一条路径任何时刻最多只有一个编辑者」落实到表格面板内部：同一个面板里不许两栏指向同一个数据文件；选到已被占用的文件时，同面板另一栏拿着就闪一下那一栏的边框，别的标签拿着就切到那个标签，本栏都保持原目标。同时把 17 为了让「两栏同表」能联动刷新而收窄的刷新守卫恢复成 Plan 16 确认过的「或」形状，删掉两栏同表的测试，并把 `TablePanel.isSamePanelWrite` 收窄到「兄弟 schema 栏写盘」这一种仍然合法的情形。

Purpose: 两栏共享一份路径缓冲时，「谁先确认谁被后写的悄悄覆盖」只能靠「最后写盘者胜」解释；用户决定从结构上关掉这个口子（D-28 / D-29 取代 D-12 / D-13）。口子一关，两栏同表的用例描述的就是不存在的状态，必须删；`TablePanel.isSamePanelWrite` 只收窄到「另一栏的 `target.dataPath` 就是这次变化的路径」这一支（兄弟 schema 栏写盘），不能整段消失——数据栏为脏时它是唯一还能阻止假冲突框的抑制点；刷新守卫也才有条件回到 Plan 16 的形状——但恢复「或」会把「本栏自己有待写」的栏一起冻住，而同面板数据栏 ↔ schema 栏的联动刷新恰好落在这一类，因此必须同时给 `TablePanel.refresh` 一个只跳过 `pendingWrite`、永不跳过 `pendingConflict` 的放行口。
