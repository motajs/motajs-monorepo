  <action>
    给 `NumberInput` 加本地草稿状态（初始值由 `props.value` 推出，非数字时按空值呈现）：输入框的 `onChange` 只更新本地草稿，**不调用** `props.onChange`。

    三个确认动作各提交一次：失焦时提交、按下回车时提交（**提交后不失焦**）、值被清空时提交空值。Escape 放弃本次输入并把本地草稿回填成 `props.value`。提交时把草稿转成数字或空值后调一次 `props.onChange`。

    **提交必须是同步的一次回调，不得返回 Promise、不得自己派发失焦**：`INumberInputProps.onChange` 的类型是 `(value: number | null) => void`，它在一次确认里只被调一次；回车分支里**不要**为了实现「确认后收起」而手动 blur 或 `event.currentTarget.blur()`。理由是这条提交要让面板侧的 `TablePanel.applyEdit` 观察到「用户确认了一次」，弹窗推迟才会被解除（Plan 08 的 (f)）；用 blur 来表达确认会把语义压回「失焦才算停手」，数字框回车后就必须靠移开焦点才弹窗。这条语义与 Plan 08 一致，两处不得各说一套。

    加一个副作用：`props.value` 变化时把本地草稿回填成新值，使外部刷新 / 撤销重做后输入框显示最新内容（依赖只有 `props.value`，不要依赖对象引用）。

    保留 `size` / `className` / `disabled` 的既有写法与类名；`INumberInputProps` 的三个成员逐字不变。**不要**引入新依赖、不要用受控组件以外的模式改变调用点。
