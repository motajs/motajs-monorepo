## Accomplishments

- `tablePanel.ts` 的栏状态接口 `ITablePanelColumn` 新增必选布尔 `pendingWrite`，JSDoc 写明它是「本栏目标路径现在还有内容在等待写盘」，与组件草稿脏、面板侧未落盘标记一起决定工具栏的「未保存」，5 秒自动写盘完成后自动变回假；`createColumn` 里紧挨 `unsaved: false` 初始化为 `false`。全文件除此初始化外没有第二个读写点。
- 面板渲染根的参数接口 `ITablePanelViewProps` 新增**可选**成员 `onFieldEditingChange?: (editing: boolean) => void`，JSDoc 说明「真表示焦点在某个可编辑字段（input / textarea / select / contenteditable）上且尚未失焦 / 尚未确认提交，外部冲突弹窗据此推迟到停手后再弹」，并写死「实现方必须同步、不返回 Promise」。视图函数 `TablePanelView` 没有传它——本计划零接线。
- `NumberInput.tsx` 只改注释：`INumberInputProps.onChange` 的 JSDoc 补上「只在输入框失焦、按下回车、或值被清空这三种确认动作之后各触发一次，不再随每次按键触发；未确认期间输入内容只活在控件本地」，组件 JSDoc 补一句「与文本域共用同一套『确认后才提交』的语义」。props 三个成员形状未变，`props.onChange(next)` 实现行逐字未变。
- `explorerPanel.test.tsx` 里全仓唯一手写的假面板上下文补齐 Plan 02 新增的三个必选成员：`flushResource`（立刻成功）、`discardPendingResource`（空方法体）、`watchPendingChange`（立刻用空数组回调一次，再返回空退订函数）。没有使用任何 `as` 断言，`editor-impl` 的 typecheck 由此从 TS2739 转回 exit 0。

## Decisions Made

- **`pendingWrite` 的位置**：放在 `unsaved` 之后、`unsavedSchema` 之前，让「未落盘」类成员聚在一起；`createColumn` 里同样紧挨 `unsaved: false`，读代码时两处一一对应。
- **回调声明为可选**：本计划视图不传它，Plan 08 才接线；若写成必选，本计划就凭空多出一处必须实现的接线，违反「零行为改动」。
- **「必须同步」写进 JSDoc**：签名是 `(editing: boolean) => void`，接线时若写成 `async` 箭头，返回 `Promise<void>` 会直接触发 TS2322。提前把这条约束写在契约处，比在 Plan 08 里踩一次编译错误更省事。
- **数字控件不一并对齐实现**：此刻实现仍是逐键提交，属于「注释超前于实现」的已知临时不一致，只持续到 Plan 09；这条不一致正是本计划要立的契约，若现在顺手改实现就变成行为改动。
- **假上下文的订阅立刻回调一次**：接口契约是「订阅瞬间立刻回调一次当前待写路径列表」，所以空实现先 `listener([])` 再返回空退订函数，而不是什么都不做。

## Deviations from Plan

没有自动修复类偏差，三处改动与计划逐条对应。以下两点是**计划内的顺序性事实**与**一处行文口径选择**，如实记录：

1. **Task 1 / Task 2 的 verify 里 `typecheck` 一步在当时仍为红（exit 1），且唯一错误就是 Task 3 要修的那一条。** `IEditorPanelContext` 三个必选成员是 Plan 02 加的，`editor-impl` 里唯一手写假上下文缺这三个成员，`tsc -b` 也会检查测试文件，因此在本计划顺序执行到 Task 3 之前，`pnpm --filter @motajs/editor-impl typecheck` 必然报 `explorerPanel.test.tsx(36,3): error TS2739 … missing … flushResource, discardPendingResource, watchPendingChange`。Task 1 / Task 2 提交时已确认**错误清单里只有这一条**（我的声明本身零错误），Task 3 提交后 `typecheck` exit 0。这条跨计划依赖在 `04.3-02-SUMMARY.md` 中已登记为「留 Plan 03 修复」。
2. **两处 JSDoc 用了多行块而非单行**（`ITablePanelViewProps.onFieldEditingChange`、`INumberInputProps.onChange`、`createContext`）。代码风格要求「成员 jsDoc 单行，除非一行写不下」，这几条用途说明都超过一行的合理长度，因此换成多行块；`ITablePanelColumn.pendingWrite` 与其它既有长注释一样保持单行。

**Impact:** 无行为改动。三处改动全部是类型成员与注释，运行时不产生任何新的读写路径；`isColumnDirty` / `publish` / `saveDocument` / `applyEdit` / `save` 五个方法体在 diff 中零变化。
