# Phase 04.3 Plan 08: 表格自动保存与冲突两个定稿动作 Summary

**表格从「必须点保存才落盘」变成「确认一格就写缓冲、5 秒后自动落盘、保存按钮立刻写盘」，并把外部冲突改成「保存编辑器的 / 保存外部修改」两个立刻生效的动作、只在用户停手后才弹**

## Accomplishments

- **字段确认即写缓冲**：`TablePanel.applyEdit` 成功分支末尾调 `TablePanel.saveAfterEdit`（即发即忘，不改同步签名），内部转调 `TablePanel.saveColumn(columnIndex, true)`。一次确认 = 一次缓冲写入，与手动保存共用同一条 `saveDocument` → `persist` / `persistSchema` 链，没有第二套序列化。基线推进与 `refreshDependents` 的位置逐字未动：写缓冲返回后立刻推进基线（早于 50 毫秒合并通知）、同一方法内刷新本面板其它栏，因此写者自己那一栏不弹冲突、两栏同步不变成 5 秒延迟。
- **安静模式**：`TablePanel.saveColumn` / `TablePanel.saveDocument` 各加可选 `quiet`；安静模式只把内容排进缓冲、不刷「已保存」也不清提示位，所以自动保存不会把「添加成功」这类文案顺手擦掉（`behaviour.uat` 的提示文案用例仍绿）。
- **保存按钮 = 立刻写盘**：`saveDocument` 的非安静分支在写缓冲之后按该栏数据文件与推导出的 schema 文件各 `flushResource` 一次，失败走既有「写入失败，请重试。」并返回 `Failed`。保存按钮、`TablePanel.save()`、切走、保存并关闭、释放编辑器因此全部等的是磁盘结算；全程没有全量写盘，不会写掉别的面板还没确认的内容。
- **「未保存」收成单一口径**：`TablePanel.isColumnDirty` 加第三来源 `pendingWrite`（面板侧未落盘标记 ‖ 组件草稿脏 ‖ 本栏路径还有待写），`publish` 的 `unsaved` 用同一个表达式。于是自动写盘完成后待写消失、标记自动消失；「只有待写、没有草稿」时关闭询问也会弹三态框，用户能看到既有的「正在保存…」并等落盘（复用 `handleCloseChoice` / `saveAllColumns`，没有第二个保存中态）。
- **待写标记的订阅**：`TablePanel.refreshPendingWrites` 按订阅回调送来的全部待写路径刷新每栏布尔并重发视图；`initialize` 订阅（订阅时立刻收到一次当前值）、`dispose` 退订。
- **「不保存关闭」丢弃待写**：`TablePanel.onDiscard` 清完脏标记后对本栏两条路径各 `discardPendingResource` 一次，否则 5 秒后会把刚丢弃的改动写回磁盘。
- **外部冲突两个定稿动作**：「保存外部修改」= 先 `discardPendingResource`（同时失效内容缓存）再按收到变化时记下的外部原文换内容（不重新读盘）；「保存编辑器的」= 先把该栏显式放回未落盘 → `saveColumn(columnIndex, true)` 排进缓冲 → `flushResource(conflict.path)` 立刻覆盖外部修改 → 清冲突与弹窗。两条失败分支都确定性结算：待写保留、弹窗不关、未保存标记仍在，只走既有错误提示与 `resource.flushFailed` 日志，点击处理器不产生未处理拒绝。
- **「停手才弹」**：`isEditableFieldElement` 把「正在打字」收窄到 input / textarea / select / contenteditable，`etable-columns` 根的 `onFocus` / `onBlur` 经 `onFieldEditingChange`（同步 void）报到 `TablePanel.setFieldEditing`；`onBlur` 看 `relatedTarget` 保持字段→字段的跳转。**一次成功的确认提交也解除推迟**（`applyEdit` 末尾调 `setFieldEditing(false)`），所以数字框按回车确认后不失焦也会立刻弹；被拒绝的编辑不解除。全程不读 `document`。
- **在途写回的护栏**：`saveDocument` 用内容版本号判断「写盘期间内容是否被换过」，撤销 / 外部刷新换了内容时旧快照不再回写面板状态；撤销 / 重做本身把新算出的内容写进缓冲（传面板自己算出的文档，而不是 `currentDocument`——那一刻挂载中的组件还持着撤销前的草稿并自称脏）。

## Decisions Made

- **flush 落在 `TablePanel.saveDocument` 的非安静分支**，而不是只在 `TablePanel.save` / `TablePanel.saveAllColumns` 里显式循环（见偏差 2）。这样保存按钮、`panel.save()`、切走、关闭、释放、换表后的写回全部经同一处落盘，只有一处实现。
- **撤销 / 重做也写缓冲**：撤销只改面板内容，但更早那一份快照可能还在缓冲里；不刷新的话 5 秒后会把撤销掉的内容写回磁盘。写入时用面板自己算出的文档，避免组件残留草稿把撤销的内容写回去。
- **`saveDocument` 的内容版本护栏**：自动保存是即发即忘，撤销 / 外部刷新可能落在它的 `await` 之间；用版本号让位给更新的面板状态，而不是让旧快照覆盖。
- **`isColumnDirty` 的第三来源直接读 `pendingWrite` 字段**（由订阅维护），不在每次判脏时现查资源层。
- **地图 / 素材面板一个字都没改**：不传新文案、行为不变（D-21 / T-04.3-22）。
