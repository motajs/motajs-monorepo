  <action>
    在 `resourceSystem.ts` 加模块级数字字面量常量 `NOTIFY_COALESCE_MS = 50`，加一个实例字段「路径 → 待发通知定时器」的 `Map`（**不能是模块级 `new Map()`**）。

    `writeContent` 在「写缓冲 + `cache.set`」之后调一次私有方法安排合并通知；安排逻辑是：该路径**已有**待发定时器时直接返回（首次排程不重置），没有时才排一个 `NOTIFY_COALESCE_MS` 毫秒的定时器，回调里先删掉表项，再对全部钩子投递一次「该路径、内容变化」——投递照抄既有广播的吞错口径：每个钩子单独 `Promise.resolve().then(...).catch(...)`，失败记 `resource.hookFailed`，且**不预读内容**（只给路径与种类）。

    `discardPendingContent` 在丢弃缓冲之后，若该路径有待发通知就清掉定时器并删表项（丢弃的内容不应该再通知别人）。

    `dispose` 在清缓冲之后、退订之前，清掉所有待发通知定时器并清空表。

    **不要**改 `updateResource` 与 `handleFileChange` 里 Plan 04 已接好的「外部变化标记」逻辑，也不要在合并通知里调用它——这条通知表达的是「本编辑器刚写完」，走了会把刚写的待写标成「外部已改」、把它的自动落盘取消掉。本计划只在三处接线：`writeContent` 排通知、`discardPendingContent` 取消通知、`dispose` 清通知定时器。`updateResource` 的既有广播次数与 `core.test.ts` 的旧通道断言不要变。**不要**新增第三条钩子、不要给通知加来源参数。**不要**在通知里调用 `readContent`。
