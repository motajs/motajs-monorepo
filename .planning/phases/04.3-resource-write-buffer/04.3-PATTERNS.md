### W2-1. `src/resource/writeBuffer.ts`（新建，缓冲本体）

**Analog:** `packages/libs/editor-core/src/resource/contentCache.ts:23-91`

这是全仓**唯一**「interface + 类 + 实例 `Map` + 模块级纯函数」的写法，也正是缓冲需要的形状。逐字摘录头部与写入口：

`[VERIFIED: packages/libs/editor-core/src/resource/contentCache.ts:5-10]`

```ts
export class ContentCache implements IContentCache {
  /** 路径到缓存条目的映射，按最近使用序排列（最旧在前） */
  private readonly entries: Map<string, IContentCacheEntry> = new Map();
  /** 缓存内容的总字节上限 */
  private readonly maxBytes: number;
  /** 当前缓存内容的总字节数 */
  private totalBytes: number = 0;
```
`[VERIFIED: packages/libs/editor-core/src/resource/contentCache.ts:23-29]`

**必须改掉的地方（三条，全是坑）：**

1. **不能有上限、不能有 LRU**：`ContentCache.set` 对超过 8 MiB 的单条内容**直接不入缓存**（`contentCache.ts:46-52`），缓冲照抄会让大地图 / 大素材静默丢内容。缓冲的 `set` 永远写、只在 flush 成功后 `delete`。
2. **模块级不能放 `new Map()`**：`coreModuleState` 的第三条选择器专门拦 `Program > VariableDeclaration[kind="const"] > VariableDeclarator > NewExpression[callee.name=/^(Map|Set|WeakMap|WeakSet)$/]` `[VERIFIED: scripts/verify/coreModuleState.js:55-59]`。所有 `Map` 必须是**实例字段**（像上面 `entries` 那样）。
3. **模块级常量只能是字面量**：`export const FLUSH_DEBOUNCE_MS = 5000;`（数字字面量）合规；`export const DEFAULTS = { ... }` 不合规，要么 `Object.freeze(...)`、要么 `as const`——仓库既有做法是 `Object.freeze` `[VERIFIED: packages/libs/editor-core/src/log/messages.ts:4]`。

**本文件的术语红线：** `coreEngineNeutral.js` 对 `editor-core` 生产源码（排除 `__tests__`）逐词扫描 `tower / floor / loc / autopass / autotile / idnum / airwall / commonEvent / prefab / mota`，注释也算 `[VERIFIED: scripts/verify/coreEngineNeutral.js:49,53,67]`。写 JSDoc 时别用这些词，也别写 `Math.floor` 之外的裸 `floor(...)`。

### W2-3. `src/resource/resourceSystem.ts`（核心改写）

**Analog:** 同文件四处，逐字引用：

读（要插缓冲查找）：

```ts
      logger.error('system.notInitialized', 'Resource');
      return undefined;

    const cached = this.cache.get(id);

    if (cached !== undefined) return cached;

    const content = await this.fs.readFile(id);

    return content;

```
`[VERIFIED: packages/libs/editor-core/src/resource/resourceSystem.ts:64-78]`

```ts
  async writeContent(id: IResourceIdentifier, data: ResourceContent): Promise<void> {
    if (!this.fs) {

      return;
```

## Shared Patterns

### S1. 定时器 / 防抖 / 合并：仓库里只有「裸 `setTimeout` + `clearTimeout`」，没有库

全仓 `editor-core` / `editor-impl` / `editor-dev` 的 `setTimeout` 命中只有 3 个非测试点：`MapLayerDialog`（一次性 focus，`clearTimeout` 在 effect cleanup 里）、`MemoryBackend.notify`（宏任务推迟）、测试里的 `settle` 辅助。**没有任何 debounce / throttle 工具、也没有对应依赖**（D-24 禁新依赖）。

可照抄的清理形态：

```tsx
  useEffect((): (() => void) => {
    if (!props.open) return (): void => undefined;
    ...
    const timer = setTimeout((): void => { ... }, 0);

    return (): void => clearTimeout(timer);
  }, [props.open, ...]);
```
`[VERIFIED: packages/libs/editor-impl/src/map/components/dialogs/MapLayerDialog.tsx:44-61]`

**本阶段的差别（必须写进计划）：** 这是 **class 字段上的定时器**，不是 effect 里的。生命周期的等价物是 `ResourceSystem.dispose`——实现里要逐个 `clearTimeout` 并清空表（`04.3-RESEARCH.md:1433-1438` 的 R7）；测试 `afterEach` 调 `ResourceSystem.dispose()` / `core.dispose()`。

**两条定时器语义相反，别写成一个函数：**
- 5 秒防抖：**每次写入都重置**（D-03）。
- 50 ms 合并：**首次排程后不重置**（R10，`04.3-RESEARCH.md:1454-1459`），否则高频写入下永不通知。

## Risks & Tensions（没有完美 analog 的地方）

1. **缓冲放在 `writeBuffer.ts` 还是塞进 `resourceSystem.ts`**：研究推荐前者，`resourceSystem.ts` 现有 214 行已承担 6 个职责。两条都可，但**接口计划必须定死一条**，否则两波各写一半（`04.3-RESEARCH.md:1588-1597`）。
2. **`flush` 挂在哪个接口**（`IResourceSystemAccess` / `IResource` / `IEditorPanelContext`）：这是**本期唯一必须扩的跨包接口**。挂到 `IResource` 最自然（`resource.write` + `resource.flush` 成对），但 `TablePanel` 只持有 `IEditorPanelContext`，还要在 `PanelContext` 里再转发一次。在计划里写清「谁是唯一入口」。
3. **`deleteResource` 与 pending 的交互**：若不丢弃，删掉的文件会在 5 秒后复活。`mapDialogs.test.tsx:745,764` 正是断言「删除后文件不存在」，但测试不推进 5 秒，所以**测试不会红、线上会出事**——必须写成实现真值 + 一条显式用例。
4. **`createResource` 的边界**：O5 已定「新建立即落盘」。R9 警告实现者会为了「统一」顺手也缓冲，导致新建的表 5 秒后才真的存在、`fileExists` / 目录列举不一致。计划里写成真值 + 一条测试。
5. **两栏同表「正在输入被打断」**：50 ms 通知会让另一栏 `contentVersion++`，`EditableTable` 的 `useEffect([props.contentVersion])`（`EditableTable.tsx:110-114`）重置草稿、`TextareaInput` 的 `useEffect([props.value])`（`TextareaInput.tsx:60`）把文本设回 prop → 未失焦的输入被吞。研究推荐「接受 + 写进 UAT」，若用户不接受要扩大到新回调（`04.3-RESEARCH.md:1233-1267`）。
6. **地图 / 素材的 owner 面板没有 flush 能力**：它们的保存时机不变（D-21），所以保存后磁盘最多晚 5 秒。所有「保存后读裸 fs」的资产 / 地图测试都必须补显式 flush（§S6），否则会大面积红。**不要**为了让测试绿去改 `FakeFileSystem`。
7. **`NumberInput` 改失焦提交会改撤销粒度**：现在逐键一次编辑一步撤销；改成确认后一次提交，撤销步数会变少。这是 O4 已接受的交互变更，但 UAT 里要当成已知行为记下来，别当 bug 报。
8. **`schema 视图成对数字框` 容易被漏**：`TableGrid.tsx:475-486` 绕过了 `NumberInput`。只改 `NumberInput` 会让「最小 / 最大」一类字段继续逐键提交，D-09 在 schema 视图里就不成立。
9. **`ShellSystem` 页面事件的注册时机**：放在组件 `useEffect` 里会随挂载 / 卸载重复注册（外壳根可能重挂）。放 `ShellSystem.initialize` / `dispose`，字段与 `ResourceSystem.unwatch` 对称（`resourceSystem.ts:38-39`、`shellSystem.ts:456-466,722-734`）。
10. **`beforeunload` 的诚实限制**：浏览器不等异步写盘；它只能「弹原生确认 + 发起一次 flush」。计划里的 `must_haves` 不能写成「保证不丢数据」（`04.3-RESEARCH.md:939-948`）。
