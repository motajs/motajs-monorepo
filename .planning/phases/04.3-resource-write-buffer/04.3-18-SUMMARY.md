# Phase 04.3 Plan 18: 关闭失败时保留标签与面板（G1）Summary

**素材面板「保存并关闭」写盘失败时不再悄悄关掉标签：面板自己逐条写盘、失败就恢复未保存标记并把「写入失败，请重试。」留在弹窗里；外壳的关闭判断也改成「缓冲是否真的空了」，写盘抛错或还有冲突未表态的待写就把标签与面板留下。**

## Performance

- **Duration:** 约 25 min
- **Started:** 2026-11-01T11:25Z（首个基线测试）
- **Completed:** 2026-11-01T11:40Z（全量回归与结构门禁）

- **Files modified:** 4（2 个源码 + 2 个测试）

## 这个计划要干什么（一句话）

以前点「保存并关闭」时，素材面板只是把内容排进写缓冲便回答「保存」，真正写磁盘发生在外壳里，而外壳把失败吞成一条日志后照常关标签——磁盘没写成功，标签却没了。现在失败会把标签和面板留在屏幕上，用户重试成功才真正关闭。

## Accomplishments

### Task 1：先写会失败的用例（不碰源码）

- **`shellFlush.test.ts`** 追加三条：
  - 「保存并关闭写盘失败时标签保持打开、重试成功后才关闭」——抛错来源的假值；
  - 「冲突被跳过时仍有待写、标签不被丢弃」——给 `FlushPanel` 加一个默认指向 `TARGET_PATH` 的目标路径字段，关闭面板改写到 `OTHER_PATH`，钉住「跳过 → 仍有待写 → 假」而不是「抛错 → 假」；
  - 「干净标签在别处有未决写入时保持打开且既有提示可见」——渲染外壳并断言既有 `editor-shell-pending` 文案。
  - 同时把 `configure({ testIdAttribute: 'data-test-id' })` 与 `afterEach` 的 `cleanup()` 补齐。
- **`assetCloseChoice.test.tsx`**：把旧的「保存失败时改动不丢且重试可落盘」改走真实 `ShellSystem.closeTab`，断言标签、弹窗、错误文案、待写、`unsaved`，并覆盖清掉故障后的重试成功；新增「部分分类写失败时不结算保存」——先给音频分类 seed 一条条目，否则第二个脏分类根本造不出来。
- 实现前两条命令全部失败：`shellFlush` 3 failed / 8，`assetCloseChoice` 2 failed / 7。

### Task 2：两层实现

- **`ShellSystem.flushPendingContent`** 改为 `Promise<boolean>`：`try` 内 `await this.resourceSystem.flushAllContent()`，抛错记 `resource.flushFailed` 并返回 `false`；成功后返回 `!this.resourceSystem.hasAnyPendingContent()`。JSDoc 写明「假值是全局判据、可见状态复用既有提示」。
- **`ShellSystem.closeTab`** 的 `PanelCloseChoice.Save` 分支：`const flushed = await this.flushPendingContent(); if (!flushed) return;`，因此不会走到 `ShellSystem.discardTab`。`Discard` / `Cancel` 分支不变。
- **`AssetPanel.saveAll`**：先把所有 `unsaved` 分类拍成 `IAssetCategory[]` 快照，逐个 `AssetPanel.writeCategory`，全部跑完后重新检查快照里每个分类是否都 `unsaved === false`；任一被守卫跳过或写失败都返回 `false`。快照为空时返回 `false`（保持手动保存不弹「已保存」的旧行为）。
- **`AssetPanel.answerCloseDialog`**：保存前拍同一份快照；`AssetPanel.saveAll` 为假时按原样结算 `Cancel` 并带既有错误文案；为真时按快照逐条 `IEditorPanelContext.flushResource(category.listPath)`，任一条抛错就把快照里每个分类的 `unsaved` 恢复为真，再 `AssetPanel.settleCloseDialog(PanelCloseChoice.Cancel, '写入失败，请重试。')`。全部成功才结算 `Save`。
- 未改 `AssetPanel.writeCategory` 的守卫、`AssetPanel.onSwitchOut` / `AssetPanel.save` 的排缓冲路径；未新增任何文案、toast 或禁用态。

## Decisions Made

- 判据保持全局，不按标签收敛：收窄需要给面板新增「我持有哪些待写路径」的公开成员，与 Plan 16 的「不新增公开接口成员」冲突；假值的可见状态就是既有「正在等待保存」提示。
- 不新增失败文案：只复用表格的「写入失败，请重试。」，避免弹窗的「保存失败：」前缀套出重复标题。
- 素材关闭失败时恢复快照里**所有**脏分类的 `unsaved`（含已成功写出的那份），让重试完整重走一遍保存链；这是 Plan 16 写明的做法。

## Issues Encountered

- **测试夹具细节：** `FakeFileSystem.failing` 同时作用于读和写，所以「失败后磁盘仍是旧值」的断言必须先清掉故障再读。Task 1 初版把读取放在清故障之前，导致该用例在实现完成后仍因 `fake fs: read failed` 变红；调整为「先清故障、读回旧值、再重试关闭」。这是测试夹具限制，不改变被测行为，随 Task 2 提交。
- **`AssetPanel.saveAll` 收紧的附带影响：** 手动保存（保存按钮 / 切出）在一份分类被 `loaded` 守卫跳过时不再弹「已保存」。这是计划明确要求的判据变化（任一分类没写成功整次算失败），不是回归；相关素材测试全部保持绿。
