# Phase 04.3 Plan 21: 一栏一条路径（跨标签 + 同面板 + 刷新守卫）Summary

**把「一条路径任何时刻最多只有一个编辑者」从标签推进到表格面板内部：同一个面板里不可能再有两栏指向同一个数据文件，选到已被占用的文件时同面板另一栏闪 600 毫秒、别的标签则切过去，本栏始终保持原目标；两栏同表的测试随之删除，`TablePanel.isSamePanelWrite` 只保留兄弟 schema 栏写盘这一支，刷新守卫恢复「或」并带只跳过待写的放行口。**

## 这个计划要干什么（一句话）

同一个文件在磁盘上只有一份，所以同一个表格面板里也不该有两栏同时编辑它——用户选到「已经有地方在编辑」的文件时，编辑器不再弹窗或报错，而是把「文件在那边」用闪烁或切标签告诉用户，同时**绝不改本栏原来的目标**。

## Accomplishments

### Task 1：跨标签聚焦（声明 + 外壳 + 面板入口）

- **`IEditorPanelContext.focusResourceTab(identifier): boolean`** 与 `ResourceTabFocuser` 写进 `editor-core` 的面板接口；JSDoc 写清「同步返回、切换即发即忘」与「当前标签自己持有那条登记时返回假」。
- **`PanelContext` 多一个必填构造参数**（`ShellSystem.createInstance` 是唯一构造点，已接线）；注入函数保存在私有字段 `resourceTabFocuser`，公开接口只多一个转发方法。
- **`ShellSystem.focusResourceTab`**：归一 → 空串返回假 → `ShellSystem.findTabByPath` 反查 → 没找到或正是当前活动标签时返回假 → 否则 `void ShellSystem.activateTab(owner)` 后返回真。
- **`TablePanel.setTable`** 最前面接入跨标签分支；`explorerPanel.test.tsx` 的手写假上下文补 `focusResourceTab: (): boolean => false`，`editor-impl typecheck` 因此保持绿。
- 三条 `shellPathDedupe` 用例 + 一条跨标签端到端用例在实现前全部失败（方法不存在 / 本栏目标被改掉），实现后转绿。

### Task 2：同面板一栏一条路径 + 边框闪烁 + 收窄 `isSamePanelWrite`

- **`TablePanel.findColumnByPath(path, exceptColumnIndex)`** 只比 `ITablePanelTarget.dataPath`；查重写在 `TablePanel.setTable` **最前面**（覆盖空栏选择器、空栏新建、「编辑 Schema」复用空栏、打开参数还原四条入口），并排在跨标签分支之前。
- **`TablePanel.flashDuplicateColumn` + `DUPLICATE_FLASH_MS = 600` + `TablePanel.duplicateFlashTimers`**：每栏一个定时器，重复触发先清后装；换目标 / 关栏 / 释放时清掉；发布时带上原有提示文案，避免抹掉它。
- **视图**：有目标的栏根在 `duplicateFlash` 为真时带 `etable-column-duplicate-flash` 与 `data-test-id="table-column-duplicate-flash"`，600 毫秒后两者一起消失；空栏与布局尺寸不动。CSS 只加 `@keyframes etable-duplicate-flash`（两次脉冲、每次 300 毫秒）与 `inset` 内阴影。
- **`TablePanel.isSamePanelWrite`**：删掉「另一栏数据目标推导出的镜像 schema」一支，保留 `target.dataPath === path && column.baselineText === text` 与 `TablePanel.handleResourceChange` 脏分支里的调用；JSDoc 改成只讲兄弟 schema 栏写盘。
- **测试处置**：`twoColumnsSameTable.test.tsx` 整份删除（5 条）；`panelSync.uat.test.tsx` 的两条两栏 schema 用例改成「数据栏 + 它的 schema 栏」；`closeColumn.uat.test.tsx` 的第 1 栏改开 `other`。

### Task 3：刷新守卫恢复「或」+ `ignorePendingWrite` 放行口

- **`TablePanel.refresh(columnIndex, ignorePendingWrite = false)`** 早退条件恢复为 `pendingConflict !== undefined || (!ignorePendingWrite && pendingWrite)`；17 留下的 AND 注释删除，换成两行说明「冲突绝不重读、待写默认不重读但放行口除外」。
- **三处传真**：`refreshDependents` / `onSwitchIn` / `onRetry` 传 `true`；`setTable` 保持默认。`pendingConflict` 在任何入口都不放过。
- **用例 (d)** 钉住「本栏待写时联动刷新仍然发生」：第 0 栏有自己待写的 `t.json`，第 1 栏改 schema 后 50 毫秒内第 0 栏换成数字输入，且 `t.json` 仍在待写里。
