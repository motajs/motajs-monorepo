# Phase 04.3: 资源写入缓冲与表格自动保存 - Context

**Gathered:** 2026-10-29
**Status:** Ready for planning

<domain>
## Phase Boundary

把「什么时候写盘」从各个面板 / 组件收回到资源层：新增按路径的写缓冲，`write` 只写缓冲 + 缓存，防抖 5 秒后 flush；切标签 / 关闭 / 页面失焦 / 释放编辑器时统一 flush。表格改为「字段确认（blur 或回车）后写一次缓冲」，不再要求用户手动点保存才能落盘；两栏同一张表共享同一个路径缓冲，写入后 50ms 合并通知，另一栏立即更新，最后写盘者胜。有 pending 时右上角显示等待保存提示，`beforeunload` 弹浏览器原生确认。地图 / 素材的保存时机不变，但它们的写入也走同一缓冲。

本阶段取代 04.2 的 U-07 gap 计划 `04.2-21`…`04.2-24`；04.2 的面包屑修复（`04.2-20` / `04.2-25`）保持独立。
</domain>

<decisions>
## Implementation Decisions

### 资源层写缓冲
- **D-01:** `ResourceSystem` 增加按路径的写缓冲；`writeContent` 只写缓冲 + 更新内容缓存，不再立即 `fs.writeFile` / `writeBinary`。
- **D-02:** `request` / `readContent` 优先返回缓冲内容；其他面板能立即读到最新内容，不必等磁盘。
- **D-03:** 磁盘 flush 的防抖时间为 **5 秒**（最后一次写入后重新计时）。
- **D-04:** 写入后的通知合并为 **50ms** 一次；同一路径的连续写入合并成一次通知。
- **D-05:** 资源层提供 `flush(path)` / `flushAll()` / `hasPending(path)` / `pendingPaths()` 等能力（最终名称待接口计划确认）。
- **D-06:** flush 触发点：5 秒防抖到期、手动保存、切标签、关标签、页面失焦 / `visibilitychange`、释放编辑器。
- **D-07:** flush 失败时保留 pending、不清脏、显示错误；下一次触发重试，不能静默丢内容。
- **D-08:** 关闭标签时先 flush；「不保存关闭」丢弃该路径 pending；「保存并关闭」等 flush 完成后关闭；失败保持标签与面板打开。

### 表格自动保存
- **D-09:** 表格字段在 **blur 或回车确认**后写一次缓冲；不是每敲一个字符写一次。
- **D-10:** 表格继续保留组件草稿与撤销；不改成受控组件，也不把草稿搬进资源层。
- **D-11:** 表格保存按钮 = 立即 flush；「未保存」状态要同时覆盖「组件草稿脏」和「缓冲有 pending」。

### 两栏同一张表
- **D-12:** 必须允许同一张表在同一表格面板的两栏同时打开（用户需要一栏看上面、一栏看下面）。
- **D-13:** 两栏共享同一个路径缓冲；一栏确认写入后，50ms 内的合并通知让另一栏更新。
- **D-14:** 输入框里正在编辑时不会触发写入，因此不会收到更新，也不会被打断；只有 blur / 回车确认后才写、才通知。
- **D-15:** 如果两边同时确认造成不同步，按**最后写盘者胜**；同面板两栏之间不弹冲突框。
- **D-16:** 外部工具 / 另一个标签页的写入仍按现有冲突规则处理（脏则提示）；同面板两栏与外部来源要能区分。

### 等待保存提示与页面生命周期
- **D-17:** 只要任意路径有 pending，编辑器右上角显示「正在等待保存，请勿关闭页面或浏览器」。
- **D-18:** `beforeunload` 在有 pending 时返回浏览器原生确认（`preventDefault` / `returnValue`）；浏览器原生文案不可自定义。
- **D-19:** 页面失焦 / `visibilitychange` 做一次尽力 flush，降低切后台 / 关页丢失。
- **D-20:** 关闭标签的「正在保存…」复用共享 `PanelCloseDialog` 的 `saving` 态，等待 flush 完成后再关闭。

### 范围与兼容
- **D-21:** 地图 / 素材的保存时机不变（仍按各自切走 / 手动保存规则）；它们的写入也走同一缓冲，磁盘最多晚 5 秒。
- **D-22:** `04.2-21`…`04.2-24` 被本阶段取代，不再执行；`04.2-20` / `04.2-25` 的面包屑修复保留。
- **D-23:** 先接口、后实现：接口计划先定缓冲、flush、pending、通知、来源标识、生命周期与页面提示的契约；命名须先确认。
- **D-24:** 不新增运行时依赖。
- **D-25:** 同面板两栏与外部来源的区分方式（写入来源标识 / 资源层写日志）在接口计划中定；不得用不可靠的字符串比较冒充来源。

</decisions>

## Existing Code Insights

### Reusable Assets
- `ContentCache` 已有按路径的内容缓存；缓冲可以复用「路径 → 内容」的形态。
- `ResourceSystem.writeContent` / `readContent` 是所有面板写入 / 读取的单一入口，适合插入缓冲。
- `PanelCloseDialog` 已有 `saving` / `error` 展示态，可直接用于「正在保存…」。
- `EditableTable` 已在字段确认后提交；自动保存的触发点可以复用它现有的 blur / Enter 语义。

### Established Patterns
- 面板通过 `IEditorPanelContext.requestResource / listDirectory` 访问资源，不直接碰 fs。
- `onSwitchOut` 是当前唯一落盘点；B1 已让外壳在通知 React 前 await 它。
- 关闭三态由 `onRequestClose` 返回 `PanelCloseChoice`；`onDiscard` 清内存。
- 资源写入后目前不会自动通知；`updateResource` 只失效缓存并通知 hooks。
- 表格两栏各自持有目标与草稿；同一文件可以重复打开。

### Integration Points
- `editor-core`：缓冲 / flush / pending / 通知 / 来源 / 页面生命周期接口。
- `editor-core` shell：切标签、关闭、释放、`beforeunload`、右上角 pending 提示。
- `editor-impl/table`：字段确认 → `resource.write`；保存按钮 → `flush`；两栏同表同步。
- `editor-impl/map` / `asset`：保存时机不变，但写入走缓冲。
- `editor-dev`：两栏同表、切走 / blur / beforeunload 的端到端验收。

</code_context>

<specifics>
## Specific Ideas

- 防抖：磁盘 **5 秒**；通知合并 **50ms**。
- 表格写入触发：字段 **blur / 回车确认**，不是字符级。
- 右上角提示文案：**「正在等待保存，请勿关闭页面或浏览器」**。
- `beforeunload`：有 pending 时弹浏览器原生确认；文案不可自定义。
- 两栏同表：共享路径缓冲；一栏确认后另一栏立即更新；同时确认则最后写盘者胜；同面板不弹冲突。
- 地图 / 素材：保存时机不变，写入走缓冲。
- 草稿 / 撤销继续留在组件 / 面板；资源层只负责延迟写盘。

</specifics>

## 研究后补充决策（2026-10-29，用户逐条确认）

> 来源：`04.3-RESEARCH.md` 的 Open Questions O1–O5。以下为**用户拍板结果**，与 D-01…D-25 同等有效；冲突时以本节为准。

- **O1 → 以 04.3 为准：** 缓冲写入后按 D-04 做 50ms 合并通知；04.2 的 D-14「自己写完不再通知」**仅在这一条路径上被取代**，04.2 的基线比较去重逻辑继续保留（它仍然吞掉重复通知）。
- **O2 → 不新增失败文案：** flush 失败时 pending 不消失，右上角继续显示 D-17 那条固定文案；详细错误只进日志。本阶段不新增任何失败提示界面。
- **O3 → 用 `pagehide`：** D-19 的「页面失焦 / `visibilitychange`」落实为 `window` 上的 `pagehide`（可另加 `window` 的 `blur`），不使用 `document`，不破 `editor-core` 的结构门禁。
- **O4 → 数字输入框改为失焦 / 回车提交：** 不接受「逐键提交」；`NumberInput` 与文本域对齐为 blur / Enter 确认后才提交。该改动会改变既有输入体验与撤销粒度，`NumberInput` 及其既有测试纳入 W3 范围。
- **O5 → 新建立刻落盘：** `createResource` 不进缓冲；只有内容修改（`writeContent`）走 5 秒缓冲。

## 冲突处置定稿（2026-10-29，用户拍板）

> 来源：`04.3-RESEARCH.md` §Q8.5。D-16 只说「外部写入脏则提示、来源要能区分」；本节把「提示里的两个动作各做什么、什么时候弹」写死，与 D-03 / D-07 / D-08 / D-11 / D-14 / D-17 一起生效，与 D-16 冲突时以本节为准（D-16 不删，只是被细化）。

- **弹窗只有两个动作，点哪个都立刻生效**：「保存编辑器的」= 先把该栏显式放回「未落盘」→ 走同一条链把内容排进缓冲 → **立刻**把该路径待写写盘（显式覆盖外部修改）→ 待写条目与「外部已改」标记一起消失、右上角提示随之更新。旧口径「保留我的改动，下次保存覆盖」与「保留时重新写一次缓冲、等 5 秒自动落盘」都**作废**，不再作为备选。
- **「保存外部修改」** = 丢弃该路径待写（同时失效该路径内容缓存）→ 按收到变化时记下的外部原文重新载入；**不**重新读磁盘（磁盘可能已被在途写盘覆盖）。
- **没表态就不写盘**：待写条目保留、面板仍算未保存、右上角提示与 `beforeunload` 继续生效、该路径没有 5 秒自动落盘。冲突只由这两个动作结算，因此不存在「保留之后定时器装不回来」的中间态。
- **停手才弹**：用户正在某个**可编辑字段**里打字（焦点在 input / textarea / select / contenteditable 上、尚未失焦、尚未确认提交）时，冲突只记进栏状态、弹窗推迟；**失焦**或**一次确认提交**的那一刻立刻弹——数字框按回车确认后不失焦也算停手，文本域里回车是换行、不算停手；焦点在工具栏按钮或表格空白上不算「正在打字」。机制是面板视图根上的 React 焦点事件 + 一次提交回调 + 一个布尔，不碰 `document`。
- **写盘失败**：两个动作都不把异常抛给点击处理器。「保存编辑器的」任一步失败时：待写保留、弹窗不关、未保存标记仍在，失败走既有错误通道（既有文案「写入失败，请重试。」与缓冲的 `resource.flushFailed` 日志），**不新增任何失败提示界面**（O2）。
