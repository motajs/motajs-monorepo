## Decisions Made

- **写盘入口只留一条**：`IResource` 上不挂任何写盘 / 丢弃方法；面板侧走 `IEditorPanelContext.flushResource` / `IEditorPanelContext.discardPendingResource` / `IEditorPanelContext.watchPendingChange`（转发），外壳侧走 `IResourceSystem.flushAllContent` / `IResourceSystem.hasAnyPendingContent` / `IResourceSystem.listPendingPaths`（同一个缓冲）。
- **全量写盘用「全部尝试 + 抛第一条」**，不用 `Promise.all`：一条磁盘写失败不该让别的路径的改动一起卡在缓冲里；调用方（外壳 / 释放路径）自己 catch 并记 `resource.flushFailed`。
- **合并通知不新增第三条钩子**：复用 `IResourceSystemHooks.onResourceChange` 与 `IResourceSystemHooks.onUpdateResource`，只投给声明了 `IEditorPanel.onResourceChange` 的面板；地图 / 素材不退回预读通道，避免对二进制路径 `IEditorFileSystem.readFile` 产生日志噪音。
- **来源判定用方案 A（不引入来源标识）**：这不是「用字符串比较冒充来源」——比的是「这内容是不是本面板刚写出去的那一份」，不是猜「是谁写的」；同时它与 04.2 已落地的基线去重和 `04.2-19` 禁止「自写标记旁路状态」的约定同向。
- **外部写入靠「读取回落」而不是「丢掉待写」**：丢掉待写会让自动保存后已变干净的栏位静默载入外部内容、用户刚确认的改动直接消失，且「脏则提示」永远触发不了；保留待写才能让「有待写 = 未保存」在外部变化时依然成立。
- **页面事件用 `pagehide` 主接**：`document` 在两个包（含测试）被结构门禁禁；`pagehide` 是 `window` 上的等价意图。`beforeunload` 只承诺弹框，不承诺写完——这条已写进 `04.3-VALIDATION.md` 的人工验收前提。
- **50 毫秒合并取「首次排程不重置」**：与研究工作稿 §Q3.3 的伪代码相反，理由是持续写入下重排会让通知无限推迟，而通知只是同步节奏、不是落盘时机。此项已显式列为记录在案的决策。
- **四处命名差异按 PLAN 采用**：`hasAnyPendingContent` 取代研究稿的 `hasPendingContent`；待写表独立成 `WriteBuffer` 类而不是塞进 `ResourceSystem`；缓冲层六个方法名是本文新给的；面板侧与资源层刻意不同名。
