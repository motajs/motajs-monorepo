## Accomplishments

- `resource/types.ts` 新增四个契约类型：`WriteBufferWriter`（写盘回调）、`IWriteBufferEntry`（内容 / 版本号 / 定时器 / 在途写盘 / 失败原因 / 外部已改）、`IWriteBuffer`（11 个成员：排入、立刻写盘、全量写盘、查询、路径列表、取可读待写、丢弃、外部标记、清空、释放）、`PendingChangeListener`（待写路径变化回调）。
- 三处既有接口加法：`IResourceAccess` 加 `flushContent` / `discardPendingContent` / `watchPendingChange`；`IResourceSystem` 加 `flushAllContent` / `hasAnyPendingContent` / `listPendingPaths`；`IResourceSystemHooks` 加可选 `onPendingChange`。三者都写在 JSDoc 里定死：全量写盘「逐条尝试、全部试完抛第一条失败」、`readPending` 只看条目字段回退、`noteExternalWrite` 的「不丢待写 / 回声只重排定时器 / 真外部变化清定时器且不再重排」。
- `resourceSystem.ts` 用语义正确的空实现补齐六个成员：`flushContent` / `flushAllContent` 直接 resolve、`discardPendingContent` 空方法体、`watchPendingChange` 立刻用空数组回调并返回空退订、`hasAnyPendingContent` 返回假、`listPendingPaths` 返回空数组。既有 `writeContent`（仍立刻 `fs.writeFile` / `fs.writeBinary`）到 `dispose` 一字未改。
- `panel/types.ts` + `panel/panelContext.ts`：`IEditorPanelContext` 三个必选成员与 `PanelContext` 三条一行转发一一对应，转发到 `IResourceAccess` 上同名能力。
- `shell/shellSystem.ts`：`IShellViewState` / `IMenuRowProps` 各加 `hasPendingWrite`；`buildViewState` 的取值为 `this.resourceSystem.hasAnyPendingContent()`；`MenuRow` 收到的 props 多一项但返回语句逐字未变，本计划不渲染任何新元素。

## Decisions Made

- **条目三读三写**：`content` / `version` / `externallyChanged` 只读，`timer` / `inFlight` / `error` 可回写。整条替换时原样保留在途写盘与失败原因——同一路径不允许出现第二个在途写盘。
- **`noteExternalWrite` 两参数**：签名 `(path, diskContent)`。回声判定需要磁盘内容与「最近一次自己写出去的内容」比较；没有待写时直接返回。
- **空实现不碰 `this.fs`**：此刻缓冲区为空，任何写盘都是空操作；加 `notInitialized` 守卫反而会把「未初始化 flush 报错」变成假象。
- **面板成员保持必选**：不改成可选来绕过实现；`editor-impl` 的手写假上下文留给同波 Plan 03 修复。
- **外壳只显示布尔**：`hasPendingWrite` 只暴露「有没有待写」，不暴露任何路径（T-04.3-03）。

## Deviations from Plan

没有自动修复类偏差。两处「计划文字与命名文档 / 计划自带产物表不一致」按以下口径处理，并在此如实记录：

1. **`IWriteBufferEntry` 的只读范围（文档优先，已采纳）。** Task 1 的 action 文字写「六个成员，全部 `readonly`」，但同一计划的「Artifacts this phase produces」表与 `INTERFACE-NAME.md` 的全局约定 G2 都写「`content` / `version` / `externallyChanged` 只读，`timer` / `inFlight` / `error` 三个要在结算时回写」。按「命名文档是用户确认的最终契约、计划自身产物表也与之一致」取后者：三个只读、三个可变。若强行六者全只读，Plan 04 的写盘结算无法回写这三个字段。
2. **`noteExternalWrite` 的参数（名称不变，签名按 Plan 02/04 采用）。** `INTERFACE-NAME.md` 的 Plan 02 表把 `WriteBuffer.noteExternalWrite` 记为 `(path: string) => void`，而 Plan 02 的 action 与 Plan 04 的具体用法（`buffer.noteExternalWrite(路径, 'external')`、`ResourceSystem.noteExternalWrite` 裸读磁盘后传入内容）都需要第二个 `diskContent` 参数，否则回声判定无从比较。名字 `noteExternalWrite` 完全未变，仅补足必要入参；这里按计划与下游用法实现，并登记此差异。

**计划内已知的跨包影响（未修，按计划留给 Plan 03）：** `IEditorPanelContext` 加三个必选成员后，`editor-impl` 里唯一手写的假上下文（`src/explorer/__tests__/explorerPanel.test.tsx` 的 `createContext`）会缺成员，使 `editor-impl` 的 typecheck 变红。本计划 verify 只跑 `editor-core`，该红由同波 Plan 03 修复；没有为了让 typecheck 变绿把新成员改成可选。

**Impact:** 无行为改动；两处差异只影响类型形状与注释口径，不影响任何运行时路径。
