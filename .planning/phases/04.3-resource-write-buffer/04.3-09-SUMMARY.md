# Phase 04.3 Plan 09: 数字输入改为确认后提交 Summary

**数字输入框不再每敲一个键就改一次数据：打字时内容只留在框里，失焦、按回车或把值清空才提交一次；schema 视图里成对的最小 / 最大值框也换成同一个控件，因此整张表都按「一次确认 = 一次写入」工作。**

## Accomplishments

- `NumberInput` 改成「本地草稿 + 确认提交」：`onChange` 只更新草稿，不再逐键调 `props.onChange`；失焦、回车、清空各提交一次；Escape 放弃本次输入并把显示回落到当前值。`INumberInputProps` 的 `value` / `onChange` / `disabled` 三个成员逐字未变，`TableRow` 的调用点无需改动。
- 回车提交后**不失焦**：实现里没有 `blur` / `event.currentTarget.blur()`，提交是同步一次的 `void` 回调。这条是 Plan 08 的前提——冲突弹窗的推迟要靠「一次确认提交」在 `TablePanel.applyEdit` 里解除，而数字框回车后不会失焦，只靠失焦事件永远等不到「停手」。

## Decisions Made

- **用 `editing` 布尔而不是把 `props.value` 复制回草稿。** 提交时只关编辑态，显示自动回落到当前值；上层接受后新值经 `props.value` 的效果回到草稿，被拒时也不会把非法值留在框里。`TextareaInput` 用「解析失败就 `setText(toText(props.value))`」，数字控件没有可解析失败的文本，等价做法就是切换显示来源。
- **清空即提交。** antd 的数字框只有在文本真正为空时才回调 `null`（输入到一半的 `-` 不会回调），所以可以直接把 `null` 当作「清空确认」提交一次，同时让草稿显示为空。
- **回车不 blur。** 计划与 `INTERFACE-NAME.md` 都写死了这条：回车后仍聚焦，提交经 `props.onChange` 让面板把「正在输入」解除，弹窗随即弹出；补一次 blur 会退化成失焦用例，也让 Plan 08 的 (f) 失去前提。
- **成对框复用控件而不是复制逻辑。** 只换控件、不动行结构与选择器，schema 视图与普通视图因此共用同一套提交语义。

**2. 「清空提交」被拒后的回填发生在下一次失焦，而不是清空那一刻。**
- **Found during:** Task 2
- **Issue:** 清空时控件立刻提交 `null`，但这时用户仍在输入框里。若上层 schema 不允许 `null`（普通 `type: number` 就是如此），`props.value` 不会变；如果当场把显示切回当前值，用户刚清空的框会立刻弹回旧数字，等于清空动作被吞掉。
- **Fix:** 清空后保持编辑态（框里显示为空），提交照常发生；等这次输入结束（失焦，或上层接受后 `props.value` 变化触发回填）才把显示恢复到真实值。这样「清空即提交」的契约成立，且被拒时不会在输入中途抢改用户正在编辑的内容。
- **Files modified:** `packages/libs/editor-impl/src/shared/schemaForm/components/inputs/NumberInput.tsx`
- **Verification:** typecheck exit 0；三条数字字段用例绿；`schemaMode` / `behaviour.uat` 合并 20 例绿。
- **Committed in:** `b5e9bce`

**3. 成对用例里第二次派发同一个值不会再触发 antd 的 onChange。**
- **Found during:** Task 3
- **Issue:** 用例先 `change('5')`（只改不提交），再 `change('5') + blur`。第二次 change 的值与控件当前值相同，antd（rc-input-number）按「相等就不再回调」跳过，`onChange` 不会第二次触发。
- **Fix:** 不需要处理——草稿第一次就已经是 `5`，blur 走的是 `confirm()` 而不是依赖第二次 change；用例照常证明「失焦才提交」。
- **Files modified:** `packages/libs/editor-impl/src/table/__tests__/schemaMode.test.tsx`
- **Verification:** 该用例绿，且断言失焦前后 `minimum` 从 0 变 5、`maximum` 从 100 变 50。
- **Committed in:** `5d8000f`
