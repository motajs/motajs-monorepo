# Phase 04.3 Plan 04: 资源写缓冲本体与读写穿透 Summary

**写入不再直接碰磁盘：内容先进按路径的待写表，别的面板立刻读得到，5 秒防抖后才落盘；外部改动不会被还没落盘的内容挡住，释放编辑器前会先把所有待写写进磁盘**

## Accomplishments

- 新增 `writeBuffer.ts`：`WriteBuffer implements IWriteBuffer` 持有「路径 → 待写条目」表、自增版本号、写盘回调与待写变化回调；模块级只有数字字面量 `FLUSH_DEBOUNCE_MS = 5000` 与裸函数 `isSameResourceContent`，所有 `Map` 都是实例字段。缓冲不设上限、不做淘汰，成功写盘或丢弃才删条目。
- `ResourceSystem.writeContent` 改成「排入缓冲 + `cache.set`」，不再 `await` 写盘；`readContent` / `readBinary` 在内容缓存之前先查缓冲，`readBinary` 只在缓冲为 `Uint8Array` 时命中。`flushContent`、`hasAnyPendingContent`、`listPendingPaths` 全部接上真实缓冲。
- 5 秒防抖每次写入重新计时；立刻写盘可 `await`、无待写时幂等、同一路径并发复用同一在途写盘；写盘期间又写入时靠版本号保留待写并重排定时器；写盘失败保留待写并把错误抛给有上下文的调用方，定时器路径只记日志。
- 「外部已改」做成条目字段 `externallyChanged`：外部变化到达时整条替换条目、保留内容/版本号/在途写盘/失败原因、清掉定时器且不再自动落盘，读取回落到磁盘；自己写盘的回声（磁盘内容等于 `lastWritten`）不置标记，只重排一次定时器。再写入、成功写盘、丢弃三条路径都会让该路径重新可读。
- 删除资源丢弃该路径待写（否则 5 秒后文件复活），移动资源丢弃源路径待写，二者都记 `resource.pendingDiscarded`；`dispose` 先全量写盘（失败只记 `resource.flushFailed`），再清缓冲、退订、清索引、清缓存、清 `fs` 引用。
- 既有「保存后立刻读磁盘」断言全部迁移：`resourceSystem.test.ts` 的文本 / 二进制两处改成「读缓冲是新值 + 显式写盘后磁盘才更新」，`tracer.test.ts` 在读裸 fs 前补一次 `flushAllContent`；`externalChange.test.tsx` 的回声用例改成「点保存 → 显式写盘 → 回送变化」，并新增「有待写时外部改文件不被缓冲遮蔽」红例。

## Decisions Made

- **缓冲不复用 `ContentCache`**：内容缓存对单条超过 8 MiB 的内容直接不入（`contentCache.ts:51-52`），复用它会让大地图 / 大素材静默读回旧值。缓冲是独立的、无上限的 `Map`。
- **版本号而不是引用比较**：`ResourceContent` 的 `!==` 对 `Uint8Array` 是引用比较；整条替换条目时由自增版本号判「写盘期间又写过」。
- **`watchPendingChange` 用实例 Set**：`addHook` 只接受 `Partial<IResourceSystemHooks>`，没有携带路径列表的钩子；因此监听者放在实例 `Set` 里，返回删除函数；`onPendingChange` 钩子仍只在「有没有待写」变化时通知一次（用 `pendingNotified` 布尔）。
- **外部变化用裸读磁盘**：`ResourceSystem.noteExternalWrite` 按待写内容类型走 `fs.readFile` / `fs.readBinary`，绝不走 `readContent`（它会先命中缓冲，等于自己跟自己比）。
- **`createResource` / `deleteResource` / `moveResource` 不缓冲**：新建立刻落盘避免索引与磁盘不一致；删除 / 移动丢弃该路径待写，避免 5 秒后复活。
