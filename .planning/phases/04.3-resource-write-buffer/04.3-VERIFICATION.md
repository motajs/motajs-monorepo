## 四、偏差与缺口

### G1（阻断，判据 4 / D-08）素材面板「保存并关闭」磁盘失败仍关标签

**现象：** 素材面板的保存只把内容写进缓冲（`assetPanel.ts:1716-1733` 的 `saveAll` → `1781-1804` 的 `writeCategory` → `resource.write`），面板层因此必然结算为 `Save`。外壳拿到 `Save` 后调 `flushPendingContent()`（`shellSystem.ts:840`），该函数把失败吞成 `resource.flushFailed` 日志（`1163-1169`），随后无条件 `discardTab`（`842`）。结果：磁盘写失败时素材标签仍然关闭，待写留在缓冲里，用户看不到任何失败提示。

**对照契约：** D-08「保存并关闭 …… 失败保持标签与面板打开」、ROADMAP 判据 4「失败保持打开」。表格面板满足（`closeChoice.test.tsx:310-350` 断言标签仍在、弹窗仍在、显示「写入失败」），素材不满足。

**影响：** 数据本身不丢（待写保留，下一次 flush 触发时重试），但「失败保持打开」这条明确承诺没有兑现；并且这是相对 04.2 的行为回退（04.2 的素材保存直接写盘，失败会结算 `Cancel`）。

**记录状态：** `04.3-11-SUMMARY.md:156-158` 与 `204-205` 已如实写下「与 D-08 字面不一致，需人工确认」，但代码未改。本报告按契约判为缺口，而非「已知可接受」。

### G2（阻断，冲突处置定稿 / D-15 / D-07）未表态的外部冲突会被生命周期 flush 覆盖

**现象：** 外部变化到达时，`WriteBuffer.noteExternalWrite` 把条目标成「外部已改」、清掉 5 秒定时器（`writeBuffer.ts:128-152`），读取回落到磁盘、定时器不再自动写盘——这一半是对的。但：

1. `WriteBuffer.flush(path)` 不检查 `externallyChanged`，照样把条目内容交给 writer（`writeBuffer.ts:68-80`、`172-223`）；`flushAll()` 逐条调用它（`82-99`）。
2. `ResourceSystem.flushAllContent()` 直接委托 `buffer.flushAll()`（`resourceSystem.ts:220-222`）。
3. 外壳在**窗口失焦**、`pagehide`、`beforeunload`、切标签、关标签、释放时都调用它（`shellSystem.ts:518-536`、`1145-1169`）。
4. 表格面板自己的 `onSwitchOut` 也会 `saveColumn` → `saveDocument` 的非安静分支按本栏两条路径无条件 `flushResource`（`tablePanel.ts:1008-1017`、`1582-1589`），完全不看 `pendingConflict`。

**可复现路径（代码级）：** 表格里改一格 → 外部工具改同一文件 → 弹窗出现、磁盘仍是外部内容（`externalChange.test.tsx:346-359` 到这里都成立）→ 用户切到外部编辑器去核对（窗口失焦）→ `window blur` → `flushAllContent` → 缓冲里带标记的那一条被写出去 → 外部修改被编辑器内容覆盖。整个过程中用户没有点过弹窗上的任何一个动作。

**对照契约：** 冲突处置定稿「没表态就不写盘：待写条目保留、面板仍算未保存、右上角提示与 `beforeunload` 继续生效、该路径没有 5 秒自动落盘。冲突只由这两个动作结算」。当前实现只做到「没有 5 秒自动落盘」，「冲突只由这两个动作结算」不成立。

**影响：** 外部那一份被静默丢弃；用户在「文件已被外部修改」的提示下最自然的动作（切窗口核对）恰好触发覆盖。现有 `externalChange.test.tsx` 只在冲突刚记录时断言磁盘，没有在失焦 / 切标签 / 关页后复查，所以 1172 条全绿也不能证明这条契约成立。

**建议修复（先红后绿）：**
1. `flushAll` / 生命周期写盘跳过 `externallyChanged === true` 的条目（单路径的 `flushContent` 仍可覆盖标记——「保存编辑器的」正是先 `schedule` 清标记再 `flushResource`，不受影响）。
2. `TablePanel.saveDocument` 的非安静分支在该栏 `pendingConflict !== undefined` 时不得 flush 该路径。
3. 新增用例：记录冲突 → 派发 `window blur`（以及切标签）→ 断言磁盘仍等于外部原文、待写与冲突仍在。
