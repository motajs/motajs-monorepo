    - **表格侧——不变量写在唯一入口，不是两个调用点：** `TablePanel.saveDocument` 在取到 `target` 之后、拍 `startVersion` / `wroteData` 之前，对 `column.pendingConflict !== undefined` 一律返回 `ContentSaveStatus.Saved`，**不区分 `quiet`**。于是撤销 / 重做（`TablePanel.applyUndoRedo` 调 `TablePanel.saveDocument(..., true)`）、字段确认自动保存（`TablePanel.saveAfterEdit`）、切走、保存按钮、保存并关闭都走同一条守卫。**唯一豁免**是 `TablePanel.keepExternalConflict`：它先把该栏的冲突标记取下，再走同一条保存链（`schedule` 因此重建条目并把标记清假），最后只对真正有待写的路径各 flush 一次（未编辑的兄弟路径不写盘）。
    - **为什么不能只挡「最后的 flush」：** `persist` 走的是 `IResource.write` → `WriteBuffer.schedule`，会把条目整条替换、标记自然清假并重排定时器；只在最后不 flush 仍会在 5 秒后被定时器写出去。因此必须在 persist 之前就停手，自动保存与撤销这类安静路径同样如此。
    - **一栏两条路径必须能一起结算，但只结算真正有待写的那一条：** 一栏的数据文件与由它推导出的 schema 文件可以同时有待写（`TablePanel.computeAdd` 同时置 `unsaved` 与 `unsavedSchema`），而冲突槽只有一个、一次只弹一个框。因此两个动作动手前先取一帧「当前待写路径」（冲突路径本身视为待写），只对这一集合结算：「保存编辑器的」= 取下标记 → 把集合里的路径放回未落盘 → 走同一条链排缓冲 → 这些路径各 flush 一次；「保存外部修改」= 集合里的路径各丢弃一次待写 → 头部那条用收到变化时记下的外部原文、另一条重读磁盘，都换回外部内容。**从未编辑过的兄弟路径既不 persist 也不 flush**（`IWriteBuffer.flush` 对没有待写的路径本就只是空操作，但写这条规则是为了不把它顺带 persist 一次）。一次结算把这一栏真正脏的路径都结掉，因此不存在「没有出口」的标记；不新增名字、不引入冲突队列。
    - **切回时不得把草稿换成外部那一份：** `TablePanel.refresh`（以及所有转调它的刷新入口）在该栏 `pendingConflict !== undefined` 或 `pendingWrite` 为真时必须提前返回，不重读磁盘。原因很直接：冲突未表态时磁盘上正是外部那一份，重读会把内存草稿换成它，随后「保存编辑器的」写回去的就是外部内容——冲突弹窗两个动作也就失去了意义。这条规则不新增名字，只是给既有早退条件补两个判据。
    - **与「单路径仍可写」的关系：** 不改成「`flush` 也跳过」，因为「保存编辑器的」正是「用户明确选择覆盖外部修改」的唯一出口；它点下去就应立刻写盘。它先经 `TablePanel.saveDocument` 的安静分支 `schedule`（标记清假），再 `IEditorPanelContext.flushResource`，所以即使 `flush` 允许写标记条目，也不会出现「没表态就写盘」。
