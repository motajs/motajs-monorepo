# Phase 05.3 Plan 10: 实现与风格修正 + 基础设施 Summary

**把 TypeScript 升到 6.0.3 并给单测加 Map.getOrInsert 垫片，用 getOrInsertComputed 收敛资源缓存、合并 EditorPanelHooks、落地集中消息表与按 id 查表的 logger 单例，并让面板重复 id 只记日志并返回 null**

## Accomplishments

- TypeScript catalog `^5.9.3 → ^6.0.3` 经本地代理安装；lockfile 更新、`node_modules/typescript` 为 6.0.3；TS6 的 `lib.esnext.collection` 提供 `Map.getOrInsert` / `getOrInsertComputed` 声明。
- 新增 `packages/libs/editor-core/src/test/mapPolyfill.ts`：仅在缺失时给 `Map.prototype` 装 `getOrInsert` / `getOrInsertComputed`；经 `vitest.config.ts` 的 `setupFiles` 只加载到测试进程，生产构建不加载。无文件头注释。
- `resourceSystem.ts` 三处手写「get + if + set」默认值缓存全部改为 `this.contentCache.getOrInsertComputed(id.type, () => new Map())`；`readContent` 的可选链判空拆成嵌套 `if`；`Resource.request/write` 与 `PanelContext` 四个转发方法去掉无谓 `async`，直接 `return` promise。
- `EditorPanelHooks` 类整段移入 `panelSystem.ts` 末尾，删除 `editorPanelHooks.ts` 及其桶导出行。
- 新增 `log/messages.ts`（`Object.freeze` 的 id → 英文模板表）与 `log/logger.ts`（`class Logger implements ILogger` + `export const logger: ILogger = new Logger(messages)`），`log/index.ts` 追加两行 `export *`。
- `PanelSystem.registerPanel` 重复 id 改为 `logger.error('panel.duplicateId', panel.id)` 后 `return null`（返回类型 `Promise<IEditorPanel | null>`），不再抛错；全文件已无 `throw new Error`。
- 显式类型与 S5/S8/R1：`initialized: boolean`、`maxUndoStep: number`；`PanelSystem` 私有箭头成员（`subscribe`/`getSnapshot`/`RootComponent`/`handleFocus`/`handleBlur`）只声明类型并在构造器内赋值；三个模块内接口前的单行 `//` 删除并给成员补单行 jsDoc，`internalSwitchTo` 改多行 jsDoc；`EditorCore.initialize` 用 `const arr` 再 `Promise.all`。
- 测试更新：`panelSystem.test.ts` 重复 id 用例改为断言返回 `null`、不抛错、且 `logger.error` 以 `('panel.duplicateId', 'dup')` 被调用。

## Decisions Made

- 空 Map 默认值属 `getOrInsertComputed` 场景（未命中才 `new`），故三处统一用 `getOrInsertComputed`；`deleteResource` / `updateResource` 的 `this.contentCache.get(id.type)?.delete(...)` 是副作用调用，保留 `?.`。
- `messages` 用 `Object.freeze` 包裹而非裸对象字面量，满足 editor-core 模块级可变容器门禁（`coreModuleState` 的 sanctioned remedy）。
- 重复面板 id：`logger.error('panel.duplicateId', panel.id)`、不写入注册表、`return null`，不抛错。

- **Found during:** 计划级 `<verification>`
- **Issue:** 计划要求全量 `pnpm typecheck` 退码 0。实测退码 1，原因两类：
  - **既有红（与本次改动无关，D-43 允许）**：`@motajs/editor` 因 `@motajs/editor-impl` 仍是空壳，源码里 66 处 `TS2305`（模块无导出成员）等错误。对同源分别用 TS 5.9.3 与 TS 6.0.3 编译均为红，证明与本计划无关。
  - **TS 6.0 的两处破坏性变更（本计划引入 TS6 后新出现）**：
    1. `baseUrl` 由“弃用警告”升级为**硬错误** `TS5101`（`packages/apps/editor/tsconfig.app.json` 使用了 `baseUrl`），`tsc -b` 在配置阶段即失败。
    2. TS 6.0 **不再自动包含 `@types` 全局类型包**：`packages/apps/service-worker`（TS5 下退码 0、绿）在 TS6 下因 `node` / `serviceworker` / `wicg-file-system-access` 全局类型缺失而报错（`Buffer`、`ServiceWorkerGlobalScope`、`FileSystemDirectoryHandle#requestPermission` 等）。显式传入 `--types node,serviceworker,wicg-file-system-access` 后即退码 0，确认是自动包含行为变化。
- **Why not auto-fixed:** 修复需要改各包 tsconfig（service-worker 的 app/server 两个 tsconfig 补 `types`；editor 的 tsconfig 补 `ignoreDeprecations: "6.0"` 或去掉 `baseUrl`）——属于计划明确要求“不得擅自改动共享/包配置、须先上报”的范畴；且编辑器既有红（D-43）使“全量 typecheck 全绿”在本阶段本就不可能达成。
- **Suggested follow-up（待用户决定）:** 为 TS6 迁移单独排一个小计划：`service-worker` tsconfig.app.json / tsconfig.server.json 显式列 `types`；带 `baseUrl` 的 tsconfig 补 `ignoreDeprecations: "6.0"`；编辑器红留待 editor-impl 落地后消除。
- **Committed in:** 无（未改动配置）

**3. [Note] `getOrInsert` 与 `getOrInsertComputed` 的出现次数**
- 计划验收写“`Map.getOrInsert` / `Map.getOrInsertComputed` 在 `resourceSystem.ts` 中至少各出现一次”。按 Task 2 的 S2 明确指令，三处默认值（默认值均为 `new Map()`）统一用 `getOrInsertComputed`，故源码中只有 `getOrInsertComputed`（3 次），无裸 `getOrInsert`——空 Map 属惰性计算场景，用 `getOrInsert` 会在命中时也白建 Map。`getOrInsert` 的类型与运行时垫片均已提供，只是该文件用不到。
