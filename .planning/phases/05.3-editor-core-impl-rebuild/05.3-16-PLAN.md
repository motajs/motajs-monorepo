<objective>
把原计划 05.3-17（面板）与 05.3-18（核心）合并为一个计划，修复评审确认的面板系统与组合根缺陷：`PanelSystem.dispose()` 不复位 `initialized` / `currentParam` 造成释放后半可用（WR-05）；重复 id 注册时已创建的面板被丢弃且不释放（WR-07）；`switchTo` 不校验面板是否已注册（WR-08）；`onFocus` / `onBlur` 的 Promise 失败被 `void` 丢弃（WR-06）；以及 `EditorCore` 版本号与 `package.json` 不一致、`initialize` 无幂等 / 释放后契约（IN-02）。

Purpose: 让面板系统在释放 / 重入、重复注册、非法切换与窗口焦点回调失败等边界下行为一致、无泄漏、可排查；让组合根的生活周期有明确、可验证的契约并让包版本与对外 `version` 一致（D-09 / D-12 / D-14 / D-26 / D-28 / D-30 / D-39）。

说人话：① 面板系统被「关掉」后没把内部状态复位，再注册时以为自己还开着、但窗口焦点又收不到；正确做法是关掉时把所有状态清干净，而且重复初始化不再重复挂监听。② 重复 id 注册时，已经建好的面板被直接丢掉、从不释放；正确做法是丢掉前先释放它。③ 切换面板时不检查这个面板是不是系统注册过的；没注册就拒绝切换。④ 窗口进 / 出时调面板回调，回调报错会被无声吞掉；正确做法是捕获并记日志。⑤ `EditorCore` 对外报的版本号（0.1.0）和包自己的版本号（0.0.0）对不上，得统一；而且现在重复「初始化」会重复注入、被「关掉」之后还能再初始化，正确做法是只认第一次初始化、关掉之后拒绝再初始化。

Output: 状态复位 + 幂等重入 + 重复释放的 `panelSystem.ts`、`switchTo` 校验与焦点回调兜底的同一文件、带生活周期守卫的 `core.ts`、新增四条消息的 `messages.ts`、对齐到 `0.1.0` 的 `package.json`，以及覆盖各场景的测试与 `05.3-INTERFACE-NAME.md` 的命名记录。

⚠️ 只动本计划列出的文件；不改公共接口 `panel/types.ts` 与三个系统的接口文件；不重做 05.3-13 / 05.3-14 已完成的工作。新日志 id `'panel.callbackFailed'` / `'panel.notRegistered'` / `'core.duplicateInitialize'` / `'core.initializeAfterDispose'` 与 `EditorCore` 私有成员名 `initialized` / `disposed` 为**提案，需用户确认**后才可写入代码。不改 `hook/` 的接口与实现（用户已判定 WR-01 / WR-02 / IN-01 不是问题）。若发现必须改行为或扩大公共接口才能修好，先停下汇报（D-34）。
