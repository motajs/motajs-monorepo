<objective>
修复评审确认的资源系统两处缺陷：`dispose()` 只清缓存、不清 `injection`，释放后仍调用后端（WR-04），且 `core.test.ts` 把该泄漏固化成期望；以及资源钩子派发不做错误隔离，一个坏钩子的异常会中断其余钩子与整个更新流程（WR-09）。

Purpose: 让释放后的资源系统真正不可用（命中既有未初始化守卫），并让资源更新广播对单个监听者的失败免疫（D-09 / D-20 / D-36 / D-37 / D-39）。

说人话：① 资源系统被「关掉」以后，现在还会偷偷去问后端要数据；正确做法是关掉就把后端引用也清掉，之后所有请求都走「没初始化」那条路、返回空值。② 广播资源更新时，只要有一个面板的回调报错，后面的面板就收不到通知；正确做法是每个监听者单独兜底，一个坏了不影响其他。

Output: 释放后真正不可用的 `resourceSystem.ts`、隔离钩子派发的同一文件、新增 `resource.hookFailed` 消息的 `messages.ts`、以及改正泄漏断言的两个测试文件与命名记录。

⚠️ 只动本计划列出的文件；**不重做** 05.3-13 / 05.3-14 已完成的接口加宽与空守卫。新日志 id `'resource.hookFailed'` 为**提案，需用户确认**后才可写入代码。不改 `hook/` 的接口与实现（WR-01 / WR-02 / IN-01 用户已判定不是问题）。若发现必须改行为或扩大公共接口才能修好，先停下汇报（D-34）。
