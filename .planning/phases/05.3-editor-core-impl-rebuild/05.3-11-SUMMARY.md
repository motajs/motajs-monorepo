# Phase 05.3 Plan 11: TS6 迁移配置修正 Summary

**删掉编辑器 tsconfig 里 TS6 已不认的 baseUrl、并给 service-worker 两个 tsconfig 点名各自需要的全局类型包，让 TS6 升级带来的新报错清零，并用双版本编译器对比证明编辑器剩下的红是升级前就有的**

## Performance

- **Duration:** 12 min
- **Started:** 2026-10-05T18:46:45Z
- **Completed:** 2026-10-05T18:58:00Z
- **Tasks:** 3（2 个改动任务 + 1 个只读审计任务）
- **Files modified:** 3

## Accomplishments

- 编辑器 `tsconfig.app.json` 删除了 TS6 已升级为硬错误（`TS5101`）的 `baseUrl` 一行；`paths` 的值本来就是 `./src/*` 这类相对路径，没有 `baseUrl` 时按 tsconfig 所在目录解析，别名继续指向原处。
- service-worker 两个 tsconfig 各自显式列 `types`：浏览器端那份只列 `wicg-file-system-access`；Node + Service Worker 那份列 `node`、`serviceworker`、`wicg-file-system-access`。TS6 起 `types` 缺省为空、不再自动包含 `node_modules/@types`，所以必须点名。
- 编辑器 TS6 迁移残余红（350 条）经与 TS 5.9.3 对比，归一化后 TS6 集合是 TS5.9 集合的子集、无新增；唯一差异是 TS5.9 缺 `Map.getOrInsertComputed` 声明而多报的 3 条（TS6 反而修好）。本计划只改配置，不碰编辑器源码与空的 `editor-impl`。

## Files Created/Modified

- `packages/apps/editor/tsconfig.app.json` — 删除 `"baseUrl": ".",` 一行，其余（`paths`、注释、各开关）一字未动
- `packages/apps/service-worker/tsconfig.app.json` — 新增 `"compilerOptions": { "types": ["wicg-file-system-access"] }`

## Decisions Made

- 删 `baseUrl` 而不是加 `ignoreDeprecations: "6.0"` 压制：`baseUrl` 在 TS7 会彻底失效，压制只是把问题留到以后。
- `types` 放各包 tsconfig、不放共享 `@motajs/config` 基底：`types` 是「整程序加载哪些全局类型包」的开关，基底被 editor 与多个包共用，放 `node` / `serviceworker` 会把 Node 与 Service Worker 全局污染进浏览器包和纯 lib 包，且基底里没有任何一份列表能同时满足 app（仅 wicg）与 server（node+sw+wicg）两种需求。

### ② 既有红（D-43 允许，未修）

编辑器 `packages/apps/editor/tsconfig.app.json` 在 TS6 下共 350 条错误，全部为 `@motajs/editor-impl` 仍是空壳所致，逐类如下：
