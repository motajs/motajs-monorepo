## Plan 05.3-02 — 接口补齐（实现层接口定义，纯声明）

- **`dispose()`**（方法，D-39）：给 `IUndoSystem` 与 `IResourceSystem` 各补一个 `dispose()`——撤销系统清空历史栈、资源系统清空缓存；返回类型提案为 `void`（面板系统的 `IPanelSystem.dispose()` 仍为 `Promise<void>`）。
- **`IResourceAccess`**（接口，模块内非导出到包根，D-35）：面板侧的四个资源读写口子 `requestResource` / `requestResourceList` / `createResource` / `deleteResource`；由 `ResourceSystem` 实现，供 `PanelContext` 使用。外部拿到的 `IResourceSystem` 不含这些方法。文件：`resource/access.ts`。
- **`IResourceStore`**（接口，模块内非导出到包根）：`Resource`（资源句柄）与 `ResourceSystem`（缓存实现）之间的**窄接缝**，只有 `readContent` / `writeContent` 两个方法。用途是让 `Resource` 只依赖这个接缝、不依赖 `ResourceSystem` 类，从而避免 `resource.ts ↔ resourceSystem.ts` 循环 import（no-circular 门禁）。文件：`resource/store.ts`。
- **`PanelUndoType`**（`const enum`，数字）：面板系统自己的撤回操作类型；目前只有成员 `Switch`（面板切换），作为 `IUndoContext.type` 取值。落点：**写入 `panel/types.ts`**（不单独开文件），随 `panel/index.ts` 的 `export * from './types'` 自然经桶导出。（用户 2026-10-04 明确要求。）

## Plan 05.3-03 — 构建/测试前提

- 本计划不引入领域命名；改动的是依赖版本/新增测试 devDependencies（`react` / `@types/react` 改 catalog、新增 `react-dom` / `@types/react-dom` / `@testing-library/react`），以及一个基础设施冒烟测试文件。

## Plan 05.3-04 — 撤销系统

- **`UndoSystem`**（类）：实现 `IUndoSystem` 的默认撤销系统——持有撤销/重做历史，受 `maxUndoStep` 限制，`undo()` / `redo()` 调用记录对象的 `IUndoable.undo/redo`，`dispose()` 清空两栈。
- **`UndoEntry`**（接口，模块内非导出）：撤销历史里的一条记录，保存「可撤回对象 + 撤回上下文」。
- 私有成员：`undoStack` / `redoStack`（内部历史栈）。

## Plan 05.3-05 — 资源系统

- **`ResourceSystem`**（类）：实现 `IResourceSystem`、`IResourceAccess`、`IResourceStore`，并 `extends Hookable<IResourceSystemHooks>`；负责资源列表缓存、内容缓存、读写、创建/删除、`updateResource` / `updateResourceList`（作废缓存 + 触发钩子）。
- **`Resource`**（类）：实现 `IResource<T>` 的资源句柄，持标识符与 `IResourceStore` 引用，`request()` 读缓存/后端、`write()` 写后端并更新缓存。
- 私有成员：`listCache` / `contentCache` / `injection`（内部缓存与后端引用）。

## Plan 05.3-06 — 面板系统

- **`PanelSystem`**（类）：实现 `IPanelSystem`；管理面板注册（id 唯一）、生命周期、切换（公共 `switchTo` 记录撤回、内部 `internalSwitchTo` 不记录）、`getPanel`、`render`、`dispose`；为每个面板挂资源更新钩子。
- **`PanelContext`**（类）：实现 `IEditorPanelContext`；转调资源读写（`IResourceAccess`）与撤回系统。
- **`EditorPanelHooks`**（类）：实现 `IResourceSystemHooks`；面板的资源更新钩子，构造时传入该面板的 `IEditorPanel` 与 `IEditorPanelContext`，`onUpdateResource` / `onUpdateResourceList` 触发时经 context 重新申请资源并通知对应面板。

## Plan 05.3-07 — EditorCore 组装与导出

- **`EditorCore`**（类）：实现 `IEditorCore`；构造器内 new `UndoSystem` / `ResourceSystem` / `PanelSystem` 并接线；`initialize(injection)` 分发给三个系统；`dispose()` 逆序释放；`version`。
- **不设版本常量**：`IEditorCore.version` 直接取字面量 `'0.1.0'`（用户 2026-10-04 决定，无需 `EDITOR_CORE_VERSION`）。
- 包根 `src/index.ts` 的公开导出（新增导出行，不改已有内容）。

## Plan 05.3-08 — 门禁迁移

## Plan 05.3-09 — 接口修正（接口/类型定义，含必要的机械跟随）

- **`IResourceSystemAccess`**（接口，`resource/types.ts`，经桶导出）：`ResourceSystem` 的完整能力接口——在公开的 `IResourceSystem` 之上补齐资源读写能力，`extends IResourceSystem, IResourceAccess, IResourceStore`。由 `ResourceSystem` 实现；`PanelSystem` / `EditorCore` 内部以该类型持有资源系统，对外仍只暴露 `IResourceSystem`。参考 `../template` 中 `IResizableMapLayer` 的做法（能力接口继承公开接口，公开接口不含该能力）。
- **`IResourceAccess`**（接口，`resource/types.ts`，经桶导出）：面板侧四个资源读写方法（request / list / create / delete）。原定义在 `resource/access.ts`，移入 `types.ts`。
- **`IResourceStore`**（接口，`resource/types.ts`，经桶导出）：资源句柄 `Resource` 与资源系统之间的窄接缝（`readContent` / `writeContent`）。原定义在 `resource/store.ts`，移入 `types.ts`。
- **`dispose()` 返回类型统一**：`IUndoSystem`、`IResourceSystem` 的 `dispose()` 由 `void` 改为 `Promise<void>`。

## Plan 05.3-10 — 实现与风格修正 + 基础设施

- **`ILogger`**（接口，`log/types.ts`，经桶导出；**定义在 05.3-09**）：日志接口，方法 `error(id: string, ...params: string[])` / `warn(id: string, ...params: string[])`。id 为集中消息表的键，params 按顺序替换模板里的 `$1` / `$2`；日志 id 与消息内容为英文，jsDoc 文字为中文。
- **`LogMessages`**（类型别名，`log/types.ts`，经桶导出；**定义在 05.3-09**）：集中消息表类型 `Readonly<Record<string, string>>`（id → 英文模板）。
- **`messages`**（`log/messages.ts`，经桶导出）：集中的 `id → 英文模板` 表。
- **`logger`**（`export const logger: ILogger = new Logger(messages)`，`log/logger.ts`，经桶导出）：模块级单例，按 id 查表、替换参数、console 输出。
