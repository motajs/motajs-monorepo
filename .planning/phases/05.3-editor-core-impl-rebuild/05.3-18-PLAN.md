<objective>
修复评审确认的 `EditorCore` 交付语义问题：版本号与 `package.json` 不一致（`0.1.0` vs `0.0.0`），且 `initialize` 无幂等 / 释放后契约——重复调用会重复下发注入，`dispose` 之后仍可再次 `initialize`（IN-02）。

Purpose: 让组合根的生活周期有明确、可验证的契约——只初始化一次、释放后不可再初始化，并让包版本与对外 `version` 一致（D-12 / D-14 / D-39）。

说人话：① `EditorCore` 对外报的版本号（0.1.0）和包自己的版本号（0.0.0）对不上，得统一。② 现在重复调用「初始化」会重复注入，被「关掉」之后也还能再初始化；正确做法是只认第一次初始化、关掉之后拒绝再初始化。

Output: 带生活周期守卫的 `core.ts`、新增两条消息的 `messages.ts`、对齐到 `0.1.0` 的 `package.json`、覆盖幂等与释放后拒绝的 `core.test.ts` 与命名记录。

⚠️ 只动本计划列出的文件；不改三个系统的接口（`undo/types.ts` / `resource/types.ts` / `panel/types.ts`）；不重做 05.3-13 / 05.3-14 已完成的工作。新日志 id `'core.duplicateInitialize'` / `'core.initializeAfterDispose'` 与 `EditorCore` 私有成员名 `initialized` / `disposed` 为**提案，需用户确认**后才可写入代码。若发现必须改行为或扩大公共接口才能修好，先停下汇报（D-34）。
</objective>
