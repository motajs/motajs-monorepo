<objective>
修复评审确认的两处撤销系统缺陷：`undo` / `redo` 先出栈再 `await` 导致操作抛错时该条历史从两栈同时丢失（WR-03）；以及 `maxUndoStep <= 0` 被静默当成「无上限」，应改为「禁用撤销」（IN-04）。

Purpose: 让撤销历史在操作失败时仍可重试，并让撤销步数的边界语义与调用方预期一致（D-31 / D-33）。

说人话：现在点「撤销」时，系统先把这条历史扔掉了再执行撤销，一旦撤销过程报错，这条历史就永久消失、再也撤不回来。正确做法是「先执行、成功了再挪走记录」。另外，把「最大撤销步数设为 0」从「不限制」改成「禁用撤销」。

Output: 保留历史语义的 `undoSystem.ts`、明确禁用语义的 `undo/types.ts` jsDoc、覆盖两种场景的 `undoSystem.test.ts`、以及记录语义变更的 `05.3-INTERFACE-NAME.md`。

⚠️ 只动本计划列出的文件；不新增任何命名；不改 `hook/` 的接口与实现（用户已判定 WR-01 / WR-02 / IN-01 不是问题）。若需要改行为或扩大公共接口才能修好，先停下汇报（D-34）。
</objective>
