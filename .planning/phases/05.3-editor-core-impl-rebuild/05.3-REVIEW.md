### WR-03: `UndoSystem.undo` / `redo` 先出栈再 await，操作抛错时该条历史从两栈同时丢失

**File:** `packages/libs/editor-core/src/undo/undoSystem.ts:33-51`
**Issue:**
`const entry = this.undoStack.pop();` 之后才 `await entry.undo.undo(entry.context)`。若被撤回对象抛错，`entry` 已从 `undoStack` 移除，且第 40 行的 `redoStack.push(entry)` 不会执行——这一条历史被静默丢弃，undo/redo 链条断裂（用户无法重试该步）。

**Fix:**
先取出再看，成功后再迁移；失败时放回原位：

```ts
async undo(): Promise<void> {
  const entry = this.undoStack[this.undoStack.length - 1];
  if (!entry) return;
  await entry.undo.undo(entry.context);
  this.undoStack.pop();
  this.redoStack.push(entry);
}
```

### WR-04: `ResourceSystem.dispose()` 只清缓存、不清 `injection`，释放后仍会访问后端

**File:** `packages/libs/editor-core/src/resource/resourceSystem.ts:126-129`
**Issue:**
`dispose()` 仅 `listCache.clear()` / `contentCache.clear()`，`this.injection` 仍指向外部后端。于是 `dispose` 之后 `requestResource()` 依然绕开「未初始化」守卫去调用后端。现有测试 `src/__tests__/core.test.ts:211-213` 恰好把这个泄漏**固化为期望行为**（dispose 后再请求，`requestResourceListCount` 从 1 变 2），等于用测试背书了错误语义。

**Fix:**
`dispose()` 中 `this.injection = null;`，并同步修正 `core.test.ts` 的断言（释放后应记录 `system.notInitialized` 并返回空，而非再次请求后端）。

### WR-05: `PanelSystem.dispose()` 不重置 `initialized`，释放后系统处于半可用状态

**File:** `packages/libs/editor-core/src/panel/panelSystem.ts:156-171`
**Issue:**
`dispose()` 移除了窗口 focus/blur 监听并清空面板，但没有 `this.initialized = false`，也没重置 `currentParam`。之后若再调 `registerPanel()`，第 106 行的 `if (this.initialized)` 仍为真，会立刻 `await panel.initialize()`；但窗口监听已移除，`onFocus`/`onBlur` 永远不会触发。系统呈现「注册可用、焦点失效」的不一致状态，且没有二次 `initialize()` 的补救路径。

**Fix:**
在 `dispose()` 末尾加 `this.initialized = false; this.currentParam = {};`。

### WR-06: 多处 `void` 掉返回 Promise 的回调，rejection 无人处理

**File:** `packages/libs/editor-core/src/panel/panelSystem.ts:74-79`
**Issue:**
```ts
this.handleFocus = (): void => {
  void this.currentPanel?.onFocus();
};
this.handleBlur = (): void => {
  void this.currentPanel?.onBlur();
};
```
`onFocus`/`onBlur` 是 `Promise<void>`。用 `void` 显式丢弃后，一旦面板回调抛错，就会变成 **unhandled promise rejection**，既不冒泡也不记录。

**Fix:**
至少捕获并记日志（新日志 id 待确认）。

### WR-07: `registerPanel` 先执行 `creator` 再做重复 id 判断，重复时面板/上下文被丢弃且不 `dispose`

**File:** `packages/libs/editor-core/src/panel/panelSystem.ts:94-101`
**Issue:**
`creator` 可能已经申请资源、注册副作用或持有句柄。重复 id 时返回 `null`，但已创建的 `panel` 既不入注册表、也永不 `dispose()`，造成泄漏。

**Fix:**
在重复分支里 `await panel.dispose()` 后再返回 `null`。

### WR-08: `switchTo` 不校验面板是否已注册，可切到「系统无法管理」的面板

**File:** `packages/libs/editor-core/src/panel/panelSystem.ts:131-140`
**Issue:**
`switchTo(panel)` 只比较 `panel === this.currentPanel`，不检查 `this.panels.has(panel.id)`。传入从未 `registerPanel` 的面板会被设为 `currentPanel` 并渲染，但 `dispose()` 遍历的是 `this.panels`，永远不会释放它；其资源钩子也从未挂载。

**Fix:**
入口校验 `this.panels.get(panel.id) !== panel` 时记日志并返回（新日志 id 待确认）。

### WR-09: 资源钩子派发不做错误隔离，单个钩子抛错会中断其余钩子与整个更新流程

**File:** `packages/libs/editor-core/src/resource/resourceSystem.ts:116-124`
**Issue:**
`updateResource` / `updateResourceList` 都写成 `await Promise.all(this.forEachHook((hook) => hook.onUpdateResource?.(id)));`。`forEachHook` 是同步 `Set.forEach`：只要某个钩子在**同步阶段**抛错，`forEachHook` 当场中断，后面的钩子根本不会进入返回数组。一个坏面板的同步异常会阻止其他面板收到资源更新。

**Fix:**
在调用点逐项隔离（`try/catch` 或 `Promise.resolve().then(...).catch(...)`），确保一个监听者失败不影响其余监听者，并记录失败（新日志 id 待确认）。

### IN-04: `UndoSystem` 的 `maxUndoStep = 0` 语义

**File:** `packages/libs/editor-core/src/undo/undoSystem.ts:26`
**Issue:** 用户裁定 `maxUndoStep = 0` 应表示**禁用撤销**（不是无上限）。当前实现 `if (this.maxUndoStep > 0 && ...)` 意味着 0 = 不裁剪（无上限），与裁定相反。

**Fix:** `addUndoContext` 在 `maxUndoStep <= 0` 时直接 `return`（不记入历史），`undo`/`redo` 自然为空操作；并在 `IUndoInjection.maxUndoStep` 的 jsDoc 写明「<= 0 表示禁用撤销」。
