<objective>
在 05.3-13 已加宽的接口上落地实现：把 `injection` 的定值断言换成真正的可空成员——未初始化时经集中日志记一条 `resource.notInitialized` 并返回空值（不抛错、不直接控制台输出）；补齐六个私有成员的 jsDoc；把面板切换参数从「可能没有」统一为「总是一个对象」（内部字段与 `currentParam` 必填，`switchTo` / `internalSwitchTo` 参数默认 `{}`，公共接口仍可选）。

Purpose: 消除评审确认的四处实现缺陷（定值断言、私有成员缺 jsDoc、未初始化的处理方式、切换参数可为空），满足 AGENTS §Code style 注释规范、D-09「朴素简洁、绝不炫技」与 D-13「initialize 注入」的语义。
Output: 加上空守卫与日志的 `resourceSystem.ts`、新增消息的 `messages.ts`、补齐 jsDoc 的 `undoSystem.ts` / `resource.ts`、参数统一后的 `panelSystem.ts`、更新的资源测试与 `INTERFACE-NAME.md`。

说人话：资源系统还没被初始化时，现在会硬报一个「我给不出数据」的正确做法——用系统日志记一条英文提示，然后老实返回「空的」（列表给空数组、请求给 null、读内容给 undefined）。另外给六个内部字段补上说明注释，并把面板切换时传的参数从「有时没有」改成「永远是个对象」。
⚠️ 只动本计划列出的文件；不新增任何命名（除用户已确认的日志 id）；若发现需要改行为或接口才能修好，先停下汇报（D-34）。
</objective>

<open_questions>
以下三点需用户确认；未确认前按「倾向方案」执行，确认后如需调整再改：

1. **`EditorPanelHooks.onUpdateResource` 的空值处理（05.3-13 已按倾向方案实现）**：倾向方案 = 就地 guard（`request()` 得 `undefined` 时不通知面板），公共 `IEditorPanel` 接口不变。备选 = 把公共 `IEditorPanel.onUpdateResource<T>(id, data: T | undefined)` 一并加宽。之所以倾向 guard：`IEditorPanel` 由外部编辑器 / impl 实现，加宽会波及所有外部实现，而该分支在已初始化路径下实际不可达。
2. **源码 sweep 中「无 `console.`」的范围**：`src/log/logger.ts` 是 editor-core 唯一日志出口，本身必须调 `console.error` / `console.warn`。故 sweep 排除 `src/log/logger.ts`。若要求全局为零，与既有日志设计冲突，需另行决定。
3. **`IEditorPanel.onSwitchIn` 的「实现默认 `{}`」落点**：editor-core 生产源码中没有任何 `IEditorPanel` 实现（只有测试 mock，且不使用该参数）。按 AGENTS「实现里未使用的后置参数不得填」，测试 mock 不应声明未用参数；若用户指的是 `editor-impl` / `editor` 的实现（本阶段范围外），请指明。
</open_questions>
