# Phase 05.3 Plan 04: 撤销系统 Summary

**Status:** Complete
**Executed:** 2026-10-04

## 结果

把 `@motajs/editor-core` 的撤销系统 `UndoSystem` 落地：它实现 `IUndoSystem`，用两个实例私有栈（`undoStack` / `redoStack`）保存「可撤回对象 + 撤回上下文」记录，`addUndoContext` 入栈并在超过 `maxUndoStep` 时从栈底裁剪、同时清空 redo 栈；`undo()` / `redo()` 把记录原样交给记录对象的 `IUndoable.undo/redo`，系统自身不感知面板或资源语义；`dispose()` 清空两栈。撤销系统的最小闭环与全部边界均有用例覆盖。

一句话：**这是「撤销 / 重做」的最底层实现——它只负责按顺序记住每一步操作并回调操作者，不掺任何 UI 或引擎概念。**

## 实际改动

- 新增 `packages/libs/editor-core/src/undo/undoSystem.ts`：
  - 模块内非导出接口 `UndoEntry`（`undo: IUndoable` + `context: IUndoContext<unknown>`，均 readonly），代表一条撤回记录。
  - `export class UndoSystem implements IUndoSystem`：
    - 字段 `maxUndoStep = 0`（实现类可变字段，满足接口 readonly；由 `initialize` 注入）；`private readonly undoStack` / `redoStack` 均为实例字段。
    - `initialize(injection)`：`this.maxUndoStep = injection.maxUndoStep;`。
    - `addUndoContext(undo, context)`：push 入 `undoStack`；`maxUndoStep > 0` 且超长时 `shift()` 从栈底裁剪；清空 `redoStack`。
    - `undo()`：空栈直接返回；否则弹出栈顶，`await entry.undo.undo(entry.context)`，再压入 `redoStack`。
    - `redo()`：反向（弹 `redoStack` → `await entry.undo.redo(entry.context)` → 压回 `undoStack`）。
    - `dispose()`：清空两栈。
    - 导入用相对路径 `./types`，普通 import（不用 `import type`、不用 `@/` 别名）；实现类不重复接口方法的 jsDoc；无文件头注释、无构造器注释。
- `packages/libs/editor-core/src/undo/index.ts`：末尾**追加**一行 `export * from './undoSystem';`（原有 `export * from './types';` 未动）。
- 新增 `packages/libs/editor-core/src/undo/__tests__/undoSystem.test.ts`：
  - 模块级测试替身 `FakeUndoable implements IUndoable`，记录 `undoCount` / `redoCount` 与最后一次收到的 context。
  - 最小闭环 2 例（`describe('UndoSystem 最小闭环')`）：undo 以同一 context 调 `undo`；redo 以同一 context 调 `redo`。
  - 边界 4 例（`describe('UndoSystem 边界')`）：超 `maxUndoStep` 从栈底裁剪仅保留最近 maxUndoStep 条；新操作入栈清空 redo 栈；空栈 undo/redo 为空操作不调替身；`dispose()` 后两栈清空。
  - 首行 import；每个 test 前单行 `//` 说明覆盖内容；无文件头大段注释。
