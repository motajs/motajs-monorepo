修好 TypeScript 6.0 带来的两处配置破坏：把编辑器 tsconfig 里已废弃并会硬报错的 `baseUrl` 删掉；给 service-worker 的两个 tsconfig 显式写上需要的全局类型包。让除「editor-impl 仍是空壳」造成的既有红外，全仓在 TS6 下重新变绿。

Output: 三个 tsconfig 的配置修正 + 一份「TS6 未新增错误」的对比证据与既有红清单。

⚠️ 若修复需要改源码而非配置，停下汇报，不擅自改。

    (2) `packages/apps/service-worker/tsconfig.app.json`（含 `src`、排除 `src/server`，即浏览器端 view）：加 `"compilerOptions": { "types": ["wicg-file-system-access"] }`。只需它——`@types/react` / `@types/react-dom` 都是显式 import、不需要全局；`vite/client` 已由 `src/vite-env.d.ts` 的 `/// <reference types="vite/client" />` 引入，不受 `types` 列表影响。规划期实测仅加 `wicg-file-system-access` 即退码 0。
    (3) `packages/apps/service-worker/tsconfig.server.json`（含 `src/vite-env.d.ts`、`src/idl`、`src/server`，即 Service Worker 服务端 + Node）：把 `"compilerOptions": {}` 改为 `"compilerOptions": { "types": ["node", "serviceworker", "wicg-file-system-access"] }`。三者都必需——`node` 供 `node:*` / `Buffer` / `BufferEncoding` / `path`；`serviceworker` 供 `ServiceWorkerGlobalScope` / `clients` / `Clients` / 事件参数类型；`wicg-file-system-access` 供 `FileSystemDirectoryHandle` 的 `requestPermission` / `queryPermission`。规划期实测三者齐备退码 0，去掉 `wicg` 会剩 `src/server/project.ts` 1 条错误。
    (4) 这些 `@types` 都已由 service-worker 的 devDependencies 声明（`@types/node`、`@types/serviceworker`、`@types/wicg-file-system-access`，走 catalog），且因 pnpm 隔离可从 `packages/apps/service-worker/node_modules/@types` 解析，无需改动依赖。
    (5) 决策（为什么放各包、不放共享基底）：`types` 是「整程序要加载哪些全局类型包」的开关，`@motajs/config` 的 `tsconfig.app.base.json` 被 editor 与多个包共用。把 `node` / `serviceworker` 放进基底会把 Node 与 Service Worker 的全局污染进浏览器包和纯 lib 包（pnpm 隔离下 `@types/node` 也未必对每个包可见）；而基底里放任何一份列表都无法同时满足 app（仅 wicg）与 server（node+sw+wicg）两种不同需求。故基底保持无 `types`，在 service-worker 两个 tsconfig 各自显式列举。
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tsconfig → 编译器类型系统 | 显式 `types` 决定加载哪些全局类型包；列多列少直接影响类型检查强度 |
| 共享 `@motajs/config` 基底 → 各包 | 基底被 editor 与多个包共用，往基底加 `types` 会跨包生效 |
| pnpm 隔离的 node_modules → service-worker | `@types/*` 只能从 service-worker 自己的 `node_modules/@types` 解析 |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
