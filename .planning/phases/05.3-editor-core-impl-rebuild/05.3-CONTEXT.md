<decisions>
## Implementation Decisions

### A. 重做范围与验收
- **D-01:** `editor-core` 与 `editor-impl` **全部重新做**，非增量整改；旧实现作废。
- **D-02:** 唯一验收标准是**最终完成时画面与现状一致**；中间步骤**不设任何要求**，哪怕运行不了也没问题。
- **D-03:** 核心架构由用户负责设计；在用户给出架构前，agent 不自行设计接口与结构。

### B. 目的与概念澄清
- **D-04:** 最终目的是**通过功能的组合，覆盖游戏引擎所有功能的编辑工作**。
- **D-05:** **不存在「抽 Engine」这个设计**。此前代码中的 `defineEngine` / `EngineAdapter` 等属理解偏差，不是本意；本阶段主题就是 `editor-core` / `editor-impl` 两个包。

### C. 职责划分
- **D-06:** `editor-core` **不预设任何需求**，只提供最底层接口与管理——包括「请求数据」（impl 获取数据的方法）、功能注册、撤回管理、页面管理等；本身**不含任何功能**，是个空壳。
- **D-07:** `editor-impl` 是用 core 接口写出的**默认实现**；没有它 core 仍可独立运行。表格编辑、地图编辑、代码编辑等功能都归它。

### D. 设计取向
- **D-08:** 接口设计核心原则是**合理且方便**，并满足**正交、可组合**；参考 `../template` 的设计思路（`packages/animate`、`audio`、`loader`、`render`；`packages-user/data-common`、`data-base`、`data-system`、`data-state`），但不公式化地照搬。
- **D-09:** 实现要**朴素、简洁、逻辑清晰**——不过度拆分函数、不过度防御式编程、不炫技；注释**少而精**，代码本身要能自解释。

### E. 流程门禁（用户 2026-10-03 重申）
- **D-10:** 严格遵循 GSD 流程，并额外遵守：讨论阶段**用户主导**；计划**逐个汇报**（先汇报第一个，用户提问/要求修改后再汇报下一个，全部汇报完统一修订）；每个计划**执行前简报并等用户文字批准**；**执行后汇报**并接着简报下一个计划。
- **D-11:** 任何行动都必须先经用户同意，不得擅自操作。

### F. editor-core 接口框架（2026-10-03 讨论定稿）

**核心与入口**

- **D-12:** `editor-core` 公开面只有 `IEditorCore`：`version` + 三个系统（`undoSystem` / `panelSystem` / `resourceSystem`）+ `initialize(injection)` + `dispose()`；**没有 `render()`**，渲染根由 `panelSystem.render()` 提供。
- **D-13:** 三个系统统一用 `initialize(injection)`（初始化并注入），且均为 `Promise<void>`：`IUndoSystem.initialize(IUndoInjection)`、`IResourceSystem.initialize(IResourceInjection)`、`IPanelSystem.initialize(IPanelInjection)`；原 `inject` 一律改名 `initialize`。
- **D-14:** `IEditorCoreInjection = IUndoInjection & IResourceInjection & IPanelInjection`，由 `IEditorCore.initialize` 一并下发给三个系统。
- **D-15:** `IPanelInjection` 暂为空接口占位（后续可能加内容）；注入只给 `IPanelSystem`，**面板本身不接收注入**（`IEditorPanel.initialize()` 无参）。
- **D-16:** 导出 `EditorCore` 类，构造器内部自己 new 三个系统；三个系统类也导出，但仅为接口统一、外部一般用不到。core / impl 都不提供「创建入口」，由**编辑器顶层构造 core**。

**资源**

- **D-17:** `IResourceIdentifier = { readonly type: number; readonly id: string }`；`type` 由外部枚举定义，core 不预设资源类型。
- **D-18:** `IResource<T>` 是面板持有的资源句柄：`request()` 读、`write(data)` 写；`IEditorPanelContext.requestResource(id)` 返回 `Promise<IResource<T> | null>`。
- **D-19:** 系统缓存资源列表——首次 `requestResource(id)` 触发 `requestResourceList(type)` 并缓存，命中返回句柄、未命中返回 `null`。
- **D-20:** 资源内容也缓存；`updateResource(id)` 时刷新缓存，`write(data)` 也同步更新缓存。
- **D-21:** `IResourceInjection` 是后端实现：`requestResource` / `requestResourceList` / `writeResource` / `createResource` / `deleteResource`。
- **D-22:** 创建 / 删除**只有面板能发起**（panel context 的 `createResource` / `deleteResource`），外部不需要；完成后调 `updateResourceList` 刷新列表并广播所有面板。创建 / 删除需要撤回，由面板自己 `addUndoContext` 记录。
- **D-23:** `write` **不触发** `updateResource`；`updateResource` 由外部监听触发。写入后有短暂防抖、期间不接受 `updateResource`（避免面板重复解析）——此细节用户表示**暂不重要，先不管**。
- **D-24:** `updateResource(id)` / `updateResourceList(type)` 刷新后，`onUpdateResource` / `onUpdateResourceList` **广播给所有面板**，各面板自行判断是否需要。
- **D-25:** 撤回**不触发** `updateResource`（撤销不等于保存，不触发外部监听）。

**面板**

- **D-26:** `IEditorPanel` 是功能单元：`id`、`initialize` / `dispose` / `render()`、`onFocus` / `onBlur`（浏览器窗口焦点进 / 出编辑器）、`onSwitchIn(param?)` / `onSwitchOut`（面板之间切换）、`onUpdateResource` / `onUpdateResourceList`；并 `extends IUndoable`。
- **D-27:** `EditorPanelCreator = (context: IEditorPanelContext) => Promise<IEditorPanel>`；面板创建时拿到 context（请求资源、创建 / 删除、加撤回）。
- **D-28:** `IPanelSystem`：`currentPanel`（同一时刻只有一个前台面板）、`registerPanel`（id 强制唯一）、`getPanel(id)`、`switchTo(panel, param?)`、`disposePanel`、`render()`、`dispose()`；并 `extends IUndoable`。
- **D-29:** 面板粒度为「工作区 / 模式」；多个编辑器同屏由面板 / impl 自己排布，core 只支持一个前台面板。
- **D-30:** 生命周期——未 `initialize` 时 `registerPanel` 只创建、不调 `initialize`，待 core.initialize 后一并补调；已 `initialize` 时 register 直接调 `initialize`。

**撤回**

- **D-31:** `IUndoContext<T> = { readonly type: number; readonly data: T }`；`IUndoable` = `undo` / `redo`；`addUndoContext(undoable, context)` 由编辑者主动记录；面板上下文的 `addUndoContext` 直接调 `IUndoSystem.addUndoContext`。
- **D-32:** 面板切换占撤回步——`IPanelSystem extends IUndoable`；内部 `internalSwitchTo` 不记录、公共 `switchTo` 记录，避免撤销时自证循环。
- **D-33:** `maxUndoStep` 预期 200–1000；只对撤回系统有意义，外部不需要。撤销 / 重做由撤回系统按操作者（面板或面板系统）自动确定撤谁，面板之间无需互相感知。

**流程补充**

- **D-34:** 修改接口设计前必须先向用户汇报、经确认后才可改；实现中发现接口不够用也一样，先报后加。

### G. 资源读写边界与 Hook 通知（2026-10-03 追加，更正 D-20 / D-24）

- **D-35:** 资源**读写只对面板开放**——唯一入口是 `IEditorPanelContext` 的 `requestResource` / `requestResourceList` / `createResource` / `deleteResource`；对外暴露的 `IResourceSystem` **不含**这些读写方法。
- **D-36:** 搬入游戏引擎的 Hook 系统（`src/hook/`：`IHookBase` / `IHookController` / `IHookObject` / `IHookable` 接口 + `Hookable` 抽象类 + `HookController`）。`IResourceSystem extends IHookable<IResourceSystemHooks>`；`IResourceSystemHooks.onUpdateResource(id)` / `onUpdateResourceList(type)` **只带 id / type**，收到者自行重新申请资源获取新内容。
- **D-37:** 资源更新到面板的桥接——`PanelSystem` 为每个面板向资源系统挂 `EditorPanelHooks`（构造时传入该面板的 context），钩子重新申请资源后通知面板。据此更正 D-20 / D-24：`updateResource(id)` 负责**作废缓存并触发钩子**；由钩子重新申请并把内容交给面板（面板层 `onUpdateResource(id, data)` 不变）。`write(data)` 仍同步更新缓存且不触发 `updateResource`（D-23 不变）。

### H. 研究后的决策补充（2026-10-03）

- **D-38:** **去掉**「core 禁 window」的旧限制（上一版 Phase 3 的 PORT-02 门禁）。core 可直接监听 `window` 的 focus / blur 来触发面板的 `onFocus` / `onBlur`，不额外加接口。
- **D-39:** 三个系统都提供 `dispose()`——给 `IUndoSystem` / `IResourceSystem` 补 `dispose()`（`IPanelSystem` 已有）。**用户授权改其已写的接口文件**。
- **D-40:** editor-core 内**一律用相对路径导入**，不用 `@/` 别名；用户已写接口文件里的 `@/hook` / `@/undo` / `@/resource` / `@/panel` 一并改成相对路径（用户授权）。
- **D-41:** editor-core 的 react 依赖改用工作区 **`catalog:default`**（仓库统一版本），**不为对齐旧编辑器**而选版本；借此去掉重复 React。
- **D-42:** `.prettierrc`（去掉 `.json`）是**有意改名**；`prettier-setup.js` 门禁改为识别 `.prettierrc`。
- **D-43:** 基础设施先对齐——八道 `scripts/verify/*.js`（及 `.dependencyCruiser.cjs`、`eslint.config.js` 模块状态规则、`panda.config.ts`、`subpathStatus.json`）按新 `src/` 结构与上述决定调整；本阶段 editor-impl 仍是空壳，**允许部分门禁红并记录**，不强行全仓绿。
- **D-44:** 测试若需渲染，新增 `react-dom` + `@testing-library/react` 作为 devDependencies（接口文件不动）。
- **D-45:** `EditorPanelHooks` 的构造签名等属实现细节，由实现决定（用户 2026-10-03：不询问）。
