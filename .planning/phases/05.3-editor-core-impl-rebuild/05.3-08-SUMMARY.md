**允许红说明（D-43）：** 上述 6 道红全部由「editor-impl 仍是空壳 / editor 尚未适配 / 需构建产物」导致，与本计划的路径迁移无关；迁移后的脚本均能被 Node 正常加载执行（Task 3 的 `Cannot find module|ENOENT` 检查未触发）。**没有任何门禁被削弱或缩小扫描范围来凑绿。**

## Decisions Made

- `subpathStatus.json` 的 editor-core `.` content 由 `kernel+ports+undo-exports` 改为 `core-exports`（用户已确认；旧值随旧架构作废）。
- D-38：`window` 从 core 的 PORT-02 禁用表移除，`coreModuleState.js` 的 `BANNED_GLOBALS` 与 fixture 同步删除 window 行；其余平台能力与 `process.env`/`import.meta.env` 保留，两极性仍逐条证明会被 error 级拦下。
- `coreBoundaries.js` 的能力互斥 fixture 父目录 `editor-impl/src/code/` 当前不存在：写前 `mkdirSync(...,{recursive:true})`，删后仅在目录原本不存在时 `rmdirSync`，不留空目录（已实测运行后 `editor-impl/src` 只剩 `index.ts`）。
- 非空转下界按当前实际文件数保守重设（`coreImportType` 55→18 对应 26 个含测试文件；`coreEngineNeutral` 30→12 对应 21 个生产文件），仍高于生产源码数，范围被削弱会立即变红。
