# Phase 04.1 Plan 09: 视口化地图画布与整条路径预览 Summary

**地图区从「一整张画布」变成「一屏视口 + 滚动条」：画布永远只有 13×13 格大小（可被宿主改成 15×9），整图尺寸只用来撑滚动占位；四向按钮、方向键、WASD 与滚轮移动视口的老路全部删除，视口只剩 `MapPanel.setViewport` 一个入口；线模式拖动时能看到这一笔经过的所有格子。**

## Accomplishments

- **画布只画一屏。** `MapCanvas` 现在是三层结构：可见框 `.emap-canvas-viewport`（`overflow: auto`，尺寸 = 视口格数 × 缩放后格像素）→ 透明占位 `.emap-canvas-spacer`（普通模式取整图尺寸，大地图取可见框尺寸）→ `position: sticky` 的 `.emap-canvas`（尺寸 = 可见框，Pixi 画布挂在这里）。40×26 地图、13×13 视口、32px 格时画布 416×416、占位 1280×832；缩放 1.5 时占位按 48px 格变成 1920×1248。256×256 地图不再创建 8192px 边长的 WebGL 画布。
- **滚动是唯一视口入口。** `onScroll` 用 `requestAnimationFrame` 节流后回报 `floor(scrollLeft / cellWidth)` / `floor(scrollTop / cellHeight)`；`MapPanel.setViewport` 夹取到 `[0, 文档尺寸 − 视口格数]` 再发布。卸载时取消帧回调；大地图期间 `onScroll` 直接返回、`MapPanel.setViewport` 直接返回。
- **大地图与滚动互斥。** `MapPanel.setBigMap(true)` 把视口钉到 `(0,0)`（进入前的值留在 `preBigMapViewport`），退出时还原并把画布的 `scrollLeft/scrollTop` 同步回 `viewport × 格像素`；占位层在大地图取可见框尺寸，因此没有滚动条，也不会把 Plan 10 的缩略图带偏。Plan 02 的零视口命中、Plan 10 的 `(0,0)` 缩略绘制与 Plan 07 写进模型的 `viewport` 三者拿到的是同一个值。
- **老路径收口。** 工具栏 `MapViewportButtons`、`IMapToolbarProps.onMoveViewport`、全部 `map-viewport-*` 标识删除；方向键 / WASD / 滚轮移动视口删除；`MapPanel.moveViewport`、`IMapCanvasProps.onMoveViewport`、`IMapPanelViewProps.onMoveViewport`、`MapPanelView.resolveMovedViewport` 全部消失。Ctrl+C / Ctrl+V / Esc / F 保留，既有用例全绿。
- **整条路径预览。** 线模式拖动时 `previewCells` 取 `buildStrokeWrites(gesture.path, pattern)` 去重后的格子集合，从 (1,1) 拖到 (4,1) 得到 `1,1;2,1;3,1;4,1`；矩形 / 填充模式不带 `previewCells`，松开或取消手势时清空。
- **props 真的到达画布与 Pixi 表面。** `MapPanelView` 用 `resolveMapLayout`（`viewportColumns` / `viewportRows` 显式传默认值，`zoom` 与渲染模型同一份）算出画布尺寸，并把 `document` / `currentLayerId` / `aboveLayerOpacity` / `cellFrameSpeed` 转交给 `MapSurface`，Plan 10 的大地图缩略纹理与动画时钟才有输入。

## Decisions Made

- **占位层取 `max(可见框, 文档尺寸)`：** 文档比视口小时（如 4×3 的样例地图）不产生滚动条，文档更大时仍能滚到边缘。
- **标尺移到滚动容器的 20px 留白里：** 画布变成 `sticky` 后，原先挂在画布内、靠负偏移（`top: -20px` / `left: -20px`）站位的标尺会被 `overflow: auto` 裁掉；现在标尺作为可见框的兄弟节点、用内联 `top/left` 定位，`map.css` 未改。
- **`MapPanel.setViewport` 大地图期间直接返回：** 大地图视口只有一个值 `(0,0)`；滚动残留的 rAF 回调不得把它改回普通模式坐标。
- **滚动换算统一用 `Math.floor`：** 回报与同步效应用同一个取整方式比较，避免「刚回报 2 格、同步效应又按四舍五入拉回」的抖动。
- **`previewCells` 复用 `buildStrokeWrites` 再去重：** 预览格与真正落笔格由同一个函数产出，不会出现「预览到了、落笔没到」。
