# Phase 04.1 Plan 37: 大地图缩略逐格渲染 Summary

**大地图缩略纹理改吃与普通模式同一套逐格数据：自动元件拆四块、大 / 小素材按 contain 摆放，纹理仍只在重建时算一次，裁切纹理按「图片路径 + 裁切矩形」共享；每格小于 4px 时只画整格裁切，contain 不受影响**

## Accomplishments

- U-28（大地图自动元件没有连接）已修：根因不是算法，而是大地图那条路径**绕过了**逐格管线（旧路径只贴每格的左上角一小块并按整格拉满）。现在 `buildThumbnailCells` 对每格调 `createRenderCell`，自动元件按同层邻居拆四块、裁切取对应象限，缩略里自然连成一片。
- U-29（大地图大 / 小素材拉满整格）顺带修掉：`createRenderCell` 里的 `resolveTileDest` 就是 contain 口径，缩略与大素材现在共用同一个目标矩形（96×64 素材在 32px 格里得到 32×21.33、纵向居中于 5.33）。
- 性能口径不变：缩略格子只在 `MapSurface` 判定 `stale` 时算一次，`IMapRenderModel` 不携带它们，动画时钟也不会触发重建；裁切纹理按「图片路径 + 裁切矩形」共享，65,536 格的文档不会变成 65,536 张纹理。
- 图元数可控：四块展开只在每格 ≥ `MAP_BIG_MAP_AUTOTILE_CELL`（4px）时发生；纹理边长上限 512 ⇒ 只可能发生在文档 ≤128×128，因展开而增加的图元最多 65,536 个；「每格一个图元」的既有口径不变。
- 旧的三段路径（`collectThumbnailTiles` / `resolveThumbnailTileTexture` / `paintThumbnailLayers`）已真正删除，没有留「大地图不画自动元件」之类的退化开关。

## Decisions Made

- **复用 `IMapRenderCell` 而不是新接口**：缩略格子就是普通模式的格子形状，四块复用 `IMapAutotileQuarters`，因此不需要单独的接口声明计划，也不会出现「两套格子结构」。
- **`detailed` 只降级自动元件的四块**：`{ ...cell, crop: image.frame.base, autotileQuarters: undefined }` 保留 `createRenderCell` 算出的 `x / y / width / height`，所以 contain 在 2px 格子里依旧成立；这是可见性上限，不是退回旧路径。
- **纹理缓存键 = 图片路径 + 四个裁切数值**：按格子 key 缓存会给每格建一张裁切纹理（65,536 格 = 65,536 张），内存与耗时都不可接受。
- **帧号用既有 `resolveInitialFrame`**：它就是 `resolveCellFrame(cell.defaultFrame, 0, cell.frameCount)`，与普通模式的首帧口径同源，不另写。
- **不动 `stale` 判据**（文档 / 当前层 / 上层不透明度 / 图片版本），缩略纹理仍不随动画逐帧重建（OQ8 / D-53 不变）。
