# Phase 04.1 Plan 28: 收藏拖拽视觉反馈 Summary

**拖收藏格时，被拖的那格变淡（`opacity: 0.4`）、要放进去的那格亮一圈强调色边框，松手就恢复——排序规则一个字没改**

## Accomplishments

- 收藏格新增两个只读渲染输入：`dragging`（这一格正在被拖）与 `dragOver`（指针正悬停在这一格且它不是源格），父组件按 `drag.from === index` / `drag.over === index && drag.from !== index` 传值；拖拽状态机、`onPointerLeave` 清理、`onReorder` 调用、`onSelectSlot(index + 1)` 口径完全没有改动。
- 类名拼装收敛到模块级纯函数 `favoriteSlotClassName(props)`：基础类 `emap-material-cell emap-favorite-tile is-favorite` 固定，`is-selected` / `is-dragging` / `is-drag-over` 按条件逐条 push，替换掉原来的两分支三元。
- `map.css` 末尾追加两条规则（第 954-962 行）：`.emap-favorite-tile.is-dragging { opacity: 0.4; }` 与 `.emap-favorite-tile.is-drag-over { box-shadow: 0 0 0 2px var(--editor-accent, #1677ff); }`，每条都带一句注释说明用途与 D-48 来源。放末尾是因为中段 `.emap-material-cell.is-selected` 同样有两个类、特异性相同，放前面会被它的 `box-shadow` 覆盖。
- 新增一条测试覆盖「按下 → 悬停 → 松手」三段：源格加 `is-dragging`、目标格加 `is-drag-over`、源格不自标悬停态、松手后 `onReorder(0, 1)` 且两类名都清空。断言统一用 `classList.contains(...)`，不断言整串 `className`。

## Decisions Made

- **类名拼装抽成纯函数**：计划允许「沿用 `filter` 写法或改成返回字符串的小函数」；这里选后者，避免一条 150+ 字符的长表达式，也让后续新增状态只加一行 `if (...) names.push(...)`。
- **`dragOver` 必须排除源格**：拖拽一开始 `over === from`（`onDragStart` 里写的是 `{ from, over: from }`），如果只判 `drag.over === index`，源格会同时带 `is-dragging` 和 `is-drag-over`，正好命中威胁表 T-4.1-28-01 描述的场景。加 `drag.from !== index` 后源格只有透明度变化。
- **CSS 规则追加在文件末尾**：这是计划明确要求的（`key_links` 与 T-4.1-28-02），也是等特异性覆盖的唯一可靠手段；注释里写清「拖动源降低不透明度」/「拖拽悬停目标加描边（D-48）」。
