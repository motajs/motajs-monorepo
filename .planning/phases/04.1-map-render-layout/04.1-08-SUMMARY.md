## Decisions Made

- **用 `context.listDirectory` 判断文件是否存在：** `requestResource` 在配置了 fs 时总是返回句柄，只有 `request()` 抛错才暴露缺失；没有这次存在性判断就无法同时满足「缺失 → 迁移且 `Ready`」和「读失败 → `Error`」。
- **`saveTilePreferences` 在文件不存在时走 `createResource`：** 它会把新文件登记进资源索引，后一次 `listDirectory` 才能看到刚写的偏好，避免「落笔写了文件、下次又当成缺失再迁移」。
- **`MapPanel.recordTileUse` 保持私有：** 它是 `MapPanel.commitCells` 的唯一尾部动作，测试经落笔路径覆盖，不额外扩大公开面。
- **收藏位选中用 `MapPaletteKind.Tiles`：** 收藏只允许普通图块；Tileset 编号已在归一化时被排除，空位与擦除都退化为空选择。
- **`MapPanel.setZoom` 忽略非有限数：** 其余值夹到 `MAP_ZOOM_MIN..MAP_ZOOM_MAX`，避免 `NaN` 污染视图状态。
- **`onSetViewport` 不在本计划：** 按 `INTERFACE-NAME.md`，`MapPanel.setViewport` 与其绑定由 Plan 09 在同一段追加；本计划结束时段内只有七条回调绑定。

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] 新增私有 `MapPanel.hasProjectFile` 以区分「文件缺失」与「读取失败」**

- **Found during:** Task 1（统一偏好文件与落笔统计）
- **Issue:** 计划写的是「`requestResource(MAP_TILE_PREFS_PATH)` 返回 `null` 时才读旧文件」，但 `ResourceSystem.requestResource` 在初始化了 fs 时永远返回句柄，文件缺失只会在 `request()` 抛错。若把所有抛错都当缺失，就无法满足「读取抛错后 `recentStatus` 为 Error」；若都当失败，就无法满足「文件缺失时迁移旧文件且 `Ready`」。
- **Fix:** 增加私有 `MapPanel.hasProjectFile(path)`：按父目录 `context.listDirectory` 列出直接子条目判断文件是否存在。缺失 → 只读一次旧文件并 `migrateRecentTiles`；存在但读取抛错 → 外层 catch 发布 `Error`。写盘同样用它决定 `resource.write` 还是 `createResource`。
