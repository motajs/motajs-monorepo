## Decisions Made

- **焦点只由 `pointerdown` 收到面板根**：不挂 `window` / `document` 全局监听，也不用「全局标志位」模拟面板有焦点。数字键仍然只有 `MapPanelView.handlePanelKeyDown` 一处实现。
- **焦点归属判断只看 DOM 属性**：`ownsKeyboardFocus` 用 `input, textarea, select, button, a[href], [tabindex], [contenteditable]` 判断，不按组件类型写死 antd 控件，因此 antd 按钮里的图标 / 文字、Pixi canvas、rc-slider 手柄都被覆盖。
- **`ownsKeyboardFocus` 与 `isTypingTarget` 不合并**：前者回答「落点自己会接受焦点吗」，后者回答「现在是不是在打字」，两个问题不同（按钮会接受焦点但不吃数字键）。
- **默认值单源**：`MAP_SHOW_FRAME_COUNT_DEFAULT` 同时供面板构造函数、视图缺省回退、三处测试断言使用，不写字面量。

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `[tabindex]` 选择器把面板根自己也匹配了，导致每次点击都被判成「落点自带焦点」**
- **Found during:** Task 1（新端到端用例首次运行即失败：点 `map-main` 之后 `document.activeElement` 仍是 `body`）
- **Issue:** 计划给的 `closest('input, textarea, select, button, a[href], [tabindex], [contenteditable]')` 是在「面板根没有 tabindex」的前提下写的。本计划给根加上 `tabIndex={-1}` 之后，`closest('[tabindex]')` 会从 `map-main` 一路向上匹配到面板根自己，`ownsKeyboardFocus` 对面板内**任何**点击都返回 `true`，`handlePanelPointerDown` 永远提前返回，焦点永远回不到根上——U-26 完全失效。
- **Fix:** 选择器改为 `[tabindex]:not([tabindex="-1"])`。画布（`tabIndex={0}`）与 rc-slider 手柄（`tabindex="0"`）仍然命中，只有 `tabindex="-1"` 的元素不再算「自带焦点」，面板根正是唯一的那个。判断依旧只看 DOM 属性、函数签名与调用点未变。
- **Files modified:** `packages/libs/editor-impl/src/map/components/MapPanelView.tsx`
- **Verification:** `mapView.layout.test.tsx` 43 条全绿（含新用例）；随后全量 `mapView.layout.test.tsx` 45 条全绿；`pnpm --filter @motajs/editor-impl typecheck` 退出码 0
- **Committed in:** `a8becee`（Task 1 提交）

### 加固（非行为偏差）

- **工具栏落点用例先按 `2` 再按 `1`**：计划只要求「按 `1` 断言擦除」，但默认调色板本来就是擦除态，那条断言会自证。用例改成先 `addFavorite(2)` → 按 `2` 断言 `primaryTileNumber === 2` → 再按 `1` 断言 kind 变回 `Empty`，才真正证明「切擦除」。两条按键都断言了 `preventDefault`（返回 `false`）。不改任何实现代码。
