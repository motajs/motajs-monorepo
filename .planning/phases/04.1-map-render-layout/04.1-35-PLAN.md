<objective>
把「图集真实有几行」这一条从宿主一路接到格子背景：宿主给每个素材组填 `rows`，`resolveGroupAtlasRect` 的普通网格与横向动画优先用它，于是只收录了第 0 行图块的 `tiles-terrain` 不会被压成一行；再用测试钉住底部栏、收藏栏与素材区三处的观感。

用大白话说：上一轮已经把「整张图集多大」算对了，但算高度时仍然只数「目录里出现过的行」。演示数据为了分类，把 128×64 的地形图拆成了四组，其中地形组只收了第 0 行；于是高度被算成 32，把 64 高的图压进一行，第 1 行的敌人 / 人物 / 物品图块就一起画进了同一个格子——这就是你看到的「露出相邻图块、纵向压扁」。这一步做三件事：让宿主把图片真实行数告诉编辑器，让算高度的函数在普通网格与横向动画上优先用它，再在底部栏、收藏栏与素材区各加一条断言，证明一个按钮只显示一个 32×32 的源格；其它布局保持原样。

Purpose: 修 U-25。地图渲染本身是对的，错的只有「整张图集多高」这一个输入，因此改动面必须限制在「宿主填值 + 算高度读它」。

Output: 宿主目录多一个字段赋值、图集矩形函数多一条优先分支、三组回归测试。
</objective>
