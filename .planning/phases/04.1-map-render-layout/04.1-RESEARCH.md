## User Constraints (from CONTEXT.md)

> 以下 D-01…D-29 逐字抄自 `04.1-CONTEXT.md`，是本阶段**锁定决策**；研究不得再讨论替代方案。

### Locked Decisions

#### A. 数据来源与注入

- **D-01:** **宿主解析引擎文件，生成中立的图块目录**交给地图面板。面板不认识 `texture/.list.jsonc`、`tile.jsonc`，也不读这些文件；换引擎只换宿主适配器。
- **D-02:** 目录给**原始素材 + 规则**，不是切好的帧：图片路径、读取方式（`Full` / `Grid` / `RowAnimate` / `ColumnAnimate` / `ScanAnimate`）、切分尺寸、图块编号列表、帧数、自动拼接类型与连接、Tileset 元数据。**编辑器自己切片、自己展开自动拼接**。
- **D-03:** **复用素材数据，不复用素材面板 UI**：宿主从同一份素材数据生成图块目录；右侧素材区由地图能力自己渲染。`map` 不 import `asset` 能力（能力互斥门禁）。
- **D-04:** **每张地图一份 `cellWidth / cellHeight`**，放在中立地图文档里；不是全局设置。
- **D-05:** 图块分类固定为六类：**Terrains / Enemy / Npc / Item / Autotile / Tileset**。`tile.jsonc` 里将要删除的类型不使用；`Animate` 归到 Terrains，不再单独一类。
- **D-06:** **自动拼接的连接规则由宿主注入**：宿主给出每个自动元件单方面连接到的图块编号；编辑器实现通用 8 方向连接与 3×4 / 2×3 贴图选择，**不判断“墙壁”**——对编辑器来说不存在墙壁概念。

#### B. 渲染

- **D-07:** **大素材 contain**：保持宽高比缩到完全放进格内，水平、垂直居中（上下或左右留空）；**小素材保持原尺寸**，同样居中。该行为与引擎默认不同，是编辑器为了实用性做的选择。
- **D-08:** **动画**：帧数、读取方式来自图块目录；默认 **300ms/帧**，宿主可传数值覆盖；**不提供 UI 配置**；最大 255 帧。
- **D-09:** **自动拼接 3×4（48 帧）与 2×3（24 帧）都要做**，支持动画；编辑器实现通用算法，宿主注入连接。
- **D-10:** **Tileset**：整图展示、按 `cellWidth / cellHeight` 分格并画分割线；可单格，也可框选多格；框选后画布显示同尺寸矩形预览。
- **D-11:** **大地图 = 整图缩略纹理**：进入大地图时把整图预渲染成一张缩略图，降采样显示；普通模式只构建可见格。先按 **256×256** 上限；稳定后再考虑 1024×1024。
- **D-12:** **通行度显示 = 四色箭头，不加图例，不填充格子**。四个方向用不同颜色；具体色值由实现选一组在深浅图块上都可读的颜色。
- **D-13:** **删除工具栏四向按钮与键盘 `↑↓←→ / WASD`**；视口改用滚动条 / 滚轮。
- **D-14:** **线模式拖动时显示整条路径的所有点**，不是只显示鼠标所在格。
- **D-15:** **地图属性抽屉禁用点外部关闭**，保留右上角 ✕ 与 Esc。

#### C. 布局与素材区

- **D-16:** **地图视口是编辑器全局设置**：默认 **13×13**，可配置、允许长方形。缩放滑块 **50%–200%**，默认 100%，debounce；同时调整地图渲染缩放与左右两栏宽度比例，并保证素材区最小可用宽度。
- **D-17:** **左侧 = 工具栏 + 地图 + 底部三页「最近使用 / 最常使用 / 收藏」；右侧 = 全部素材区**。
- **D-18:** 素材区：**普通类型竖排分类**（Terrains / Enemy / Npc / Item / Autotile），**Tileset 单独列出一个开关**；除 Tileset 外逐格拆分、只显示第一帧；素材框用**直角矩形**（避免圆角裁掉边角）；可选勾选「显示帧数」，打开后在素材右上角用小字显示帧数。
- **D-19:** **收藏栏**：`1 = 擦除`，`2–9`、`0` 共 **9 个收藏**，总计 10 格；**右键普通图块收藏**（Autotile 算普通图块，**只有 Tileset 不允许收藏**）；支持**拖拽排序**（若拖拽实现困难，退化为上下按钮）；**跨会话持久化**。
- **D-20:** **最近 / 最常 / 收藏统一持久化到 `.editor` 文件夹**，建议文件 `.editor/map-tiles.json`，形如 `{ "recent": number[], "frequent": Record<number, number>, "favorites": number[] }`；「最近 / 最常」用切换按钮选择。
- **D-21:** 素材区的 **Autotile 只显示左上角那一格**，不完整展开 3×4 / 2×3；Tileset 仍整图展示。
- **D-22:** Tileset 与其它素材**不放在一起**，像最近/最常一样在素材区做单独切换。

#### D. Phase 4 UAT 修复（全部并入本阶段）

- **D-24:** **通行度红十字**：按 D-12 改为四色箭头，解决“四方向都不可通行时看起来只有一个十字”的问题。
- **D-25:** **属性抽屉塌成灰线**：`.emap-properties` 外层没有高度，`.etable` 绝对定位导致父级 0 高；补齐高度 / flex 布局，保证首次打开即显示字段行。

| # | 问题 | 一句话结论 | 详见 |
|---|------|-----------|------|
| 1 | 中立图块目录该给什么形状（原始素材 + 规则）？ | 把现在的「每图块一个裁切矩形」换成**每个素材一份读取规则**（读取方式 / 单格尺寸 / 帧数 / 编号列表 / 分类 / 自动拼接规则 / Tileset 元数据），裁切矩形由编辑器按规则现算。 | Pattern 1 |
| 2 | 五种读取方式如何映射到帧数与帧矩形？3×4 / 2×3 连接怎么算？ | `Grid` 每格一帧；`RowAnimate` 每行一个图块、横向为帧；`ColumnAnimate` 每列一个图块、纵向为帧；`ScanAnimate` 整张网格按行优先顺序为一组动画。自动拼接用 8 位连接（最高位左上、顺时针），地图外一律视为「已连接」，连接位再查 4 个半格矩形。 | Pattern 2 / Pattern 3 |
| 3 | 每图 `cellWidth/cellHeight`、contain、300ms 动画如何驱动 Pixi / 命中 / 笔刷 / 缩略图？ | 渲染模型新增 `cellWidth/cellHeight` 与每格 `dest`；`scale = min(1, cellW/srcW, cellH/srcH)` 后居中（与引擎 `FitToSize` 的拉伸不同）；命中测试按 `cellW*zoom` 除；动画用全局帧序号 `floor(elapsed/300) % frames`；大地图把整图渲成一张 `RenderTexture`，按文档 / 当前层 / 上层不透明度变化重建。 | Pattern 4 / Pattern 6 |
| 4 | 最小安全布局改动是什么？ | 顶层由「横排（画布 + 240px 调色板）」改为「左列（工具栏 + 地图 + 底部三页）+ 右列（六类素材）」；地图画布从「整图尺寸」改为「13×13 视口尺寸 + 外层滚动占位」；缩放同时改 `cellPx` 与右栏宽度（`clamp(base/zoom, min, max)`）。 | Pattern 5 |
| 5 | G-04-1 / G-04-2 / G-04-3 的根因与最小修复？ | G-04-1：演示图集其实是 **1×1 像素**的 PNG，所有 32×32 裁切都取到同一个像素 → 整片红、素材区全空；换真实多格色块图集。G-04-2：四支箭头共用**同一个红色**且有白色圆心衬底 → 看起来是一个红十字；改四色 + 去掉整圆衬底。G-04-3：`.emap-properties` **没有任何 CSS 规则**，`.emap-properties-body` 的 `height:100%` 相对 auto 父级解析为 0，`.etable` 的 `inset:0` 于是塌成 2px 边框。 | §UAT 三缺陷根因 |

## Summary

Phase 4 的 `map` 能力已经把「宿主注入中立文档 → 面板编辑 → 按域保存 → 一笔一次撤销」这条主干做通了，但它把**图块当成「预先切好的一格图」**：目录里每个图块只带一个 `crop`，渲染模型只认一个固定 `MAP_CELL_SIZE = 32`，大地图把每个格子都建成一个精灵。这与本阶段的六个能力（每图格子尺寸、contain、动画、自动拼接、Tileset、缩略图）在根上冲突，因此本阶段的主线是**把「图块」从「一张图」升级为「一份素材 + 一条读取规则」**，并让渲染模型携带格子尺寸。

仓库内的现状经本会话逐文件确认：

- 中立文档与目录只有单帧语义：`IMapTileEntry` 只有 `number/column/row/crop/name/pass`，`IMapTileGroup` 只有 `id/name/imagePath/columns/tiles`，`IMapDocument` 没有 `cellWidth/cellHeight`。`[VERIFIED: packages/libs/editor-impl/src/map/types.ts:120-174]`
- 渲染模型只有一个固定格边长：普通模式 `const size = MAP_CELL_SIZE;`、大地图 `const size = Math.min(view.width / document.width, view.height / document.height);`。`[VERIFIED: packages/libs/editor-impl/src/map/model/renderModel.ts:195,247]`
- 所有叠加层（通行度 / 框选 / 预览 / 悬停）在 Pixi 侧**再次硬编码 32**：`mark.x * MAP_CELL_SIZE + MAP_CELL_SIZE / 2`、`toPixelRect` 用 `rect.x * MAP_CELL_SIZE`、悬停 `position.x * MAP_CELL_SIZE + 0.5`。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapSurface.tsx:300-301,346-352,407]`
- 命中测试只除以一个 `metrics.size`，且该值来自固定的 `MAP_CELL_SIZE`（大地图除外）。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:155-156,180-189]`
- 画布尺寸 = **整张地图**（`document.width * MAP_CELL_SIZE`），因此「只画可见格」实际等于「画全图」。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:601-602]`
- 大地图「超过图元上限只画当前层」只过滤**图层**，不减少格子数：256×256 单层仍是 65,536 个精灵。`[VERIFIED: packages/libs/editor-impl/src/map/model/renderModel.ts:250-270]`
- 演示图集是一张 **1×1 像素**的 PNG，却被当作 4 列 × 32px 图集使用。`[VERIFIED: packages/apps/editor-dev/src/demo/mapDemo.ts:32-37,57-64]`
- 属性抽屉的外层容器 `.emap-properties` 在样式表里**没有规则**，只有 `.emap-properties-body { position: relative; height: 100%; min-height: 0 }`。`[VERIFIED: packages/libs/editor-impl/src/map/map.css:515-519]` 而复用的 `.etable` 是 `position: absolute; inset: 0`。`[VERIFIED: packages/libs/editor-impl/src/shared/schemaForm/schemaForm.css:1-13]`

新引擎侧的行为依据（仓库外，本会话逐个 `Read`）给出了本阶段需要的全部语义：五种读取方式、`MapTileBehavior.FitToSize/KeepSize`、`setCellSize`、`frameSpeed = 300`、自动拼接的 8 位连接与 3×4 / 2×3 索引、Tileset 按格切分、以及 **13×13 的地图视口常量**。见 §Sources。

**Primary recommendation:** 用「**素材规则目录 + 纯切片模型 + 格子度量进模型 + 虚拟化画布 + 整图 RenderTexture 缩略 + 单一偏好文件**」六件事落地；接口层先定「目录形状 / 格子度量 / 渲染模型扩展 / 偏好文件 / 布局参数」五组类型，实现层先做六个纯模型（切片、自动拼接、度量、缩略、偏好、布局），再做 Pixi 与视图，最后做开发宿主图集与布局验收。**不要在 `map` 里 import `asset`**；Tileset 的整图分格、缩略图、动画都只在 `map` 内实现。**不需要改 `editor-core`**：D-15 只是 antd Drawer 的 `maskClosable`，偏好文件走既有资源层，视口尺寸走能力注入。

### Pattern 1: 中立图块目录 = 原始素材 + 规则（不是切好的帧）

**What:** 目录从「每个图块一条裁切矩形」改成「每个素材一份读取规则」，图块条目只保留编号与它在素材里的列 / 行。编辑器按规则现算帧矩形、自动拼接四块、Tileset 单格。

**Why:** D-02 锁定「原始素材 + 规则」；且只有这样才能表达 255 帧动画（给裁切矩形会膨胀 255 倍）与 Tileset 大图。

### Pattern 2: 五种读取方式 → 帧数与帧矩形

**What:** 一个纯函数把「素材尺寸 + 读取方式 + 单格尺寸 + 列数」翻译成「每个图块的帧矩形 / 帧轴 / 帧步长 / 帧数」。

**语义依据（逐字）:** `Full` = 整张图不切分；`Grid` = 网格切分、每格独立；`RowAnimate` = 横向为帧、纵向为独立素材；`ColumnAnimate` = 纵向为帧、横向为独立素材；`ScanAnimate` = 先左到右再上到下组成动画。`[VERIFIED: E:/github/template/packages-user/client-modules/src/common.ts:50-61]`

**帧数证据:** `addRowAnimate` 里 `const frames = source.width / width;`，并把每个「行」当作一个图块、`offset = width`。`[VERIFIED: E:/github/template/packages-user/client-base/src/material/manager.ts:158-175]`

| 读取方式 | 图块数 | 帧数 | 第 f 帧的矩形（源图像素） |
|----------|--------|------|---------------------------|
| `Full` | 1 | 1 | `(0, 0, imageW, imageH)` |
| `Grid` | `columns × rows` | 1 | 第 i 格：`((i % columns) * cw, floor(i / columns) * ch, cw, ch)` |
| `RowAnimate` | `rows` | `imageW / cw` | 第 r 行、第 f 帧：`(f * cw, r * ch, cw, ch)` |
| `ColumnAnimate` | `columns` | `imageH / ch` | 第 c 列、第 f 帧：`(c * cw, f * ch, cw, ch)` |
| `ScanAnimate` | 1 | `columns × rows` | 第 f 帧：`((f % columns) * cw, floor(f / columns) * ch, cw, ch)` |

> `Grid` / `RowAnimate` 的两行有源码直接支撑（`gridSplitter` / `rowSplitter` + `frames = source.width / width`）`[VERIFIED: E:/github/template/packages-user/client-base/src/material/manager.ts:144-175]`。
> `ColumnAnimate` / `ScanAnimate` 的两行是**按枚举注释推导**的 `[ASSUMED]`：本会话读到的 `ITextureManager` 只声明 `addGrid` / `addRowAnimate` / `addAutotile` / `addTileset` 四个 `add*` 方法 `[VERIFIED: E:/github/template/packages-user/client-base/src/material/types.ts:248-307]`，且样例 `.list.jsonc` 里只出现 `grid` / `rowAnimate` / `autotile` / `tileset` 四种 `type`。见 Open Question 6。

**帧轴 / 帧步长（给渲染模型用）:** 为避免把 255 个矩形塞进每个格子，渲染模型只带 `frameAxis`（`X` / `Y` / `Scan`）、`frameStride`（`cw` 或 `ch`）与 `frameCount`，视图按当前帧号算 `crop.x + f * stride`（`Scan` 用 `f % columns` / `floor(f / columns)`）。

### Pattern 3: 自动拼接 —— 8 位连接、边缘掩码、四分之一块

**What:** 每个自动拼接格子按「与周围 8 格的连接情况」得到一个 8 位连接数，再查「3×4 / 2×3 素材里 4 个半格矩形」拼出这一格。

**连接位（逐字，最高位左上、顺时针）:**

```ts

    Up = 0b0100_0000,
    RightUp = 0b0010_0000,
    Right = 0b0001_0000,
    RightDown = 0b0000_1000,
    Down = 0b0000_0100,
    LeftDown = 0b0000_0010,
    Left = 0b0000_0001

```

**连接计算（逐字）:** 邻居按下标取 `a0 = index-1`（左）、`a1 = index+width-1`（左下）、`a2 = index+width`（下）、`a3 = index+width+1`（右下）、`a4 = index+1`（右）、`a5 = index-width+1`（右上）、`a6 = index-width`（上）、`a7 = index-width-1`（左上），然后 `res |= +(a0 === block) | (+(a1 === block) << 1) | … | (+(a7 === block) << 7)`；若该自动元件配置了「特殊连接」（`spec`），则用 `spec.has(ax)` 代替相等判断。`[VERIFIED: E:/github/template/packages-user/client-base/src/material/autotile.ts:392-435]`

**边缘语义（关键，必须逐字复刻）:** 地图外一律视为「已连接」，并且 1 行 / 1 列 / 单格地图有专门掩码：

**3×4 / 2×3 索引（逐字常量）:**

### Pattern 4: 每图格子尺寸 + contain + 动画 + 命中测试

**What:** 文档带 `cellWidth/cellHeight`；渲染模型带「缩放后的格宽 / 格高」与每格目标矩形；Pixi 与 DOM 叠加层都读模型里的度量，不再读 `MAP_CELL_SIZE`。

**contain 公式（D-07）:**

```ts

destH = srcHeight * scale;
destX = cellX + (cellWidth - destW) / 2;   // 水平居中
destY = cellY + (cellHeight - destH) / 2;  // 垂直居中
```

> 这与引擎默认不同，必须明确写进实现：引擎的 `FitToSize` 是**拉伸到格子**（`return { x: cl, y: ct, w: cw, h: ch }`）`[VERIFIED: E:/github/template/packages-user/client-base/src/map/vertex.ts:318-325]`，`KeepSize` 是保持原尺寸再按 `tileAlignX/Y` 对齐 `[VERIFIED: E:/github/template/packages-user/client-base/src/map/vertex.ts:326-370]`；引擎默认「大图块 KeepSize、小图块 FitToSize、水平居中、**竖直靠下**」`[VERIFIED: E:/github/template/packages-user/client-base/src/map/renderer.ts:136-144]`。D-07 的 contain + 居中是对引擎默认的**有意偏离**。

**命中测试:** `cellX = floor((clientX - rect.left - originX) / (cellWidth * zoom))`，`cellY` 同理。现状只有一个除数 `metrics.size` `[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:155-156]`，`metrics.size` 在普通模式固定为 `MAP_CELL_SIZE` `[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:180-181]`。命中范围仍是**整个格子**（与绘制出来的 contain 尺寸无关），与引擎的 KeepSize 行为一致。

**动画时钟:** 引擎用**一个全局帧计数器**：`const frameDT = timestamp - this.lastFrameTime; if (frameDT > this.frameSpeed) { this.lastFrameTime = timestamp; this.frameCounter++; … }`，`frameSpeed` 默认 `300`。`[VERIFIED: E:/github/template/packages-user/client-base/src/map/renderer.ts:1693-1699,173]` 编辑器同样只用一个时钟：`frameIndex = floor(elapsed / frameSpeed)`，每格 `frame = defaultFrame >= 0 ? defaultFrame : frameIndex % frames`；时钟属于 `MapSurface` 本地状态（不进面板 Store、不置脏）。

### Pattern 5: 视口 13×13 + 50–200% 缩放 + 左右栏宽比

**What:** 地图区不再是「整图大小的一张画布」，而是「固定 13×13 格的视口 + 外层滚动占位」；缩放同时改 `cellPx` 与右栏宽度。

**13×13 的来源:** 新引擎的 `MAP_BLOCK_WIDTH = 13` / `MAP_BLOCK_HEIGHT = 13` 就是地图视口格数（注释：「此值只影响画面，不影响游戏逻辑」）`[VERIFIED: E:/github/template/packages-user/client-base/src/shared.ts:9-14]`。

**虚拟化画布（推荐实现）:**

```text
.emap-canvas-viewport   （可见框：viewportColumns × viewportRows 格；overflow: auto）
├── .emap-canvas-spacer （占位：document.width × document.height 格；透明，只撑滚动条）
└── .emap-canvas        （position: sticky/absolute 在滚动位置；尺寸 = 可见框；Pixi 画布）
```

- 滚动位置 → `viewport.left = floor(scrollLeft / cellPx)`、`viewport.top = floor(scrollTop / cellPy)`；`MapCanvas` 在 `onScroll` 里回报给面板（rAF 节流），面板发布 `viewport`。

- 现状是「画布 = 整张地图」，256×256 × 32px = 8192px 边长 `[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:601-602]`。

**缩放（D-16）:**

```ts
paletteWidth = clamp(Math.round(BASE_WIDTH / zoom), MIN_WIDTH, MAX_WIDTH);
```

**debounce:** antd 6.2.1 的 `Slider` 有 `onChangeComplete`（`onAfterChange` 已废弃）`[VERIFIED: packages/libs/editor-impl/node_modules/antd/es/slider/index.d.ts:78-80]`；滑块用**本地 state 驱动拇指**、`onChangeComplete` 才发布到面板（受控值 + `onChangeComplete` 会让拖动时拇指回弹）。

### Pattern 6: 大地图整图缩略纹理（D-11）

**What:** 大地图模式把整张地图预渲染成一张缩略纹理（一张 Sprite），不再每格一个精灵。

**现状的性能问题（逐字证据）:**


`limited` 只把**图层**裁到当前层，格子循环仍是 `for y < document.height / for x < document.width` `[VERIFIED: packages/libs/editor-impl/src/map/model/renderModel.ts:258-270]`。256×256 单层 = 65,536 个精灵，远超 `MAP_BIG_MAP_MAX_SPRITES = 12000`。`[VERIFIED: packages/libs/editor-impl/src/map/constants.ts:29]`

**推荐实现:**

1. 纯模型输出 `IMapThumbnail { key, width, height, scale, offsetX, offsetY, textureWidth, textureHeight }`，**不输出**逐格 `cells`（或只在需要占位时输出极少量）。
2. `MapSurface` 在 `thumbnail.key` 变化时重建：新建 `RenderTexture`（宽 = `min(mapW, 512)`、高按比例），用一个 `Container` 以 1px/格（或 `textureWidth / mapW`）铺格子，`app.renderer.render({ container, target: renderTexture })`，然后把 `renderTexture` 作为**一张 Sprite** 缩放居中绘制。`RenderTexture` 与 `renderer.render(...)` 在 8.19.0 存在：`render(options: RenderOptions | Container): void`，`RenderOptions` 继承 `ClearOptions` 且有 `container: Container` 与 `target?: RenderSurface`，而 `Texture` 结构上满足 `BindableTexture`（`source: TextureSource`），因此 `target` 可以直接传 `RenderTexture` `[VERIFIED: packages/libs/editor-impl/node_modules/pixi.js/lib/rendering/renderers/shared/system/AbstractRenderer.d.ts:46-62; packages/libs/editor-impl/node_modules/pixi.js/lib/rendering/renderers/shared/texture/Texture.d.ts:79-81; packages/libs/editor-impl/node_modules/pixi.js/lib/rendering/renderers/shared/texture/RenderTexture.d.ts]`。
3. **重建键** = `document` 引用 + `currentLayerId` + `aboveLayerOpacity`（三者任一变化即重建）；视口 / 缩放 / 悬停 / 框选 / 通行度开关**不**触发重建。
4. 通行度叠加、框选、预览、悬停仍按屏幕坐标单独画在缩略图之上（不进缩略纹理）。

**降采样倍率:** 1 源像素/格，纹理边长上限 512（256×256 恰好 1:1）；1024×1024 时自动降为 0.5。`[ASSUMED]` —— D-11 把倍率与重建时机交给实现，需在开发宿主实测。

### Pattern 8: Tileset 整图分格与多格选择

**What:** 素材区把 Tileset 整图渲染一次，按格画分割线；点击 / 框选得到「格矩形」，再换算成图块编号组成图案。

**切片依据:** 引擎 `addTileset` 用 `cellWidth/cellHeight` 算 `width = floor(source.width / cellWidth)`、`height = floor(source.height / cellHeight)`，再按 `x = unoffset % tileWidth`、`y = floor(unoffset / tileWidth)` 取格 `[VERIFIED: E:/github/template/packages-user/client-base/src/material/manager.ts:213-244,352-367]`。

**编号来源（提案）:** 目录里 Tileset 的 `tiles` 逐格枚举 `number/column/row`（256 格就是 256 个小对象，成本可接受）；素材区渲染整图 + 网格，命中 `(column,row)` 后查编号。这样不把引擎的 `tilesetReserve` / `tilesetUnit` 编号公式带进 `editor-impl`。见 Open Question 3。

**框选:** 与现有 `MapPalette` 的同组框选同形（`buildPatternSelection`：行主序、缺格填 0）`[VERIFIED: packages/libs/editor-impl/src/map/components/MapPalette.tsx:258-277]`；框选结果就是 `IMapBrushPattern`，画布预览与落笔尺寸天然一致。

**分格尺寸:** 推荐用 **Tileset 自身的** `cellWidth/cellHeight`（来自目录），而不是地图的格子尺寸；否则 32px 的 Tileset 被按 48px 地图格切会错位。D-10 的字面「按 `cellWidth / cellHeight` 分格」有歧义，见 Open Question 2。

### Anti-Patterns to Avoid

- **把裁切矩形塞回目录：** 违反 D-02，且 255 帧动画目录会膨胀 255 倍。
- **在 `MapSurface` 里继续用 `MAP_CELL_SIZE` 画叠加层：** 现状已经在大地图模式错位（Pattern 4 证据）。
- **用 `document.createElement('canvas')` 做 flatten / 缩略图：** `editor-impl/src` 禁用 `document` `[VERIFIED: scripts/verify/coreModuleState.js:52]`。

## Common Pitfalls

### Pitfall 1: 目录里给「切好的帧」而不是规则

**What goes wrong:** 动画 255 帧时目录膨胀 255 倍；Tileset 大图无法表达；自动拼接无法按邻居变化。
**Why:** 照抄 Phase 4 的 `crop` 字段最省事。
**How to avoid:** 目录只给 `read / cellWidth / cellHeight / frames / columns / tiles[]`；裁切由 `model/tileFrame.ts` 现算。`[VERIFIED: .planning/phases/04.1-map-render-layout/04.1-CONTEXT.md:34]`

### Pitfall 2: 继续在多处硬编码 32

**What goes wrong:** 改了一处漏一处，叠加层与图块错位；大地图模式现在就已经错位。
**How to avoid:** 渲染模型带 `cellWidth/cellHeight`；`MapSurface` / `MapCanvas` 不再 import `MAP_CELL_SIZE`（只保留它作为「默认值」常量）。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapSurface.tsx:300-301,346-352,407]`

### Pitfall 3: 大地图「限额」只裁图层不裁格子

**What goes wrong:** 256×256 单层仍建 65,536 个精灵，切大地图卡死。
**How to avoid:** 按 Pattern 6 走缩略纹理；纯模型不再输出逐格 `cells`。`[VERIFIED: packages/libs/editor-impl/src/map/model/renderModel.ts:250-270]`

### Pitfall 4: 把整图当画布尺寸

**What goes wrong:** 256×256 × 32px = 8192px 边长的 WebGL 画布，超过常见 GPU 纹理上限。
**How to avoid:** 画布 = 视口尺寸（13×13），外层用占位撑滚动条。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:601-602]`

### Pitfall 5: 滚动每帧都 `store.setState`

**What goes wrong:** 整个面板（工具栏 / 素材区 / 底部页签）每个滚动帧重渲染。
**How to avoid:** 滚动位置在 `MapCanvas` 里按 rAF 节流后再回报；或只把 `viewport` 放进一个轻量独立 store（Phase 4 已用「画布本地 state」避免同类问题）。

### Pitfall 6: 动画帧每次重建整棵场景

**What goes wrong:** 300ms 一次把 169 个 Sprite 全销毁重建，纹理反复分配。
**How to avoid:** 只更新动画格的 `sprite.texture`（或 `AnimatedSprite.gotoAndStop`），静态格不动；`MapSurface` 现在每次 `drawModel` 都 `removeChildren` + `destroy` `[VERIFIED: packages/libs/editor-impl/src/map/components/MapSurface.tsx:554-562]`。

### Pitfall 7: 用 `document.createElement('canvas')` 做缩略图 / flatten

**What goes wrong:** `coreModuleState` 直接判红。
**How to avoid:** 用 Pixi `RenderTexture`，或 JSX `<canvas>`；不要 `document.createElement`。`[VERIFIED: scripts/verify/coreModuleState.js:52]`

### Pitfall 8: 在 `map` 里 import `asset` 的 `readImageDimensions`

**What goes wrong:** 能力互斥门禁判红。
**How to avoid:** `readImageDimensions` 只在宿主（`editor-dev` / 未来宿主）使用，用来算 Tileset 行列与自动元件帧数。`[VERIFIED: .dependencyCruiser.cjs:53-62]`

### Pitfall 9: `frequent` 的字符串键造成原型污染

**What goes wrong:** JSON 里的 `"__proto__"` / `"constructor"` 键被直接赋值进对象。
**How to avoid:** 只接受 `/^\d+$/` 的键并转成数字；用 `Map` 或 `Object.create(null)` 承载；写回时只输出数字键。`[ASSUMED]`（防御性建议）

### Pitfall 10: 迁移时删掉旧文件

**What goes wrong:** 旧宿主 / 旧版本仍读 `map-recent-tiles.json`；删除不可逆。
**How to avoid:** 只读旧文件、写新文件，不删除。

### Pitfall 11: 缩放滑块受控值回弹

**What goes wrong:** 拖动时拇指跳回旧值，因为 `value` 来自面板 Store 而 `onChange` 没有立刻发布。
**How to avoid:** 滑块用本地 state 驱动，`onChangeComplete` 才发布（Pattern 5）。

### Pitfall 12: 13×13 视口用 `window.innerWidth` 推导

**What goes wrong:** 测试里 `innerWidth = 0`，得到退化值。
**How to avoid:** 视口格数来自能力注入（默认 13×13），像素尺寸由 `格数 × cellPx` 算。`[VERIFIED: packages/libs/editor-impl/src/__tests__/mapPolyfill.ts:50-56]`

### Pitfall 13: Tileset 分格用错尺寸

**What goes wrong:** 32px 的 Tileset 被按 48px 地图格切，格线与图块错位。
**How to avoid:** 用 `IMapTilesetMeta.cellWidth/cellHeight`（Tileset 自身），地图格子尺寸只决定画到地图上时的缩放。见 Open Question 2。

### Pitfall 14: 四色箭头仍用整圆白底

**What goes wrong:** 四方向全阻时又糊成一个圆。
**How to avoid:** 每支箭头单独描边，不要中心整圆；箭头长度略短于半格，留出间隔。

### Pitfall 15: 抽屉只改 antd 属性、不改 CSS

**What goes wrong:** `maskClosable={false}` 只解决「点外部关闭」，灰线仍在。
**How to avoid:** D-15 与 D-25 是两个独立修复，必须都做。`[VERIFIED: packages/libs/editor-impl/src/map/map.css:515-519]`

### Pitfall 16: 收藏数字键在输入框里误触

**What goes wrong:** 在素材区搜索框 / 属性表单里按 `2` 切换了收藏图块。
**How to avoid:** 数字键监听挂在**画布容器**（`tabIndex=0`）上，与现有 `MapCanvas` 的 Ctrl+C/V、F 同一处理；不挂 `window`。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:513-546]`

### Pitfall 17: 线模式只画当前格

**What goes wrong:** D-14 要求整条路径；现状 `setPreview(createPositionPreview(position, pattern))` 只覆盖指针格。`[VERIFIED: packages/libs/editor-impl/src/map/components/MapCanvas.tsx:472-475]`
**How to avoid:** 预览用 `buildStrokeWrites(gesture.path, pattern)` 的去重格子集合，模型带 `previewCells`。

### Pitfall 18: 把 4 个自动拼接 Sprite 的层级写反

**What goes wrong:** 四个半格互相覆盖出接缝。
**How to avoid:** 按 `lt → rt → rb → lb` 顺序 `addChild`（引擎 `flatten` 就是这个顺序 `[VERIFIED: E:/github/template/packages-user/client-base/src/material/autotile.ts:296-302]`）。

### 2. 自动拼接连接与四块矩形（提案，逐字移植引擎常量）

```ts
// Source of constants: E:/github/template/packages-user/client-base/src/material/autotile.ts:85-96
// Source of edge masks: .../autotile.ts:320-377
// Source of bit assembly: .../autotile.ts:392-435

// 提案；名称待 INTERFACE-NAME 确认
export function computeAutotileConnection(
  cells: readonly (readonly number[])[],
  x: number,
  y: number,
  connections: ReadonlySet<number>,
): number {
  const width = cells[0]?.length ?? 0;
  const height = cells.length;
  const center = cells[y]?.[x] ?? 0;

  if (center === 0) return 0;

  const connected = (nx: number, ny: number): number => {
    if (nx < 0 || ny < 0 || nx >= width || ny >= height) return 1; // 地图外视为已连接
    const value = cells[ny]?.[nx] ?? 0;
    return connections.size === 0 ? Number(value === center) : Number(connections.has(value));
  };

  return (
    connected(x - 1, y) |
    (connected(x - 1, y + 1) << 1) |
    (connected(x, y + 1) << 2) |
    (connected(x + 1, y + 1) << 3) |
    (connected(x + 1, y) << 4) |
    (connected(x + 1, y - 1) << 5) |
    (connected(x, y - 1) << 6) |
    (connected(x - 1, y - 1) << 7)
  );
}
```

> 注意：上面对「地图外」直接返回 1，与引擎「先算 `connectEdge` 掩码再 OR」等价（引擎在边缘必然把该位设为 1）；实现时二选一，但**必须**保留 1 行 / 1 列 / 单格地图的等价行为（引擎那三种情况返回 `0b1111_1111` / `0b1110_1110` 等）。`[VERIFIED: E:/github/template/packages-user/client-base/src/material/autotile.ts:320-346]`

### 1. `.list.jsonc` 的 `type` 字符串与 `IClientTextureListConfig` 字段不一致 — 推荐口径：宿主按样例读

- **What we know:** 接口声明 `read: TextureReadType` / `usage: TextureUsage` `[VERIFIED: E:/github/template/packages-user/client-modules/src/common.ts:72-83]`；样例用 `"type": "grid" | "rowAnimate" | "autotile" | "tileset"` `[VERIFIED: E:/github/template/src/content/texture/.list.jsonc:6,29,318,342]`。

- **Recommendation:** 以**样例**为准（它是仓库里真实存在的项目数据）；`editor-impl` 不需要知道这件事，由宿主适配器负责。不阻塞本阶段。

### 2. Tileset 分格尺寸用谁 — 推荐：Tileset 自身

- **What we know:** D-10 写「按 `cellWidth / cellHeight` 分格」`[VERIFIED: .planning/phases/04.1-map-render-layout/04.1-CONTEXT.md:45]`；引擎 `addTileset` 用的是纹理清单里的 `cellWidth/cellHeight` `[VERIFIED: E:/github/template/packages-user/client-base/src/material/manager.ts:192-197,243]`。

### 3. Tileset 每格编号来源 — 推荐：目录逐格枚举

- **What we know:** 引擎用 `tilesetReserve` + `tilesetUnit` 计算编号 `[VERIFIED: E:/github/template/packages-user/client-base/src/material/manager.ts:340-369]`；那是引擎编号规则，不应进 `editor-impl`。
- **Recommendation:** 目录给 `tiles[]`（`number/column/row`）。**需用户确认**（目录体积 / 宿主实现成本）。

### 4. 「最近 / 最常」是三个页签还是两页签 + 切换 — 推荐：三个页签

### 6. `ColumnAnimate` / `ScanAnimate` 本阶段是否实现 — 推荐：实现纯函数，但不做演示数据

### 7. 真实宿主能否自动创建 `.editor` 目录 — 待宿主确认
