# Phase 04.1 Plan 35: 图集真实行数从宿主接到格子背景 Summary

**宿主把「来源图片真实有几行」交给目录，`resolveGroupAtlasRect` 的普通网格与横向动画据此算高度，`tiles-terrain` 的图集尺寸第一次是 128×64 而不是 128×32**

## Accomplishments

- `buildTileCatalog` 的三个 `createGroup` 调用点（自动元件 / Tileset 分桶 / 普通素材分桶）统一填 `rows = max(1, floor(图片高 ÷ cellHeight))`，不再有「某类素材漏填」的可能。
- `resolveGroupAtlasRect` 新增 `resolveImageRows(group, fallback)`：普通网格与横向动画优先用图片真实行数，缺省 / 0 / NaN 退回旧口径，`0` 或负数不会漏进 CSS。
- U-25 的根因被钉死：演示地形组只收录第 0 行（编号 1–4），但整张图集是 2 行高，于是矩形是 128×64；底部三页、收藏栏、素材区的一格仍然只显示一个 32×32 源格（第二格靠 `-32px` 负偏移取列）。
- 其它五个布局分支（Tileset / 自动元件 / 纵向动画 / 扫描动画 / Full）一条未改，既有 12 条模型用例与 `64px 32px` 断言原样通过。

## Decisions Made

- 宿主侧临时变量用 `imageRows` 而非计划里的 `rows`：tileset 分支已有一个语义不同的局部 `rows`（局部跳过条件），同名会遮蔽。只影响函数体内的临时变量名，不影响任何对外命名。
- `imageRows` 只用于填 spec，不改 tileset 分支原有的 `rows <= 0` 跳过条件——Tileset 算法一字不变。
- 组件侧回归用「只收录第 0 行、图片两行」的专用夹具，而不是给既有夹具加 `rows`：既有 `64px 32px` 断言正是「旧宿主不填 rows 时行为不变」的证据，必须留着。

## Deviations from Plan

None - plan executed exactly as written（唯一差异是宿主函数内一个临时变量名 `rows` → `imageRows`，理由见上；不影响行为、接口与测试判据）。

## Issues Encountered

- 计划 Task 1 要求「图片高小于素材格高（例如 16 高、32 格高）→ `rows === 1`」。普通网格在 `row * cellHeight + cellHeight > image.height` 时会整条跳过，因此该场景改用 `autotile` 条目验证（自动元件没有这条高度闸门），断言仍是 `rows === 1`，没有放宽判据。
