# Phase 04.1 Plan 26: 地图区结构与比例 Summary

**地图区终于只有一个框、一层滚动条，宽度也不再漏算那条 20 像素标尺：外框 = 标尺 + 画布，素材区拿剩余宽度且可以为 0，滑块改叫「地图区比例」，宽高框改成输完按回车或点别处才生效**

## Accomplishments

- **宽度口径修好了**：`resolveMapLayout` 不再用「可用宽度 − 素材区宽度」倒推地图区，而是直接 `canvasWidth + MAP_RULER_SIZE`。13×13 @100% 的地图区从 416 变成 436，正好包住左边那条 20px 标尺；素材区从「至少 240」改成 `max(0, 剩余宽度)`，可用宽度 600 时拿 164，可用宽度 300 时直接是 0。这是 U-11「地图区比画布窄 20px」的正面修复。
- **双层滚动合并成一层**：`.emap-canvas-scroll` 整个删掉，标尺与画布一起放进新的 `.emap-map-region` 外框。外框固定为「画布 + 标尺」并 `overflow: hidden`，只有画布内部的可视区 `.emap-canvas-viewport` 保留 `overflow: auto`（全文件恰好一处）。标尺现在是外框里的固定元素，不再跟着内容滚。
- **标尺厚度只剩一个来源**：`MapCanvas` 本地写死的 `RULER_SIZE = 20` 删除，改为读计划 25 声明的 `MAP_RULER_SIZE`；大地图模式 `ruler = 0`，外框就等于画布。左上角补了 `.emap-ruler-corner`，CSS 里不再有 `-20px` 负偏移的补丁。
- **说法改成用户能懂的**：滑块可见文案从「缩放」改成「地图区比例」，因为它调的是地图区多大、不是把画面放大缩小；字段仍叫 `zoom`、常量仍叫 `MAP_ZOOM_*`，契约一个字没动。
- **输入框不再边打字边跳**：宽 / 高两个数字框各自持有草稿，输入过程中只改草稿、不重排布局；失焦或回车时取整、夹到 1..64，再与另一个框的 props 当前值配对上报。清空或非法输入失焦后不上报，显示回退到面板回传的当前值。
- **测试按新口径重写并有「无下限」证明**：布局测试新增「可用 300 → 素材区 0」与「可用 600 → 素材区 164」，删掉了 240 下限和「地图区小于画布」的旧断言；工具栏测试覆盖「change 不提交 / blur 提交 / Enter 提交 / 清空回退」四条路径。

## Decisions Made

- **`mapPaneWidth` 无条件加标尺。** 即使量不到可用宽度（jsdom / 首次渲染）也按「画布 + 20」算，避免「地图区比画布窄」在回退分支里重新出现。
- **素材区宽度可以为 0。** 不再用 240 兜底；宽度不够时由用户调「地图区比例」，而不是让地图区被挤到比画布还窄。
- **外框尺寸用内联样式给出。** `.emap-map-region` 的宽高由 `canvasWidth/canvasHeight + ruler` 现算，CSS 只负责 `overflow: hidden` 与背景；标尺位置同样全部内联，CSS 不再保留负偏移。
- **提交时把夹取结果写回草稿。** 面板可能把输入夹到与 props 相同的值，此时 `useEffect` 不会触发；提交函数自己写回草稿，保证框里显示的是权威值。
- **滑块只改文案。** 组件名、`data-test-id`、`zoom` 字段与 `MAP_ZOOM_*` 常量全部保留，避免把这次 UI 修正扩散成一次重命名。
