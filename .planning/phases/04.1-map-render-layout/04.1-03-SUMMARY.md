# Phase 04.1 Plan 03: 帧与自动拼接模型 Summary

**编辑器现在能自己算出「一张素材按规则该切成哪一帧、动画走到第几帧」和「自动拼接的每一格该取素材里的哪四个小方块」，把引擎里那组靠注释口口相传的 magic number 变成了有测试钉住的纯函数。**

## Accomplishments

- `model/tileFrame.ts` 落地四个纯函数。`resolveFrameInfo(group, entry)` 把「读取方式 + 单格尺寸 + 帧数」翻译成 `axis / stride / count / base` 四个标量——不预展开 255 个矩形；五种读取方式逐条对应引擎语义（`Full` 整图一帧、`Grid` 每格一帧、`RowAnimate` 横向为帧、`ColumnAnimate` 纵向为帧、`ScanAnimate` 逐行扫描），自动元件在帧数大于 1 时优先接管、帧步长为整块宽度（3×4 走 3 格、2×3 走 2 格）。帧数一律用 `Math.min(MAP_FRAME_LIMIT, Math.max(1, …))` 夹取，上限来自常量而不是散落的字面量。
- `resolveFrameRect(info, frame, frameColumns?)` 按帧轴给出裁切矩形；`resolveCellFrame(defaultFrame, frameIndex, frameCount)` 让 `defaultFrame >= 0` 永远优先于全局帧号；`resolveFrameTickAt(elapsedMs, frameSpeedMs)` 是画布动画时钟唯一的时间换算入口——300ms 默认与 150ms 宿主覆盖都在单元测试里钉住，画布不必自写 `Math.floor(elapsed / 300)`。
- `model/autotile.ts` 落地两个纯函数。`computeAutotileConnection(cells, x, y, connections)` 逐字复刻引擎的 8 位连接位（最高位左上、顺时针到最低位左），并把引擎的「整表掩码」等价表达成越界判定：地图外一律已连接，因此 1 行 / 1 列 / 单格地图自动得到引擎同样的掩码；连接集合为空时按同值判定，非空时按集合判定宿主的单方面连接。
- `resolveAutotileQuarters(type, connection, cellWidth, cellHeight)` 把引擎的十个形状常量（`h / v / luo / ruo / ldo / rdo / luc / ruc / rdc / ldc`）原样照抄，按每行 6（3×4）或 4（2×3）个象限换算出四块源图矩形，每块宽高是素材单格的一半——编辑器只给矩形，绘制交给画布的四个 Sprite。
- 测试共 29 条（16 + 13），断言全部是具体数值：单行首末掩码 `0b1110_1111` / `0b1111_1110`、十字连接的四个象限索引 `4 / 5 / 11 / 10`、300ms 下 599 毫秒落在第 1 帧等。

## Decisions Made

- **Full 的「整张源图」就是素材单格**：宿主目录对 `full` 类型不切格，`cellWidth / cellHeight` 即图片尺寸，所以第 0 帧矩形天生是 `(0, 0, imageW, imageH)`，不需要给 `IMapTileGroup` 加图片尺寸字段（P-01 成立）。
- **自动元件只在帧数 > 1 时接管**：单帧自动元件与普通静态图块等价，此时帧轴留 `None`、步长不参与计算；这样 `autotile.png`（96×128、1 帧）不会被当成动画。
- **Scan 帧的纵向步长取帧矩形自身高度**：`stride` 是横向步长，扫描帧折行后的纵向位移必须用素材格高，非正方形素材才不会错位。
- **连接集合的口径按 D-06**：空集合按「与中心同值」判定（引擎的默认行为），非空集合按「是否在集合里」判定；编辑器不认识「墙壁」，只认宿主注入的连接集合。
