# Phase 04.1 Plan 02: 每图格子尺寸 + contain 端到端 Summary

**以前整个编辑器只认 32 像素一格；现在每张地图可以说自己一格多大，格子不是正方形时大图块按比例缩进格子并居中、小图块保持原样，而「画出来的格子」和「点中的格子」从此读同一份尺寸。**

## Accomplishments

- `model/cellMetrics.ts` 落地三个纯函数：`resolveTileDest`（contain：大素材缩小、小素材不放大、双向居中，素材尺寸非法时返回整格矩形）、`resolveCellMetrics`（度量组装）、`resolvePointerCell`（指针 → 格子，同时减掉画布容器原点与第一格留白原点再叠加视口）。整层只 import `../types`，没有 React / Pixi / editor-core / 文件访问。
- `renderModel.ts` 成为格度量的唯一来源：`buildMapRenderModel` 顶部把 `view.zoom` 夹到 `MAP_ZOOM_MIN..MAP_ZOOM_MAX` 后乘一次，得到 `cellWidth = 文档格宽 × 缩放`、`cellHeight = 文档格高 × 缩放`；`buildWindowModel` / `buildBigMapModel` / `buildEmptyModel` 三条返回路径都原样写进模型，可见行列、网格线、每格目标矩形全部读这一对值。
- `createRenderCell` 改为接收格子原点与这一对格尺寸，目标矩形交给 `resolveTileDest`；`MapPanelView` 用「文档格尺寸 × 缩放」算画布宽高，并把 `zoom: view.zoom ?? MAP_ZOOM_DEFAULT` 交给渲染模型。
- `MapCanvas.tsx` 清掉同名冲突：删除本地 `interface IMapCellMetrics`（字段只有 `size`）与 `resolvePointerPosition`，改从 `../types` 取共享形状、从 `../model/cellMetrics` 取 `resolvePointerCell`；本地构造器更名 `buildCanvasCellMetrics` 并返回共享形状。命中视口按模式选择：`pointerViewport = props.bigMap ? { left: 0, top: 0 } : props.viewport`，三个指针换算调用点与复制 / 粘贴兜底指针都用它；画布宽高改为由 `props.model.cellWidth/cellHeight` 推导，不再出现 `view.zoom`。
- 夹具扩展：`createTileGroup` 补 `category` / `read` / `cellWidth` / `cellHeight` / `frames` 缺省，新增 `createSizedTileGroup`（可造 64×64 素材），`createMapDocument` 补 32 的格尺寸缺省。
- 测试盯住整条链路：`model.cellMetrics.test.ts` 11 条纯函数用例（含「容器偏移」与「大地图留白原点 72.8」两条关键用例），`mapView.cellMetrics.test.tsx` 7 条视图 / 画布用例（48×24 contain、缺省 32、150% / 200% / 不传缩放、大地图命中得 `(0,0)`、普通模式对照得 `(100,100)`），`model.renderModel.test.ts` 新增 3 条格度量用例。

## Decisions Made

- **裁剪来源改为推导**：`buildTileImages` 不再读 `IMapTileEntry.crop`，按「列 / 行 × 素材格尺寸」推出第 0 帧矩形作为过渡（Plan 03 的 `tileFrame` 接管）。这样 64×64 素材与 48×24 格子共用同一条路径，也提前对齐 Plan 15 删除 `crop` 的方向；现有 32px 夹具的裁剪值不变，旧断言全绿。
- **非法格尺寸回退 32**：`resolvePositiveSize` 对缺省 / 0 / 负数统一回退 `MAP_CELL_SIZE`，落实威胁模型 T-4.1-02-02 的「只接受正数」；`resolvePointerCell` 对 0 格宽高直接返回视口原点，避免 Infinity / NaN 进入命中。
- **大地图模型度量与缩略尺寸分离**：模型上报的 `cellWidth/cellHeight` 始终是「文档格 × 缩放」，整图适配的缩略边长只用于排格子。`MapCanvas` 在 bigMap 分支另算度量，所以缩略绘制与模型字段不会互相污染。
- **命中视口规则落在调用点**：`resolvePointerCell` 保持模式无关，`MapCanvas` 用 `pointerViewport` 决定是否叠加视口；Plan 09 把面板视口钉到 `(0,0)` 时两处自然一致。
