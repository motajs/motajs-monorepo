<objective>
让开发宿主真的能「读引擎文件 → 生成中立的图块目录」，并把那张整片红的 1×1 演示图换成看得出区别的多格图集。

用大白话说：地图编辑器自己不认游戏引擎的文件格式，它只认一份「素材清单」——哪张图、怎么切、每块叫什么、能不能走。这份清单要由宿主（现在是开发用的演示宿主）准备好。演示用的图以前其实只有 1 个红色像素，所以整张地图都是红的；这次换成 8 个不同色块。

Purpose: D-01 / D-02 / D-06 都落在宿主这一侧。同时 G-04-1（演示图集整片红）必须在本阶段收口，而它的根因就在演示数据。

Output: `tileCatalog.ts` 解析器、新的多格演示图集与目录、地图文件记录带格子尺寸，以及对应测试。
</objective>

## Trust Boundaries

| Boundary | 描述 |
|----------|------|
| 引擎文件（用户项目）→ 宿主解析器 | JSONC 可能畸形、字段缺失、类型错误、图片尺寸超限 |
| 图片字节 → `readImageDimensions` | 伪造头 / 超大尺寸；函数已有上限校验 |
| 宿主 → 能力包 | 目录是数据；能力包不得读取任何文件 |

| T-4.1-06-01 | Tampering | `buildTileCatalog` 的路径 / 编号 | high | mitigate | 路径只做相对项目根的字符串拼接；编号必须为正整数；畸形条目跳过而不是原样写入 |
