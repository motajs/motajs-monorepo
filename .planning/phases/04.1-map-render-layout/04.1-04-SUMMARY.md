## Accomplishments

- `model/thumbnail.ts` 落地 `buildThumbnail(document, canvasWidth, canvasHeight)`。它把「整张地图」压成一份七字段的形状描述：显示宽高按画布等比适配并居中（256×256 → 416×416 / 缩放 1.625；40×26 → 416×270.4、上下各留 72.8），纹理宽高按 1 源像素/格生成并受 `MAP_THUMBNAIL_MAX_SIZE = 512` 约束（1024 地图自动降采样一半、600×300 得 512×256、512 恰好不降采样）。描述里没有逐格格子、也没有任何重建键——256×256 单层原本会生成 65,536 个精灵，这正是 Plan 10 要换成一张纹理的原因。
- 同一份函数还钉住了「什么时候重建」的语义边界：视口 / 缩放 / 选区 / 悬停都不进参数，把文档对象上挂着这些视图字段时输出仍逐字段相同，说明重建判据只能由视图比较「文档引用 + 当前层 + 上层不透明度」得出，纯函数不参与。
- `model/layout.ts` 落地 `resolveMapLayout(document, options)`。默认 13×13 视口、30 像素级数字全部落定：0.5 倍 → 格 16 / 画布 208 / 右栏顶到 360；1.5 倍 → 格 48 / 画布 624 / 右栏 160；2 倍 → 格 64 / 画布 832 / 右栏缩到下限 160。缩放超出 0.5..2 一律夹取（0.1→0.5、5→2），视口格数非正整数退回默认，文档格尺寸缺省或非法按 32。
- 右栏宽度公式 `clamp(round(基准 / 缩放), 160, 360)` 用 8 档缩放 × 6 档基准宽度的扫描钉住：素材区永远不会窄到不可用，也不会抢走地图区的宽度。
- 布局与渲染模型同源被显式断言：同一个 `zoom = 1.5` 下 `resolveMapLayout` 与 `buildMapRenderModel` 报出的格像素都是 48，Plan 09 / 11 传同一个缩放就不会出现「画布用了 48、格子画在 32」的错位。
- 测试共 29 条（缩略 12 + 布局 17），全部断言具体数值；布局的「不读窗口」用「把 `window.innerWidth` 改成 4000 后结果不变」证明，而不是只依赖桩里的 0。

## Decisions Made

- **缩略纹理尺寸取整数**：RenderTexture 的宽高必须是整数像素，所以 `textureWidth/textureHeight` 用 `Math.round`（并保底 1）；显示尺寸 `width/height/scale` 保持浮点，视图层负责摆放。
- **画布尺寸非正时也退回全零描述**：计划只写了「文档宽或高为 0」，但画布为 0 时显示尺寸本就无意义；统一退化成一份全零描述，比留下 `scale = 0` 的半截结果更难被误用。
- **布局的缩放 NaN / Infinity 回退到 `MAP_ZOOM_DEFAULT`，而不是夹到边界**：夹取只对「有意义的越界值」有效，NaN 夹完仍是 NaN；两种输入因此走两条不同分支。
- **视口格数要求正整数，2.5 直接退回默认 13**：半格视口没有语义，静默向下取整会让宿主以为注入生效却看到别的宽度。
- **两个模块都不加入 `model/index.ts` 桶**：沿用 04.1-02 / 03 的做法，后续计划按相对路径 import；桶的统一整理留给 Plan 15 收紧接口时处理。

## Issues Encountered

- **非二进制可精确表示的小数不适合整对象 `toEqual`**：`40 × 26 → 270.4 / 72.8` 这类值由 `416 / 40 = 10.4` 再乘回时会产生尾差（实测 `72.79999999999997`）。因此非正方形用例改为逐字段 `toBeCloseTo(…, 6)`，与计划的「偏移断言到小数点后一位」一致；正方形与整数用例仍用整对象 `toEqual` 钉住（`416 / 1.625 / 0`）。
- **`thumbnail.ts` 是未跟踪文件时 `git checkout --` 无法还原变异**：第一次变异还原时报 `pathspec … did not match any file(s)`，改为直接编辑还原并重跑确认（`12 passed`），未使用任何 blanket reset。
- **PowerShell 控制台把中文输出显示成乱码**（`Test Files` 行的中文用例名尤其明显）：只是控制台代码页问题，文件内容与提交信息经 `Read` 复核均为正常 UTF-8；提交信息统一用 `git commit -F <UTF-8 文件>`，避免参数传递损坏中文。
