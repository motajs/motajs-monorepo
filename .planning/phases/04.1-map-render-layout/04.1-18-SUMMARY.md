# Phase 04.1 Plan 18: 自动保存契约与切换时序 Summary

**「离开面板就自动存」从一句口头约定变成了外壳的硬保证：切换、关闭、替换、注销四条路径都会先等面板把改动写完，才让下一个面板进来或者把旧面板释放；`onSwitchOut` 是唯一落盘点，`onBeforeClose` 不再问「要不要保存」。**

## Accomplishments

- **外壳不再「通知一声就走」**：`ShellSystem` 内部多了一条私有 promise 链。以前是「切出和切入同时投出去」，现在是「切出排队 → 结算 → 切入排队 → 结算」。新面板收到 `onSwitchIn` 时，前一个面板的 `onSwitchOut` 一定已经返回。
- **关闭 / 替换 / 注销一律先落盘再释放**：`leaveActiveInstance` 从「发完不管」改成返回可等待的 Promise；`discardTab`、`openPanelInTab` 在释放实例前 await 它；`closePanelInstance` 在自己调用 `dispose()` 之前再 await 一次链，于是「标签被替换」「注销面板类型」「释放整个 core」这三条**没有**走 `discardTab` 的路径也自动被覆盖。
- **抛错不卡住切换**：`invokeSwitchOut` / `invokeSwitchIn` 内部 catch 并记 `shell.callbackFailed`，链节点因此永远 resolve；链一旦 reject，后续所有 `.then` 都会被跳过、切换会永久停摆——这一点被测试用「抛错后再切一次」钉死。
- **契约写进类型注释**：`onSwitchOut`（唯一落盘点 / 外壳 await / 禁止弹确认框 / 四条调用路径）、`onBeforeClose`（不再问未保存，只拦破坏性场景）、`onSwitchIn`（前一个面板落盘结算后才投递）。签名一字未改，三个能力面板无需适配。
- **顺序被测试钉死**：新增 `shellAutosave.test.ts` 四个用例，用「手工门闩 + 共享事件数组」把钩子停在半路，先断言「只走到 `onSwitchOut 开始`」，结算后再断言完整序列。

## Decisions Made

- **落盘点只留一个**：不给接口加新成员（计划的禁止项），把语义全压在既有 `onSwitchOut` 上；`onBeforeClose` 保留签名，只缩小用途。
- **串行链放实例内部**：不新增 `IShellSystem` 成员、不给 `activateTab` 加 `async`。代价是「钩子延后一拍」——标签渲染仍立刻切换（`notify()` 同步），只有 `onSwitchIn` / `onSwitchOut` 的投递变成一个微任务之后。这个代价换来了外部调用方零适配。
- **`closePanelInstance` 统一 await 链**：比在四个入口各写一遍更稳，因为将来新增「销毁实例」的入口会自动获得落盘等待。
- **`openPanelInTab` 也显式 await `leaveActiveInstance`**：计划只点名 `discardTab`，但替换路径若只靠 `closePanelInstance` 内部 await，读代码时看不出「旧落盘 → dispose → 新 initialize → 新切入」这条序；显式 await 让顺序直读。
- **不给落盘加超时（T-4.1-18-02 取 accept）**：面板写入的失败与超时归各自资源层；外壳加超时会在正常慢写入时误杀，反而制造「保存被中断」。
- **抛错只记日志**：`invokeSwitchOut` 已有 catch 保持不变，因此链永不 reject；面板要把失败显示在自己的提示区（地图 / 表格 / 素材各有提示行）。
