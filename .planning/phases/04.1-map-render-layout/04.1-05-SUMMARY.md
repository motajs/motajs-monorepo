## Accomplishments

- `model/tilePreferences.ts` 落地五个纯函数。`normalizeTilePreferences(raw, knownNumbers, favoriteNumbers, limit)` 把一份任意内容的偏好文件收成合法形状：最近使用沿用 `normalizeRecentTiles` 的口径（非数组 → 空，0 / 负数 / 小数 / 字符串丢掉，目录外丢掉，重复留第一次，超上限截断）；收藏固定 9 格、只留允许收藏的编号、空位与重复位都是 0；次数表只认纯十进制键、次数必须是有限正数、编号必须在目录里。
- 原型污染这条真实威胁被钉死：`JSON.parse('{"frequent":{"__proto__":9,"constructor":4,"abc":2,"0x10":5,"1e1":6,"12":3}}')` 归一化后只剩 `[[12, 3]]`，而且 `({}).polluted` 仍然是 `undefined`——`__proto__` 这类键连当普通键进入表的机会都没有，写回时容器本身也没有原型。
- 超大文件不会拖垮读取：次数表超过 `MAP_FREQUENT_LIMIT = 200` 条时只保留次数最高的 200 条（300 条 1..300 的输入 → size 200、最小保留编号 101），与写盘裁剪同一口径，结果与文件里键的排列顺序无关。
- `rankFrequentTiles` 与 `reorderFavorite` 把编辑手感固定下来：「最常使用」按次数降序、同次数编号升序（`[[3,5],[1,5],[2,9]]` → `[2,1,3]`）；收藏移位先把数组补齐到 9 格再移动，越界索引夹到 `0..8`，返回新数组且不改入参。
- `migrateRecentTiles` 只读迁移旧文件：`{ tiles: [3,1,3,0,99] }` 且目录含 `1/3/5` 时得 `recent: [3,1]`，`frequent` 为空 Map、`favorites` 9 个 0；非对象 / `tiles` 非数组 / 只有新格式字段（`{ recent: [1] }`）都退化为空偏好。函数不读也不删旧文件——旧文件是否清理由宿主决定。
- `serializeTilePreferences` 把写回形状钉成逐字固定的三字段：`{"recent":[3],"frequent":{"12":2},"favorites":[1,0,0,0,0,0,0,0,0]}`（用例直接断言这段 JSON 字符串）。写回后再归一化一轮，三份数据与写回前逐项等价。
- 33 条用例全部断言具体值，没有一个「只检查不抛错」的空断言。

## Decisions Made

- **最近使用复用 `./recentTiles` 的 `normalizeRecentTiles`，而不是把守卫 / 去重 / 截断再抄一遍。** 计划写的是「Copy 这些做法」，但两个调用方（旧面板读最近使用、新偏好文件读 `recent`）必须给出完全相同的列表，抄一份就多一处会漂的实现；`recentTiles.ts` 已有自己的用例，复用让两边天然一致。
- **次数表的存储上限用 `MAP_FREQUENT_LIMIT`（200），超出时保留次数最高的 200 条**，而不是按读到的键顺序砍尾：与写盘「按次数降序裁剪」同一口径，结果与文件里键的排列无关（威胁 `T-4.1-05-02` 的落点）。
- **`favoriteNumbers` 由调用方传入，模型不认识「Tileset」这个分类。** 分类规则只存在于目录侧；模型只回答「这个编号允许收藏吗」，因此在 `[1, 12, 2]` 里 12 变成空位而不是被当成非法输入整份丢弃。
- **写回时 `recent` / `favorites` 复制成新数组、`frequent` 逐键写进 `Object.create(null)`。** 写回结果不带输入对象的任何残留，也不存在可以被 `__proto__` 命中的原型链。
- **两个新文件都不加入 `model/index.ts` 桶**：沿用 04.1-02 / 03 / 04 的做法，后续计划按相对路径 import；桶的统一整理留给 Plan 15 收紧接口时处理。

## Issues Encountered

- **PowerShell 控制台的代码页是 shift_jis，中文既会在输出里显示成乱码，也会把命令里内联的中文提交信息写坏。** 第一次 RED 提交（`eaebae8`）因此带上了乱码主题行，随后用 `git commit --amend -F <UTF-8 文件>` 修成 `e220fef`（同一棵树、同一父提交，只改信息）。之后所有提交都改为「先用文件工具写 UTF-8 消息文件，再 `git commit -F`」，并用 `git cat-file commit` 复核字节正确。
- **`reorderFavorite` 的目标索引夹取无法用变异单独证明**：`Array.prototype.splice` 自身会把越界的目标下标夹到数组末尾，因此「夹到 8」与「不夹」结果相同。来源索引的夹取用例（`-3`）能真正失败，这一条足以证明夹取代码是必要的；目标侧断言保留为行为文档。
- **对象里的数字键在 JSON 往返后会被重排**：`{'12':2,'5':7}` 序列化后变成 `{"5":7,"12":2}`，因此往返用例比较的是「size + 每个编号的次数」而不是 `frequent` 的条目顺序。
