<objective>
Turn two prose promises into gates that can be shown to fail: core must not reach for `fetch`, the DOM or ambient env (PORT-02), and core must not carry module-level mutable state (KERN-06's structural half).

Purpose: neither promise is enforceable by the type system. `packages/libs/config/tsconfig.lib.base.json` enables `ESNext`, `DOM` and `DOM.Iterable`, so `window`, `document` and `fetch` typecheck perfectly inside core; and `no-restricted-properties` provably misses `import.meta.env` because that is a `MetaProperty`, not an `Identifier` — both facts were established by the research's executed probes. That makes the scoped ESLint override load-bearing and its two-polarity proof mandatory: a green gate that cannot be made red is indistinguishable from a dead gate, which is exactly what Phase 2's `coreBoundaries.js` was built to prevent. Both gates go inside the existing `lint` job; `.dependencyCruiser.cjs` is already correct for Phase 3 and must not be touched.
Output: two core-scoped flat-config blocks in `eslint.config.js`, `scripts/verify/coreModuleState.js`, and one extra `- run:` step in the existing `lint` job.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| core source → the ambient platform (network, DOM, env) | Core must not reach outside the injected ports; the ESLint override is the only static enforcement because the DOM libs are enabled for typechecking. |
