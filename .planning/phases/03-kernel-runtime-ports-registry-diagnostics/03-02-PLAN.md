<objective>
Make construction atomic and make teardown honest: a core that cannot satisfy its required registrations must release what it built and refuse to hand back a half-finished graph, and `EditorCore.dispose()` must be able to lose one teardown without losing the rest — and must say so through the diagnostic bus.

Purpose: KERN-04's guarantee ("startup fails loudly") is only worth anything if the failure releases the resources it already acquired — otherwise a rejected startup leaks a registry, a bus, and any subscriptions an adapter installed. KERN-02's guarantee ("reverse creation order") is only worth anything if one bad teardown cannot strand the others, and D-21 names the channel: the bus plus the console, which makes the failure both testable and visible on site. Both properties are asserted from outside the instance, which is why `CapabilityRegistrar.addTeardown` exists (D-18).
Output: the required-resolution and startup-throw path in `lib/kernel/core.ts`, the real `EditorCoreStartupError`, and the two lifecycle test files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config (adapter) → construction | The adapter supplies both the `install` callback and the required-registration list; a wrong list (or a wrong install) must fail loudly rather than silently produce a crippled core. |
| teardown callback → the drain loop | Teardown callbacks are arbitrary code (adapter-supplied); a throwing one crosses back into the drain. |
| diagnostic history → the thrown startup error | The error carries the whole history out of the failed construction; it becomes a log-visible artifact. |
